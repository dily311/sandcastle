## 중장기 계획 평가 (2026-11-16)

코드와 ADR(`docs/`)을 대조해 본 결과다.

**잘 된 점**
- 1단계의 핵심(기능 / 작업 / 사용량 책임 분리, 모든 유료 호출의 작업화, 실행 기록 화면)은 M2에서 끝났다. 뒤 단계의 자동 기능(선톡·에이전트·자동 색인)이 올라설 바닥이 이미 있다.
- 원칙(기본 off, 실행 주체 명시, 원본 보존)이 코드 구조(`sys/plugins.rs`의 `require`, 작업의 `run_by`, 공용 번역 캐시)에 실제로 박혀 있다.

**빈 곳과 위험**
1. **1단계가 "화면"에 치우쳤다.** M3~M8이 모두 화면 다듬기였고 안정성 쪽은 비어 있다: 예산 한도 없음(ADR-006이 다음 단계로 미룸), 작업·사용량 기록이 계속 쌓임, E2E 없음, CI에 Android 빌드와 `cargo fmt --check` 없음, 업데이트·서명 없음, 버전 어긋남(package.json 0.0.0 / tauri.conf.json 0.1.0).
2. **Android는 목표 플랫폼인데 검증 기록이 없다.** CI는 프런트(ubuntu)와 Rust(windows)만 돈다. 키 저장(`keyring`)·파일 고르기·백그라운드 생성이 Android에서 되는지 문서에 없다. 동기화(2단계)는 모바일이 돌아야 의미가 있으므로 2단계 전에 1-C가 필요하다.
3. **백업에 빠진 폴더가 있어 보인다.** `service/data/backup.rs`의 `BACKUP_DIRS`는 characters·games·themes뿐이고, 만든 그림(`generated/`)과 배경(`backgrounds/`)은 따로 있다. 동기화 전에 "무엇이 사용자 데이터인가"부터 확정해야 한다(1-B).
4. **2단계는 한 줄짜리지만 가장 크고 위험하다.** 지금은 변경 추적·기기 구분·병합 규칙이 없다. 클라우드 연결보다 병합 로직이 본체이므로, 파일로 주고받는 수동 병합(2-B)으로 먼저 검증하고 클라우드는 그 위에 얹는다.
5. **3·5단계 기능은 테이블만 있고 엔진이 없다.** `memory_settings`·`memory_embeddings`·`proactive_settings`·`agent_definitions`·`agent_states`·`agent_tool_calls` 테이블은 있지만 쓰는 코드가 없고, 어댑터(`src-tauri/src/adapter/`)에 임베딩·도구 호출이 없다. 그래서 3-A(어댑터 확장)를 선행 작업으로 넣었다.
6. **자동으로 돈이 나가는 기능의 순서.** 선톡·에이전트·자동 색인·유료 linter는 모두 "사용자가 안 볼 때 요금이 나가는" 기능이다. 예산 한도(1-A)가 먼저 있어야 한다.
7. **다국어·접근성은 늦출수록 비싸다.** Svelte 파일 130개 중 `$_(`를 쓰는 것은 6개다. 전면 번역은 5단계에 두되, "새 화면은 locales 키"(ADR-003) 규칙을 지금부터 지키고 하드코딩이 늘지 않게 검사를 먼저 건다(5-C-2).
8. **4단계의 "템플릿 전환"은 구조가 먼저다.** 템플릿은 dating-sim 하나, 플레이 화면은 `features/game/play/vn` 하나, capabilities는 선언만(게임 ADR-016)이다. 규칙 템플릿과 화면 템플릿을 나누는 작업(4-B)이 새 템플릿(4-C)보다 앞선다.
9. **6단계가 비어 있었다.** 외부 코드 실행은 위험이 크므로 "선언형 묶음 → 격리된 코드" 순서로 정의했다.
10. **문서 어긋남.** `docs/Tech Spec.md`의 마일스톤 일정이 이 파일과 다르고, ADR-005의 "기본 켜짐" 목록에 HTML 렌더링이 남아 있다(실제는 off). 1-D-3에서 맞춘다.

**선행 관계**
```
1-A 예산 한도 ─→ 3-B(유료 규칙) · 3-C(자동 색인) · 4-D · 5-A · 5-B
1-B 데이터 안전 ─→ 2-A → 2-B → 2-C → 2-D → 2-E
1-C Android 점검 ─→ 2-D(모바일 동기화) · 5-C-4(모바일 최적화)
3-A 어댑터 확장 ─→ 3-C · 3-D · 4-D · 5-B
4-B 템플릿 구조 ─→ 4-C
5-B 에이전트 ─→ 아이디어 스케치의 "프로필 자동 반영", "AI가 씬 만들기"
```

**다음 마일스톤 제안 (합의 전)**: M9 = 1-A + 1-B, M10 = 1-C, M11 = 1-D + 1-E. 그 뒤 2단계와 3-A는 건드리는 파일이 거의 겹치지 않아 나란히 진행할 수 있다.

## 단계별 세부 계획

각 항목은 `번호 이름 — 무엇을. 어디: 파일. 완료: 기준` 순서로 적는다. "현재"는 2026-11-16 코드 기준이다.

### 1단계 — 기본 완성도와 안정성 (남은 일)

**현재** M1~M8 완료. 기능·작업·사용량 분리(ADR-006)와 설정 > 관리 > 실행 기록 화면이 있다.

**1-A 예산 한도와 기록 정리** (ADR-006 "다음 단계")
- 1-A-1 한도 모델 — API 프로필별 일/월 상한(토큰·음성 글자·그림 수)을 저장한다. 기본은 한도 없음. 어디: 새 마이그레이션, `db/usage.rs`. 완료: 기간별 사용량 대비 남은 양을 돌려주는 함수와 단위 테스트.
- 1-A-2 실행 전 확인 — 작업을 시작하기 전에 TaskManager가 한도를 묻고, 넘으면 새 오류 코드(`BUDGET_EXCEEDED`)로 거절한다. 어디: `task/task_manager.rs`(`submit`, `run_inline`), `error/error_code.rs`. 완료: 막힌 작업은 공급자를 한 번도 부르지 않고 실행 기록에 "한도로 막힘"으로 남는다. **결정 필요**: 사용자가 직접 누른 실행(user)은 "이번만 계속"을 허용할지(추천: 허용, auto는 항상 막음).
- 1-A-3 단가표 — 모델별 입력·출력 단가를 사용자가 적는 표. 앱이 가격을 넣어 두지 않는다(가격은 바뀐다). 금액은 "추정"으로 표시. 어디: `plugin-setting` 또는 새 테이블, `features/settings/ActivitySection.svelte`.
- 1-A-4 기록 정리 — 작업·시도·사용량 상세 행의 보존 기간(설정에서 고름). 일별 합계는 남기고 상세만 지운다. 어디: `db/usage.rs`, `task/task_repository.rs`. 완료: 정리 뒤에도 기간별 사용량 숫자가 같다.
- 1-A-5 화면 — 실행 기록에 한도 막대, 한도 설정, 80% 도달 알림(앱 안 알림).

**1-B 데이터 안전** (2단계의 선행)
- 1-B-1 사용자 데이터 범위 확정 — 앱 데이터 폴더를 "사용자 데이터 / 캐시 / 기기 전용"으로 나눈 표를 ADR에 적는다. `generated/`·`backgrounds/`가 백업에서 빠지는지 복원 테스트로 확인하고, 빠지면 `BACKUP_DIRS`에 넣고 `BACKUP_VERSION`을 올린다. 어디: `service/data/backup.rs`, `service/data/tests.rs`. 완료: 백업 → 빈 환경에 복원 → 갤러리·배경·테마 배경이 그대로. 이전 버전 백업도 복원된다.
- 1-B-2 마이그레이션 전 자동 백업 — 시작 시 적용할 마이그레이션이 있으면 DB 사본을 먼저 만든다(최근 몇 개만 유지). 어디: `db/conn.rs`, 복원 흐름의 `restore-backups/`와 같은 자리.
- 1-B-3 무결성 점검 — 설정 > 데이터에 "DB 점검" 버튼(`PRAGMA integrity_check`, 고아 파일 목록). 지우지는 않고 보여주기만.
- 1-B-4 키 누출 테스트 — 백업·내보내기 파일 안에 keyring 값이 없음을 자동 테스트로 고정한다(가짜 키를 넣고 산출물 전체에서 찾기).

**1-C Android 점검과 모바일 레이아웃 최소선**
- 1-C-1 점검표 — `pnpm android:dev`로 실기기나 에뮬레이터에서 확인하고 결과를 `docs/`에 표로 남긴다: 앱 시작 / API 키 저장·읽기(`keyring`이 Android에서 동작하는지. 안 되면 Android Keystore 기반으로 바꾸고, 평문 파일에 두지 않는다) / 채팅 스트리밍 / 파일 가져오기·내보내기 / 그림 표시 / HTML iframe(`http://htmlview.localhost`) / 알림 / 생성 중 화면 꺼짐(백그라운드 서비스) / 백업·복원.
- 1-C-2 깨진 항목 고치기 — 순서: 키 저장 → 채팅 → 가져오기 → 나머지. 고칠 수 없으면 "모바일 미지원"으로 숨기고 표에 적는다.
- 1-C-3 좁은 화면 — 모든 페이지(채팅·폰·게임 플레이·게임 편집기·설정·갤러리)를 모바일 폭으로 확인: 안전 영역, 키보드가 입력칸을 가리지 않기, 누르는 대상 최소 44px, 오른쪽 클릭 메뉴마다 꾹 누르기 대체, 끌어서 순서(`shared/dnd/sortable.svelte.ts`)의 터치 동작.
- 1-C-4 데스크톱 전용 숨김 — 위젯, 파일 위치 열기, 전역 단축키, 자동 시작이 Android에서 보이지 않는지.

**1-D 품질 기반**
- 1-D-1 E2E 스모크 — 앱 시작 → 캐릭터 가져오기 → 가짜 공급자(로컬 서버)로 메시지 한 번 → 백업. 어디: `docs/Tech Spec.md`의 WebdriverIO 계획. 완료: CI에서 돈다.

- 1-D-5 성능 측정 — 먼저 잰다: 메시지 수천 개 대화 열기, 그림 수천 장 갤러리, 시작 시간, 꺼진 플러그인이 시작 때 아무것도 읽지 않는지. 기준을 넘는 곳만 고친다(가상 스크롤, 나눠 읽기, 인덱스).
- 1-D-6 오류 모으기 — 처리 안 된 프런트 오류와 Rust panic을 로그 탭에 남긴다. 외부로 보내지 않는다.

**1-E 배포**
- 1-E-1 버전 규칙 — package.json·Cargo.toml·tauri.conf.json 버전을 하나로, 변경 내역 파일.

### 2단계 — 데이터 관리 및 동기화

**현재** 전체 백업·복원(`.scbackup`), 캐릭터 묶음(`.scpack`), 게임(`.tgame`)이 있다. API 키는 keyring에만 있어 백업에 들어가지 않는다. 변경 추적·기기 구분·병합은 없다.

**원칙** 동기화는 새 기능이므로 기본 off(플러그인 `sync`). 올리기·내려받기는 실행 기록에 남긴다. 덮어쓰기 전에 기존 데이터를 보관한다. 키·토큰은 어떤 경우에도 묶음에 넣지 않는다.

**결정 (2026-11-17, ADR-011)** ① 사용자가 고른 폴더 먼저 → 구글 드라이브 앱 전용 폴더(WebDAV 안 함) ② 항목(행)별 병합 ③ 충돌은 둘 다 남김(대화는 분기, 지우기↔고치기는 고친 쪽) ④ 사용자 데이터 파일만 해시로(캐시 제외, Android Wi-Fi에서만 옵션) ⑤ 암호화는 선택·기본 꺼짐, 암호 문구는 기기마다 keyring(2-C 뒤)

**2-A 변경 추적과 휴지통**
- 2-A-1 대상 표 — 동기화하는 테이블(캐릭터·페르소나·로어북·대화·메시지·프리셋·정규식·게임 정의·게임 세션·테마)과 안 하는 것(작업·사용량 기록, 캐시, 위젯 음악, 창 상태)을 ADR에 표로.
- 2-A-2 컬럼 — 대상 테이블에 `updated_at`·`deleted_at`을 넣고 id가 기기 사이에서 겹치지 않는지(uuid) 확인한다. 어디: 새 마이그레이션, `db/*.rs`의 upsert·delete. 완료: 모든 쓰기가 `updated_at`을 갱신하는 테스트.
- 2-A-3 휴지통 — 지우기는 `deleted_at` 표시로 바꾸고, 설정 > 데이터에 휴지통(되살리기 / 완전히 지우기 / 기간 뒤 자동 정리). 모든 목록 조회가 지운 행을 빼는지 확인.
- 2-A-4 기기 id와 설정 나누기 — 설치마다 기기 id 하나(동기화 안 됨). 설정을 "같이 쓰는 것(테마·프리셋 선택)"과 "기기 전용(창 크기·경로·위젯)"으로 나눈다. API 프로필 행은 동기화하되 키는 기기마다 다시 넣게 하고 "키 없음" 상태를 보여준다.

**2-B 묶음 형식과 수동 병합**
- 2-B-1 묶음 형식 — manifest(형식 버전·스키마 버전·기기 id·시각) + 바뀐 행 + 파일 목록(해시). 어디: `service/data/` 아래 새 모듈.
- 2-B-2 병합 — 묶음을 지금 DB에 합치는 순수 로직. 완료 테스트: 두 DB에서 따로 고친 뒤 양방향으로 합치면 결과가 같다 / 지우기와 고치기 충돌 / 스키마가 낮은 기기는 거절하고 업데이트를 안내.
- 2-B-3 파일로 주고받기 — 내보내기·가져오기 화면. 적용 전에 미리보기(추가·변경·충돌 개수)를 보여주고 자동 백업 뒤 적용.
- 2-B-4 키 누출 테스트 — 1-B-4와 같은 테스트를 묶음에도.

**2-C 폴더 대상 동기화**
- 2-C-1 `SyncTarget` 인터페이스(list / get / put / delete)와 로컬 폴더 구현.
- 2-C-2 실행 — "지금 동기화" 버튼이 먼저. 자동(시작·종료·몇 분마다)은 별도 스위치, 기본 off. TaskManager 작업으로 실행(feature `sync`).
- 2-C-3 상태 — 마지막 동기화 시각, 진행, 실패 원인, 동기화 기록.

**2-D 구글 드라이브**
- 2-D-1 로그인 — OAuth(PKCE). 토큰은 keyring에. 권한은 앱 전용 폴더만(Least Privilege). 데스크톱과 Android의 로그인 흐름이 다르므로 따로 확인.
- 2-D-2 `SyncTarget` 구현 — 큰 파일 이어 올리기, Android의 "Wi-Fi에서만" 옵션.
- 2-D-3 연결 끊기 — 토큰 삭제. 클라우드에 올린 데이터 지우기는 따로 확인을 받는다.

**2-E 충돌·기록 화면** — 둘 다 남긴 항목을 나란히 보고 고르기, 기기별 마지막 동기화, 되돌리기(적용 전 백업으로).

### 3단계 — AI 기능 확장

**현재** 어댑터(claude·gemini·openai·vertexai·nai)는 글 생성·스트리밍·그림만 한다. 메모리 관련 테이블은 있고 코드는 없다(ADR-003). 대화별 수동 메모·작가 노트는 있다(`service/chat/notes.rs`).

**3-A 어댑터 확장** (선행 작업)
- 3-A-1 임베딩 — `AiService`에 임베딩 호출을 추가하고 사용량 기록에 종류를 추가한다. 어디: `adapter/*.rs`, `service/ai/ai_service.rs`, `db/usage.rs`.
- 3-A-2 도구 호출 — 요청에 도구 목록, 응답에서 도구 호출 파싱(스트리밍 포함), 공급자별로. 어디: `adapter/*.rs`, `adapter/sse.rs`.
- 3-A-3 구조화 출력 — JSON 스키마에 맞춘 응답. 지원하지 않는 공급자는 "JSON만 답하라" 지시 + 검증으로 대체.
- 3-A-4 지원 표 — 공급자·모델별로 무엇이 되는지 한 곳에 두고, 안 되면 화면이 이유를 보여준다.

**3-B 메시지 linter** (플러그인 `lint`, 기본 off)
- 3-B-1 ADR — 실행 자리(응답 저장 → 정규식 → linter)와 정규식과의 관계를 정한다.
- 3-B-2 무료 규칙 — 요금 없이 앱 안에서: 닫히지 않은 태그·따옴표·마크다운, 반복 문단, 사용자 대사 대신 쓰기 감지, 금지어, 길이. 규칙마다 "표시만 / 자동 고침". 어디: `service/chat/` 아래 새 모듈. 완료: 규칙별 단위 테스트, 스트리밍 중에는 돌지 않음.
- 3-B-3 원본 보존 — 고친 결과는 메시지 meta에 원문과 고친 목록을 남기고, 메시지에서 "원문 보기 / 되돌리기".
- 3-B-4 유료 규칙 (2026-11-18 ADR-017로 바뀜: 코어 재생성의 "지시 추가" + 코어 플러그인 `rewrite`(자동 재생성), 대상은 금지어·단어 반복 오류, 완료) — — AI에게 다시 쓰게 하기. 별도 스위치(기본 off), `run_by = auto`, 응답당 최대 한 번, 1-A 한도 안에서. 선행: 1-A.
- 3-B-5 설정 화면 — 규칙 목록, 대화별 덮어쓰기, 오른쪽 패널에 이번 응답에서 걸린 규칙.

**3-C 임베딩 검색** (플러그인 `memory`, 기본 off, 새 ADR 필요)
- 3-C-1 ADR — 임베딩 제공자·모델, 색인 단위(메시지 / 묶음 / 요약), 비용 상한, 모델을 바꾸면 다시 색인.
- 3-C-2 저장과 검색 — `memory_embeddings`에 벡터·모델 id·원문 해시. 검색은 먼저 메모리 안 코사인 계산으로, 느려지면 그때 벡터 확장을 검토.
- 3-C-3 색인 실행 — "이 대화 색인" 버튼(예상 토큰을 먼저 보여줌). 자동 색인은 별도 스위치. 해시로 같은 글을 두 번 색인하지 않는다(공용 번역 캐시와 같은 방식).
- 3-C-4 찾기 화면 — 뜻으로 찾기(대화 안 / 전체). 프롬프트를 건드리지 않으므로 이것부터.
- 3-C-5 컨텍스트에 넣기 — 보낼 때 관련된 지난 내용을 프롬프트 블록으로 넣는다(토큰 상한). 컨텍스트 탭에 무엇이 들어갔는지 보여준다. 보낼 때마다 질의 임베딩 호출이 생긴다는 점을 설정에 적는다. 어디: `service/prompt/`, `service/chat/context_manager.rs`.
- 3-C-6 무효화 — 메시지 수정·삭제·분기 때 색인 정리. (완료: ADR-015 "추가 3-C-6")

**3-D 대화 요약** — (2026-11-18 사용자 결정으로 바뀜, ADR-016) 별도 코어 플러그인 `summary`(메모리 확장). 켜면 그것이 동의라 프롬프트 창 밖으로 밀려난 대화가 쌓일 때 자동으로 요약해 AI에게 전달한다(제안 확인 없음, 매 채팅 아님). 사용자의 메모는 AI에게 보내지 않는다. 완료.

### 4단계 — 게임 엔진 확장

**현재** 템플릿은 dating-sim 하나(`src-tauri/resources/templates/`), 플레이 화면은 `src/features/game/play/vn/` 하나. capabilities는 선언만 한다(게임 ADR-016). StoryPlan은 보류(게임 ADR-019), `game_story_plans` 테이블은 있다.

**4-A 미결 정리** — 게임 ADR의 "미결·후속 작업"과 "ADR-018 갱신"의 후속 항목을 코드와 대조한다. 이미 된 것은 ADR에서 지우고, 남은 것(예: AI의 아이템 지급, 게임 삭제 시 로어북 정리, 일지 성장 정책)을 항목별로 처리한다.

**4-B 템플릿 구조**
- 4-B-1 capabilities 강제 — 꺼진 능력의 행동은 엔진이 거절하고(`GAME_ACTION_BLOCKED`에 이유 추가), `get_game_view`가 꺼진 것을 빼고, 편집기도 해당 탭을 숨긴다. 어디: `game/template.rs`, `game/engine.rs`, `game/guard.rs`, `features/game/editor/`.
- 4-B-2 화면 레지스트리 — 템플릿 id → 플레이 컴포넌트를 필요할 때 불러온다(Lazy Initialization). 공용(런타임 store·대사 기록·세션 탭)과 템플릿별 화면을 나눈다. 어디: `features/game/play/`, `features/game/runtime/`.
- 4-B-3 템플릿 전환 표시 — 규칙 템플릿(엔진이 무엇을 허용하나)과 화면 템플릿(어떻게 그리나)을 나눈다. 게임이 쓰는 capabilities를 화면 템플릿이 모두 지원할 때만 전환할 수 있다. 고른 화면은 세션 옵션에 저장하고 게임 데이터는 바꾸지 않는다. 완료: 같은 세션을 두 화면으로 번갈아 열어도 진행 상태가 같다.
- 4-B-4 버전 검사 — 템플릿 패키지의 format_version·apiVersion이 맞지 않으면 여는 대신 이유를 보여준다.

**4-C 새 템플릿**
- 4-C-1 대화 전용 템플릿(지도·시간 없음) — 가장 작고, 4-B-1의 검증용.
- 4-C-2 2D RPG 화면 템플릿 — pixi.js(지금은 위젯 마스코트에서만 씀)로 타일 맵·이동·맵 스프라이트. 엔진 규칙은 그대로 두고 화면만 다르게(위치 = 구역). 모바일 터치 조작 포함. 4-B-3의 시험대.
- 4-C-3 템플릿마다 — 번들 패키지, 역직렬화 테스트, 편집기 지원 범위 표.

**4-D StoryPlan 각본가** (게임 ADR-019, 기본 off) — 선행: 1-A, 3-A-3. 체크포인트에서만 별도 호출, 출력은 스키마·크기·존재하는 id로 검증, 엔진 상태를 직접 바꾸지 않음.

### 5단계 — 사용자 경험 및 자동화

**5-A 선톡** (플러그인 `proactive`, 기본 off, 새 ADR 필요) — 선행: 1-A
- 5-A-1 ADR — 누가(캐릭터별 허용), 언제(조용한 시간·최소 간격·하루 최대 횟수), 어디서(먼저 앱이 켜져 있을 때만), 선톡 전용 하루 상한.
- 5-A-2 스케줄러 — 기능이 꺼져 있으면 타이머를 만들지 않는다. 켜면 "다음 실행 시각" 하나만 예약한다. 어디: 새 모듈 + `proactive_settings`.
- 5-A-3 실행 — 채팅 생성 작업을 `run_by = auto`, 이름 "선톡"으로. 실패해도 다시 시도하지 않는다.
- 5-A-4 화면 — 캐릭터별 스위치, 다음 예정 시각과 "이번은 건너뛰기", 실행 기록의 자동 필터, 알림.
- 5-A-5 연동 — 폰 모드의 읽지 않음 표시, 위젯 마스코트 말풍선.
- 5-A-6 Android 백그라운드 — **결정 필요**: 앱이 꺼진 동안의 선톡은 배터리·OS 제한이 있어 별도로 정한다.

**5-B AI 에이전트** (플러그인 `agent`, 기본 off, 새 ADR 필요) — 선행: 1-A, 3-A-2
- 5-B-1 ADR — 할 수 있는 일(도구 목록), 승인 방식, 실행당 최대 단계·토큰.
- 5-B-2 도구 등록소 — 읽기 도구(캐릭터·로어북·대화 찾기)와 쓰기 도구(로어북 항목, 프로필 수정, 게임 씬 초안). 도구마다 필요한 권한을 선언한다(Least Privilege).
- 5-B-3 제안 → 승인 — 쓰기 도구는 원본을 바로 바꾸지 않고 "제안"을 만든다. 사용자가 바뀌는 부분을 보고 승인하면 적용한다.
- 5-B-4 실행 루프 — 에이전트 실행 하나 = 작업 하나. 단계마다 시도·도구 호출을 기록하고(`agent_*` 테이블) 언제든 멈출 수 있다.
- 5-B-5 첫 사용처 — ① 로어북 정리 도우미 ② 대화 → 캐릭터·사용자 프로필 갱신 제안 ③ 게임 씬 초안(아이디어 스케치).
- 5-B-6 화면 — 진행 중 단계, 도구 호출 내역, 승인 대기 목록.

**5-C 접근성 및 사용 편의성**
- 5-C-1 단축키 — 동작 목록(이름·실행 함수·기본 키)을 한 곳에 두고 단축키·명령 팔레트·메뉴가 같이 쓴다. 키 바꾸기, 충돌 검사, 기본값으로. 어디: `features/settings/ShortcutSection.svelte`(지금은 목록 보기만).
- 5-C-2 다국어 — 먼저 하드코딩 한글이 새로 늘지 않게 검사를 CI에 건다. 그다음 공용 UI(`shared/ui`, `app`) → 설정 → 채팅 → 나머지 순서로 옮긴다. 백엔드가 주는 글자(플러그인 이름·오류 메시지)는 키나 코드로 보내고 프런트가 번역한다.
- 5-C-3 접근성 — 키보드만으로 전 기능(포커스 순서·표시, 대화상자 안에 포커스 가두기), 버튼 이름(aria), 글자 크기·줄 간격 설정, 움직임 줄이기, 테마 편집기의 대비 경고, 스트리밍 응답을 스크린 리더가 읽게.
- 5-C-4 모바일 최적화 (1-C 뒤) — 스와이프(다른 응답·옆 패널), 하단 탐색, 한 손 조작.
- 5-C-5 알림 정책 — 종류별(응답 완료·선톡·작업 실패·동기화) 켬/끔, 조용한 시간, 앱이 앞에 있으면 끄기.
- 5-C-6 처음 실행 안내 — API 연결 → 캐릭터 가져오기 → 첫 대화. 빈 화면마다 다음에 할 일을 보여준다.

**5-D 대필** (플러그인 `ghostwrite`, 기본 꺼짐, ADR-018, 완료) — 펜 버튼 → 초안 작성 → AI가 내 말투의 다음 대사를 써서 입력칸에 채움(보내지 않음). 옵션: 초안 없이 바로 요청. 어디: `service/chat/ghost.rs`, `ChatManager::ghost`, `commands/ghost.rs`, `features/ghost/`. 완료: 지시 글·정리·프롬프트 마무리 테스트.

### 6단계 — 생태계 및 확장성

- **6-A 형식 명세** — `.scpack`·`.tgame`·`.scbackup`·테마 JSON을 문서로 적고 format_version 호환 규칙을 정한다. 다른 앱 카드의 가져오기 범위를 넓히고 내보내기도 지원한다.
- **6-B 선언형 확장 묶음** — 코드가 없는 것(프롬프트 묶음·정규식 묶음·linter 규칙·테마·HTML 상태창)을 파일 하나로 주고받는다. 가져올 때 내용을 미리 보여주고 HTML/JS가 들어 있으면 표시한다.
- **6-C 게임 iframe SDK 재개** (ADR-003 보류, 게임 ADR-002) — 외부 HTML/JS 게임과 사용자 템플릿. 호스트 전용 커맨드와 게임이 부를 수 있는 커맨드를 나눈다.
- **6-D 커뮤니티 플러그인** (코어 플러그인 `community`, 기본 off, ADR-012) — 결정(2026-11-17): 격리된 JS(sandbox iframe) + manifest 권한 선언, 확장 지점은 후처리·프롬프트·화면·데이터, AI 호출은 `ai` 권한 + 작업·한도 안에서, 설치는 파일·폴더로만. 세부 항목은 M16.
- **6-E 문서와 예제** — 사용 설명서, 예제 캐릭터·게임, 제작 안내.
- **6-F 공유 방법** — **결정 필요**: 온라인 저장소는 운영 비용과 책임이 따르므로 파일·링크 가져오기부터. AGPL-3.0이 확장 배포에 주는 조건도 정리한다.
