- **3-B-4 후속**: 사슬 전체를 실제 앱에서 확인(사용자가 보내면 자동 작업이 먼저 멈추는지·끊긴 작업 폐기·후처리 지연), **대필 플러그인**("내 대사 대신 쓰기"를 기능으로 — 지금은 linter 규칙으로만 있음), 규칙별 자동 재생성 결과를 실행 기록에서 보기

- **3-D 후속**: 두 기기 사이 요약 동기화(고친 글 우선·더 많이 반영한 쪽 병합), 요약 프롬프트를 고치는 앱 프롬프트 슬롯, 폰 대화 패널의 요약 구역, 요약 입력에 프롬프트용 정규식 통과

- **3-B-5 남은 것**: 폰 엿보기·게임 대사에는 linter가 적용되지 않음
- **3-C-5 후속**: "이번 보내기만 회상 건너뛰기" 단추, 컨텍스트 탭에서 회상한 대화로 이동, 회상 기록을 사용자 메시지에 두기(지금은 응답 meta), 질의를 프롬프트용 정규식에 통과시키기
- **3-C 후속**: 커맨드를 거치지 않는 경로(플러그인 후처리·linter 되돌리기)가 바꾼 글의 색인 즉시 맞추기, 검색 결과에서 오래된 메시지로 바로 이동("메시지 주변 읽기" API 필요), 자동 색인(별도 스위치·`run_by = auto`·한도), f16/int8 저장, 4000자 넘는 한 메시지의 뒷부분

### 확인하지 못한 것 (실제 환경에서 확인해야 함)

- 3-A: 실제 OpenAI·Claude·Gemini·Vertex 호출(가짜 서버로만 확인), Vertex `:predict`의 네트워크 구간, GPT-5·o 계열 `max_completion_tokens`
- 3-B: 설정 화면·메시지 아래 알림·대화 패널은 타입 검사와 단위 테스트까지(실제 앱 화면 확인 못 함), 응답 → linter → 플러그인 후처리 순서의 E2E
- 3-B-4: 사슬 전체(작업 제출·선취·취소·재개)는 앱 핸들이 있어야 해서 단위 테스트가 없음 — 결정·묶음·스와이프 고르기·payload만 테스트. 화면(설정·패널·표시)은 타입 검사와 가짜 응답까지
- 5-D: `ChatManager::ghost` 전체(컨텍스트·공급자 호출·취소)는 앱 핸들이 있어야 해서 단위 테스트가 없음 — 지시·정리·프롬프트 마무리만. 화면은 미리보기(가짜 응답)에서 펜→작성창(입력 prefill)→채움→원래대로까지 확인
- 3-D: 실제 공급자로 요약이 도는 것, 실제 앱에서 응답 뒤 자동 요약·분기·되돌리기, 화면(패널·설정)은 타입 검사와 가짜 응답까지
- 3-C: 실제 공급자·실제 앱에서 색인·검색·자동 회상, 시간 초과(4초) 경로의 테스트(가짜 서버에 지연 없음)
