## 좁은 화면 (1-C-3)

| 화면 | 결과 |
| --- | --- |
| 캐릭터·게임·로어북 목록 | 제목이 "캐릭/터"로 잘림 → 도구 줄이 제목 아래로 내려가게 |
| 설정 | 그룹 제목("API별 사용량")이 두 줄 → 같은 방식 |
| 채팅 | 입력칸 안내에서 Ctrl+Enter를 뺌 (터치 화면) |
| 게임 편집기 | 가로 탭 글자가 한 글자씩 세로로 쪼개짐 → 줄이지 않고 옆으로 넘김. 제목 입력칸 테두리 두 겹(데스크톱도) → 편집기 CSS가 공용 Input을 건드리지 않게 |
| 게임 플레이·폰·이미지 | 문제 없음 |
| 누르는 대상 | 작은 버튼(28~34px)도 터치 화면에서는 누르는 범위를 44px로 (`--touch-target`, 보이는 크기는 그대로) |
| 오른쪽 클릭 메뉴 | 꾹 누르면 열림(WebView가 contextmenu를 보냄). 카드는 꾹 눌러도 글자가 선택되지 않게 |
| 끌어서 순서 | 손가락으로는 HTML 드래그가 시작되지 않음 → 손잡이(⋮⋮)를 누른 채 끌면 옮겨짐 (`Sortable.handle`). 로어북 항목에도 터치 화면에서만 손잡이 |

## 남은 것

- 실기기 확인 (에뮬레이터만 함). 특히 제조사별 배터리 정책(백그라운드 서비스).
- 알림 권한 묻기: 서비스 알림은 권한이 없으면 보이지 않는다(서비스는 동작). 알림 정책(5-C-5)에서.
- 대화상자·오른쪽 패널이 열려 있을 때 뒤로 가기는 그것을 닫지 않고 화면을 이동한다 (5-C-4).
- 게임 편집기 가로 탭 아래 빈 공간, 게임 플레이 아래 도구 줄이 캐릭터 그림과 겹침 (5-C-4).
- 개발 모드(`android:dev`)에서는 앱이 뒤로 갔다 오면 vite가 페이지를 다시 불러온다 (배포 빌드에는 없음).
- 쓰이지 않는 `tauri-plugin-background-service` 의존성 정리.
