## 동기화 (M12, 2026-11-17)

PC는 E2E용 데스크톱 빌드(`com.dilly311.sandcastle.e2e`, 실제 사용자 데이터와 다른 폴더), 폰은 에뮬레이터의 디버그 빌드. 두 앱의 WebView에 원격 디버깅으로 붙어 화면 버튼이 부르는 것과 같은 커맨드로 주고받음.

| 항목 | 결과 |
| --- | --- |
| 폰 → PC (처음) | O — 행 221개 중 211개 추가·10개 같음(기본 페르소나·프리셋 등), 파일 40개, 충돌 0. 적용 전 사본 `sync-backups/` 생김 |
| 경로 바꾸기 | O — 폰의 `/data/user/0/…/characters/avatars/…` → 묶음 안 `$SANDCASTLE_DATA$/…` → PC `C:/Users/…/characters/avatars/…`. 묶음 안에 폰 경로가 남지 않음. PC에서 아바타가 그대로 보임(400×600) |
| 게임 | O — 받은 게임을 열면 진단 오류 0, 에셋(`game.localhost`) 200 |
| PC → 폰 (처음) | **X** → 고침 — PC가 고친 대화 제목이 충돌로, PC의 캐릭터 지우기가 "이 기기 고침 유지"로 막힘. 폰이 PC에게서 처음 받는 것이라 폰의 모든 행을 "폰에서 고친 것"으로 봤기 때문 (PC는 이미 폰의 묶음을 합쳐 그 행들을 봤는데 묶음이 그걸 말해 주지 않음). 묶음에 `acks`(보낸 쪽이 합친 다른 기기 묶음의 시각)와 `held`(보낸 쪽이 자기 것을 둔 충돌 행)를 넣음 (ADR-011) |
| 고친 뒤 PC가 지움 → 폰 | O — 지움 1, 막힘 0 |
| 고친 뒤 폰이 고침 → PC | O — 변경 1, 충돌 0, 양쪽 이름 같음 |
| 양쪽이 같은 대화 제목을 고침 | O — 양쪽 다 자기 제목을 두고 받은 것은 충돌 목록에 (한쪽이 덮어쓰지 않음) |
| 같은 대화에 양쪽이 이어 씀 | O — 받은 쪽마다 "… · 다른 기기" 분기 대화 |
| Android 파일 고르기 | O — 시스템 파일 고르기(다운로드) → `content://` → 앱 임시 폴더로 복사(.scsync) → 미리보기. 이미 합친 묶음은 "이미 합친 묶음"으로 거절 |
| 남은 어긋남 | 고치기 전 첫 교환에서 폰이 거절한 지우기("테스트" 캐릭터)는 PC의 지운 기록이 "이미 본 것"이 되어 폰에만 남음 — 고친 뒤에는 생기지 않음. 개발 데이터라 그대로 둠 |

## 남은 것

- 실기기 확인 (에뮬레이터만 함). 특히 제조사별 배터리 정책(백그라운드 서비스).
- 동기화: 저장 대화상자(SAF)로 내보내기는 백업과 같은 길(`saveTo`)이라 따로 누르지 않음. 큰 묶음(수백 MB)의 시간·메모리.
- 알림 권한 묻기: 서비스 알림은 권한이 없으면 보이지 않는다(서비스는 동작). 알림 정책(5-C-5)에서.
- 대화상자·오른쪽 패널이 열려 있을 때 뒤로 가기는 그것을 닫지 않고 화면을 이동한다 (5-C-4).
- 게임 편집기 가로 탭 아래 빈 공간, 게임 플레이 아래 도구 줄이 캐릭터 그림과 겹침 (5-C-4).
- 개발 모드(`android:dev`)에서는 앱이 뒤로 갔다 오면 vite가 페이지를 다시 불러온다 (배포 빌드에는 없음).
- 쓰이지 않는 `tauri-plugin-background-service` 의존성 정리.
