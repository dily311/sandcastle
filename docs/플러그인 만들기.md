# 플러그인 만들기

Sandcastle의 커뮤니티 플러그인은 JavaScript로 만듭니다. 플러그인은 앱 안에서 **격리된 곳**에 갇혀 돌고, 사용자가 허락한 **권한**의 기능만 쓸 수 있습니다. 설계의 이유와 결정은 `docs/아키텍처 결정 기록 (ADR) — 프로젝트 전반.md`의 ADR-012에 있습니다.

> 이 문서의 내용은 앱 버전 0.2.x, 플러그인 API 버전(`apiVersion`) **1** 기준입니다. 완성된 예제는 `examples/plugins/`에 있습니다 — 먼저 `word-count`를 열어 보세요.

## 1. 5분 만에 시작하기

폴더를 하나 만들고 파일 두 개를 넣습니다.

`hello/manifest.json`

```json
{
  "id": "hello",
  "name": "안녕",
  "version": "0.1.0",
  "apiVersion": 1,
  "description": "시작하면 기록에 인사를 남깁니다"
}
```

`hello/main.js`

```js
sandcastle.app.info().then((info) => sandcastle.log("안녕! 나는", info.pluginId));
```

> `main.js`는 일반 스크립트라 맨 위에서 `await`를 바로 쓸 수 없습니다. `.then(...)`을 쓰거나 `async` 함수로 감싸세요.

설치해서 확인합니다.

1. 설정 > 코어 플러그인에서 **커뮤니티 플러그인**을 켭니다 (기본 꺼짐).
2. 설정 > 커뮤니티 플러그인 > **폴더에서 설치** → `hello` 폴더를 고릅니다.
3. 미리보기를 확인하고 설치합니다. 설치해도 **꺼진 채**입니다.
4. 목록의 스위치를 켜고 권한 동의 창에서 **허락하고 켜기**를 누릅니다.
5. 플러그인 줄의 화살표를 펴고 **기록 보기**에서 인사가 보이면 성공입니다.

코드를 고친 뒤에는 같은 폴더를 **폴더로 업데이트**로 다시 고르면 됩니다.

## 2. 폴더 구조와 설치 형식

```
my-plugin/
├── manifest.json        필수. 맨 위에 있어야 함
├── main.js              필수(이름은 manifest의 main으로 바꿀 수 있음). 보이지 않는 곳에서 돈다
└── ui/                  선택. 패널 화면(html·css·js)과 그림
    ├── panel.html
    ├── panel.css
    └── panel.js
```

- **zip**으로 묶을 때는 폴더 *안의* 내용을 묶으세요(`manifest.json`이 zip의 맨 위). 폴더 하나로 감싼 zip(`my-plugin/manifest.json`)도 받아 주지만 그 폴더 하나뿐일 때만입니다.
- 받아 주는 파일: `js` `mjs` `css` `html` `json` `md` `txt` `png` `jpg` `jpeg` `webp` `gif` `svg` `woff` `woff2` `ttf` `otf`. 그 밖의 파일(`exe` `dll` 등)이 하나라도 있으면 설치되지 않습니다.
- 한 플러그인은 **파일 300개, 5MB**까지.
- `.`으로 시작하는 파일·폴더(`.git` 등)와 `__MACOSX`는 건너뜁니다.
- 경로에 `..`, 절대 경로, `\`가 있거나 링크(심볼릭 링크)가 있으면 설치를 거절합니다.

PowerShell에서 zip 만들기:

```powershell
Compress-Archive -Path .\my-plugin\* -DestinationPath my-plugin-1.0.0.zip
```

설치는 **미리보기 → 설치 → 켜기** 세 단계로 나뉩니다. 미리보기에서 본 파일과 설치되는 파일이 다르면(그 사이 파일이 바뀌면) 앱이 설치를 거절합니다.

## 3. manifest.json

| 칸 | 필수 | 설명 |
| --- | --- | --- |
| `id` | O | 소문자·숫자·`-`, 2~64자, 글자나 숫자로 시작. 앱 안에서 유일. **한 번 정하면 바꾸지 마세요** (바꾸면 다른 플러그인이 됨) |
| `name` | O | 사용자에게 보이는 이름, 80자까지 |
| `version` | O | `1.2.3` 같은 판 이름. 업데이트 비교에 쓰임 |
| `apiVersion` | O | 이 문서의 판은 `1`. 앱이 지원하는 것보다 크면 설치되지 않음 |
| `author` | | 작성자 |
| `description` | | 설명, 500자까지 |
| `main` | | 시작 스크립트, 플러그인 폴더 안의 `.js` (기본 `main.js`) |
| `permissions` | | 필요한 권한 목록 → [권한](#4-권한). 없는 권한을 쓰면 그 기능이 거절됨 |
| `settings` | | 사용자가 앱 설정 화면에서 고칠 설정칸 → 아래 |
| `panels` | | 오른쪽 패널 화면, 5개까지. `ui.panel` 권한 필요 |
| `commands` | | 명령 메뉴 항목, 20개까지. `ui.command` 권한 필요 |
| `minAppVersion` | | 이 앱 판 이상이 필요할 때 |

**panels**와 **commands**

```json
"panels":   [{ "id": "main", "title": "글자 수", "page": "ui/panel.html" }],
"commands": [{ "id": "count", "title": "이 대화 글자 세기" }]
```

`id`는 글자·숫자·`-`·`_` 32자까지(플러그인 안에서 유일), `title`은 40자까지. `page`는 플러그인 폴더 안의 `.html`이고 묶음에 실제로 있어야 합니다.

**settings**: 앱이 설정 화면을 그려 줍니다. 값은 `sandcastle.settings.get()`으로 읽습니다.

```json
"settings": [
  { "key": "countSpaces", "type": "toggle", "label": "공백도 세기", "default": true },
  { "key": "recent", "type": "number", "label": "최근 메시지 수", "description": "최대 200", "default": 100 },
  { "key": "length", "type": "select", "label": "길이", "options": ["짧게", "자세히"], "default": "짧게" },
  { "key": "greeting", "type": "text", "label": "인사말", "default": "안녕" }
]
```

- `type`은 `text`(2000자까지) · `number` · `toggle` · `select`(`options` 필요). 50칸까지.
- `default`를 안 쓰면 글은 빈 글, 숫자는 0, toggle은 `false`, select는 첫 항목.
- 사용자가 값을 바꾸면 플러그인이 **다시 시작**되어 새 값을 읽습니다.
- 설정은 사용자의 것입니다. 플러그인이 쓸 수 없고, 화면에는 "여기 적은 값은 플러그인이 읽을 수 있음, 비밀번호·API 키는 넣지 마세요" 안내가 붙습니다.

이름·설명·제목에 섞인 제어 문자와 글자 방향을 바꾸는 문자는 앱이 지웁니다. 앱은 어디서든 이름 옆에 `id`를 같이 보여 줍니다.

## 4. 권한

`permissions`에 적은 권한은 **켤 때 사용자가 전부 한꺼번에 허락**합니다(일부만 허락할 수 없음). 설치 미리보기와 켜기 창에 위험도와 함께 설명이 보이므로, **필요한 것만** 적으세요. 권한이 많으면 사용자가 켜기를 망설입니다.

| 권한 | 위험도 | 할 수 있는 일 |
| --- | --- | --- |
| `storage` | 낮음 | 이 플러그인만 쓰는 작은 저장소 (1MB) |
| `ui.panel` | 낮음 | 오른쪽 패널에 화면 추가 |
| `ui.command` | 낮음 | 타이틀바 플러그인 명령 메뉴에 항목 추가 (누를 때만 실행) |
| `messages.process` | 보통 | 새 AI 응답을 읽고 메모를 붙임. 사용자가 '자동 고침'을 고르면 글도 바꿈 |
| `prompt.modify` | 보통 | AI에게 보내기 전에 규칙·안내 글을 **더함** (있는 것을 고치거나 빼지는 못함) |
| `data.read:character` `data.read:persona` `data.read:lorebook` | 보통 | 해당 데이터의 글 칸 읽기 (파일 경로는 못 봄) |
| `data.read:chat` | **주의** | 대화의 메시지 내용 읽기 |
| `data.write:character` `…:persona` `…:lorebook` `…:chat` | 보통 | 고치기를 **제안** (사용자가 승인해야만 바뀜) |
| `ai` | **주의** | 연결된 AI API로 글 만들기 (요금이 들 수 있음) |

manifest에 없는 권한이 필요한 SDK 함수를 부르면 `권한이 없음` 오류로 거절됩니다. 앱이 모르는 권한 이름이 있으면 설치가 거절됩니다.

업데이트로 권한이 **늘면** 플러그인이 꺼지고 사용자가 다시 켜서 늘어난 권한에 동의해야 합니다. 권한이 줄었다가 다시 늘어도 이전 허락은 되살아나지 않습니다.

## 5. 실행 환경: 무엇이 되고 무엇이 안 되나

플러그인의 `main.js`는 앱 화면과 **분리된 숨은 iframe**(`sandbox="allow-scripts"`)에서 돕니다. 패널 화면도 따로 iframe입니다.

**됩니다**

- 보통의 브라우저 JavaScript (`Promise`, `async/await`, `setTimeout`, `JSON`, `Date`, DOM 등. 네트워크만 빠짐 — 아래)
- `window.sandcastle` (SDK, 아래 참고)
- 폴더 안의 css·그림·글꼴을 패널에서 쓰기

**안 됩니다**

- **네트워크**: `fetch`, `XMLHttpRequest`, `WebSocket`, 외부 이미지·스크립트·CDN 모두 막힙니다. 외부 서비스가 필요하면 만들 수 없습니다.
- 앱 화면의 DOM, 다른 플러그인, 앱의 저장소·파일 시스템, API 키에 접근
- `localStorage`/`sessionStorage`/쿠키 (→ `sandcastle.storage`를 쓰세요)
- 인라인 `<script>`, `eval`, 다른 곳의 스크립트 (패널 페이지는 폴더 안의 `.js` 파일만 `<script src=…>`로)
- 폼 전송, 하위 프레임

`main.js`는 한 파일로 쓰는 것을 권합니다. 코드는 설치된 뒤 바뀌지 않아야 하므로 CDN이나 외부 파일을 받아 쓰지 못합니다 — 필요한 라이브러리는 폴더에 넣어 두세요 (5MB 안에서).

플러그인은 **켜진 동안에만** 불러옵니다. 앱을 켜면 켜진 플러그인만 시작하고, 끄거나 지우거나 업데이트하면 곧바로 내립니다. 설정을 바꾸거나 다른 플러그인을 설치해도 모든 플러그인이 다시 시작될 수 있으니 시작할 때마다 같은 일이 안전하게 반복되도록 만드세요.

## 6. SDK 레퍼런스

`window.sandcastle`로 쓰고, 모든 함수는 `Promise`를 돌려줍니다(`on` 제외). 응답이 15초 안에 오지 않으면 `응답 없음` 오류가 납니다. 오류는 `Error` 객체이고 `code`가 붙을 수 있습니다.

### 로그와 앱 정보 (권한 필요 없음)

| 함수 | 설명 |
| --- | --- |
| `sandcastle.log(...값)` | 기록에 남김 (설정 > 커뮤니티 플러그인 > 기록 보기, 최근 200개, 앱을 다시 켜면 비워짐) |
| `sandcastle.warn(...값)` | 경고로 남김 |
| `sandcastle.app.info()` | `{ appVersion, apiVersion, pluginId, version, permissions }` |
| `sandcastle.app.context()` | 지금 화면: `{ page, conversationId, characterId }` (없으면 `null`). id만 줌 |
| `sandcastle.settings.get()` | manifest `settings`의 현재 값 객체 (기본값 채움) |

처리 안 된 오류와 `Promise` 거절은 앱이 자동으로 기록에 남깁니다.

### 저장소 — `storage` 권한

```js
await sandcastle.storage.set("last", { chars: 120 }); // 값은 JSON으로 바꿀 수 있는 것. null이면 지움
const last = await sandcastle.storage.get("last");    // 없으면 null
await sandcastle.storage.delete("last");
const keys = await sandcastle.storage.keys();
```

키 200자, 값 64KB, 키 1000개, 합계 1MB까지. `__`로 시작하는 키는 앱이 쓰므로 못 씁니다. 저장소는 이 기기의 앱 DB에 있어 백업에는 들어가지만 **다른 기기로 동기화되지는 않습니다.** 플러그인을 지우면(휴지통) 저장소도 같이 가고, 되살리면 같이 돌아옵니다.

### 데이터 읽기 — `data.read:*` 권한

```js
const chars = await sandcastle.data.characters.list();     // [{ id, name, tags, category }]
const c = await sandcastle.data.characters.get(id);        // { id, name, description, firstMessage, exampleDialogue,
                                                           //   creatorNotes, systemPromptOverride, tags, category }
const people = await sandcastle.data.personas.list();      // [{ id, name, tags }]
const p = await sandcastle.data.personas.get(id);          // { id, name, description, tags }
const books = await sandcastle.data.lorebooks.list();      // [{ id, name, description, entries }]  (entries = 항목 수)
const b = await sandcastle.data.lorebooks.get(id);         // { id, name, description, entries: [{ id, keys, secondaryKeys,
                                                           //   content, comment, enabled, priority, constant }] }
const convs = await sandcastle.data.chats.list({ characterId }); // [{ id, title, characterId, personaId, updatedAt }]
const msgs = await sandcastle.data.chats.messages(conversationId, { limit: 50, beforeSeq });
                                                           // 오래된 것부터 [{ id, seq, role, name, content, createdAt }]
```

- 목록은 500개까지, 메시지는 한 번에 최대 200개(`limit`, 기본 50). 더 오래된 것은 `beforeSeq`로 이어서 받습니다.
- 파일 경로(아바타·커버), 메시지의 내부 정보(meta), API 연결 정보는 주지 않습니다.
- 각 종류를 읽으려면 그 `data.read:*` 권한이 있어야 합니다 (캐릭터를 읽는 권한으로 대화를 읽을 수는 없음).

## 7. 이벤트

플러그인이 "언제 불리는가"는 앱이 정합니다. 핸들러가 값을 돌려주지 않으면(`undefined`/`null`) 아무것도 하지 않은 것입니다. 핸들러가 던진 오류는 기록에 남고, 오류가 1분에 20번 쌓이면 이번 실행 동안 그 플러그인을 **멈춥니다**(사용자가 다시 켜면 풀림).

### `command` — 사용자가 명령을 눌렀을 때

- 필요: `ui.command` 권한 + manifest의 `commands`
- 받는 값: `{ id, context }` (`context`는 `app.context()`와 같은 모양)
- 시간: 90초
- **사용자가 눌렀을 때만** 불립니다. 플러그인이 스스로 부를 수 없습니다.

```js
sandcastle.on("command", async ({ id, context }) => {
  if (id !== "count") return;
  // …
});
```

### `message.process` — 새 AI 응답이 저장된 뒤

- 필요: `messages.process` 권한
- 시점: 응답이 저장되고 정규식까지 적용된 뒤. **스트리밍 중에는 불리지 않음.** 대화·폰의 응답에만(게임 대사·폰 엿보기는 아님)
- 받는 값: `{ message: { id, role, name, conversationId, content } }` — 앞선 플러그인이 고친 글이 `content`로 옴
- 돌려줄 값: `{ content?, notes? }`
  - `notes`: 응답 아래에 붙는 메모. 글 또는 `{ level: "info" | "warn", text }`의 배열, 20개·각 500자까지. **어떤 방식이든 붙음**
  - `content`: 고친 글. 사용자가 이 플러그인을 **'자동 고침'** 으로 골랐을 때만 받아들여짐 ('표시만'이 기본). 원문은 남고 '원문 보기·되돌리기'가 붙음
- 시간: 플러그인당 5초. 설치 순서대로 부르고, 실패하거나 늦은 플러그인은 건너뜀
- **거절되는 고침**: 응답에 ` ```html ` 코드 블록(또는 태그로 시작하는 블록)을 **새로 넣거나 바꾸는** 것. 앱이 그런 블록을 살아 있는 화면으로 그릴 수 있어서 막습니다. 원래 있던 블록을 그대로 두고 다른 글을 고치는 것은 됩니다.
- 그 사이 사용자가 메시지를 고쳤으면 결과를 저장하지 않습니다.

```js
sandcastle.on("message.process", ({ message }) => {
  if (!message.content.includes("TODO")) return;
  return { notes: [{ level: "warn", text: "TODO가 남아 있습니다" }] };
});
```

### `prompt.build` — AI에게 보내기 직전

- 필요: `prompt.modify` 권한
- 받는 값: `{ conversationId, characterId, userInput }` (대화 내용이 필요하면 `data.read:chat`으로 읽기)
- 돌려줄 값: `{ blocks: [{ text, position, depth? }] }` (또는 글 배열)
  - `position: "rules"`(기본): 앱의 시스템 규칙 끝에. `position: "history"`: 대화 기록의 **끝에서 `depth`번째 앞**에 시스템 메시지로 (`depth: 0`이면 이번 입력 바로 앞)
- **더하기만** 됩니다. 있는 프롬프트를 고치거나 빼지 못합니다.
- 시간: 플러그인당 2초 (넘으면 그 플러그인은 건너뛰고 기록에 남음). 켜진 `prompt.modify` 플러그인이 없으면 앱은 기다리지도 않습니다.
- 상한: 플러그인당 블록 5개·각 4000자·1000토큰, 모든 플러그인 합쳐 2000토큰. 넘는 블록은 버립니다.
- 넣은 것은 컨텍스트 탭에 "플러그인이 더함: 이름 토큰수"로 보이고, 블록 앞에는 `[플러그인: 이름]`이 붙습니다.
- 대화·폰의 응답에만 적용됩니다 (게임 대사·폰 엿보기는 아님).

```js
sandcastle.on("prompt.build", ({ userInput }) => ({
  blocks: [{ text: "답은 항상 존댓말로 한다", position: "rules" }],
}));
```

## 8. 패널 화면 만들기

manifest의 `panels`에 `page`를 적으면 오른쪽 패널(대화·폰·게임 화면)에 탭이 생깁니다. 페이지는 일반 HTML이고, 앱이 `<head>` 맨 앞에 SDK와 `<base>`(플러그인 폴더)를 넣어 줍니다. 그래서 `panel.js`·`panel.css`를 상대 경로로 부를 수 있고 `window.sandcastle`을 바로 쓸 수 있습니다.

```html
<!doctype html>
<html>
<head><meta charset="utf-8"><link rel="stylesheet" href="panel.css"></head>
<body>
  <p id="out">…</p>
  <script src="panel.js"></script>   <!-- 인라인 <script>는 안 됨 -->
</body>
</html>
```

**테마**: 앱이 지금 테마의 색을 CSS 변수로 보내 주고, 테마를 바꾸면 다시 보냅니다. 아무것도 안 해도 앱과 같은 배경·글자색·버튼 모양으로 보입니다. 쓸 수 있는 변수:

`--bg` `--bg-sunken` `--surface` `--surface-hover` `--border` `--border-strong` `--text` `--text-muted` `--text-faint` `--text-on-accent` `--accent` `--accent-hover` `--accent-soft` `--accent-text` `--danger` `--success` `--warning` `--info` `--radius-sm` `--radius-md` `--radius-lg` `--font-sans`

**패널에서 할 수 있는 것**: 플러그인과 같은 권한으로 같은 SDK를 부릅니다. 단, 패널은 눈에 보이는 화면이므로 `ai.generate`를 부르면 **호출마다 사용자에게 확인 창**이 뜹니다([AI 호출](#9-ai-호출과-요금)). 요금이 드는 일은 명령에서 하고, 패널은 저장된 결과를 보여 주는 편이 좋습니다 (`chat-summary` 예제).

플러그인이 꺼지거나 멈추면 패널 탭은 사라집니다.

## 9. AI 호출과 요금

`sandcastle.ai.generate(prompt, options)`

| 옵션 | 설명 |
| --- | --- |
| `prompt` | 보낼 글 (필수). `system`과 합쳐 20,000자까지 |
| `system` | 시스템 지시 (선택) |
| `maxTokens` | 출력 토큰, 기본 500, 최대 2000 |
| `temperature` | 0~2, 기본 0.7 |

돌려주는 값은 `{ text, model }`입니다. 대화 기록은 자동으로 붙지 않으니 필요하면 직접 읽어 `prompt`에 넣으세요. 앱에서 고른 API 연결을 씁니다(플러그인이 고를 수 없음).

호출은 앱의 **작업**으로 실행되어 실행 기록에 "플러그인 · 이름"으로 남고, 사용량과 **예산 한도**(설정 > 실행 기록)가 그대로 적용됩니다. 실패해도 자동으로 다시 시도하지 않습니다. 한 번에 하나, 1분에 10번까지입니다.

**누가 실행했는지**는 플러그인이 정하지 못하고 앱이 봅니다:

| 상황 | 결과 |
| --- | --- |
| **사용자가 방금 누른 명령** 안 (명령 하나에 3번, 60초 안) | 사용자가 한 것으로 바로 실행 |
| 훅(`message.process`, `prompt.build`) 안 | 자동 실행 — 사용자가 설정의 **자동 AI 호출**을 켜 두어야 함. 아니면 거절 |
| 패널에서 | 자동 AI 호출이 꺼져 있으면 **호출마다 확인 창**(보낼 글·시스템 지시·글자 수·출력 상한 표시). 거절하면 30초 동안 다시 못 묻음 |
| 그 밖(숨은 곳의 타이머 등) | 자동 AI 호출이 꺼져 있으면 거절 (확인 창을 띄우지 못함) |

예산 한도를 넘으면 자동 실행은 항상 막히고, 공급자를 부르지도 않고 `BUDGET_EXCEEDED`로 실패합니다. 사용자가 누른 실행은 알림에서 "이번만 계속"을 고를 수 있습니다.

그러므로: **AI는 명령 안에서 부르는 것이 가장 좋습니다.** 훅에서 AI가 꼭 필요하다면 manifest 설명에 "자동 AI 호출을 켜야 동작함, 요금이 들 수 있음"을 적어 주세요.

## 10. 데이터를 고치고 싶을 때: 제안

플러그인은 데이터를 **직접 바꾸지 못합니다.** 대신 "이렇게 고치자"는 **제안**을 만들고, 사용자가 바뀌는 칸을 전·후로 보고 승인해야 반영됩니다.

```js
// 반환: { id, status: "pending" }
await sandcastle.data.characters.propose(id, { description: "새 설명" }, "이유를 한 줄로");
await sandcastle.data.personas.propose(id, { tags: ["친구"] }, "이유");
await sandcastle.data.lorebooks.propose(bookId, { description: "…" }, "이유");             // 로어북 자체
await sandcastle.data.lorebooks.proposeEntry(entryId, { keys: ["숲", "forest"], enabled: true }, "이유"); // 항목 고치기
await sandcastle.data.lorebooks.proposeNewEntry(bookId, { keys: ["강"], content: "…", comment: "강" }, "이유"); // 새 항목
await sandcastle.data.chats.proposeMessage(messageId, "고친 글", "이유");
```

| 종류 | 고칠 수 있는 칸 |
| --- | --- |
| 캐릭터 | `name` `description` `firstMessage` `exampleDialogue` `creatorNotes` `systemPromptOverride` `tags` |
| 페르소나 | `name` `description` `tags` |
| 로어북 | `name` `description` |
| 로어북 항목 | `keys` `secondaryKeys` `content` `comment` `enabled` (새로 만들기 가능) |
| 메시지 | `content` |

- 지우기·새 캐릭터 만들기는 제안할 수 없습니다.
- 지금 값과 같은 칸은 빠지고, 같은 제안이 이미 기다리고 있으면 그것을 돌려줍니다 (시작할 때마다 다시 제안해도 쌓이지 않음).
- 플러그인마다 기다리는 제안은 50개까지.
- 사용자가 적용하기 전에 원본이 바뀌었으면 적용되지 않습니다(덮어쓰지 않음). 적용한 것은 그 뒤 다시 고치지 않았다면 되돌릴 수 있습니다.
- 사용자는 새 제안이 오면 알림을 받고, 설정 > 커뮤니티 플러그인 > "플러그인의 고치기 제안"에서 고릅니다.

## 12. 사용자가 보는 것과 배포

사용자는 설정 > 커뮤니티 플러그인에서 다음을 봅니다. 플러그인을 만들 때 이 흐름을 알아 두세요.

1. **설치 미리보기**: 이름·id·버전·작성자·설명, 파일 수·크기·코드 지문, **요청 권한(위험도 순)**. "믿을 수 있는 곳에서 받은 것만" 경고가 보입니다. 업데이트면 이전 버전과 늘어난 권한이 강조됩니다.
2. **켜기 동의**: 권한 전부를 보고 한 번에 허락.
3. **자세히**: 권한, AI 응답 후처리 방식(표시만/자동 고침), 자동 AI 호출 스위치, 설정칸, 기록, 업데이트, 삭제.
4. 삭제는 휴지통으로 가고 되살리면 **꺼진 채** 돌아옵니다.

앱이 사용자를 지키려고 하는 일들 — 플러그인이 알아 둘 것:

- **코드가 바뀌면 꺼집니다.** 켤 때의 코드 지문을 기억하고, 폴더의 파일이 달라지면(직접 고침 등) "코드가 바뀌어 꺼짐"이 되어 다시 켜서 동의해야 합니다. 업데이트는 설치 화면을 거치므로 해당하지 않습니다.
- **백업을 복원하면 모든 플러그인이 꺼집니다** (남이 만든 백업이 동의 없이 코드를 돌리지 않게).
- 플러그인은 **기기마다** 설치합니다. 동기화되지 않습니다. 켜짐·허락도 기기마다입니다.
- Android에서는 zip으로 설치합니다 (폴더 고르기는 데스크톱만).

배포할 때는 zip과 함께 다음을 적어 두면 사용자가 판단하기 쉽습니다: 무엇을 하는지, **왜 그 권한이 필요한지**, AI를 부르는지(요금), 대화 내용을 읽는지, 네트워크는 쓰지 않는다는 것(쓸 수 없음).

## 13. 디버깅

- **기록 보기**: 설정 > 커뮤니티 플러그인 > 플러그인 줄을 펴고 "기록 보기". `sandcastle.log`/`warn`, 처리 안 된 오류, 거절된 호출의 이유, 훅 시간 초과가 모두 여기 남습니다.
- **개발 순서**: 폴더로 설치 → 켜기 → 코드를 고침 → "폴더로 업데이트". 업데이트하면 플러그인이 새 코드로 다시 시작합니다.
- **자주 겪는 일**
  - `권한이 없음`: manifest `permissions`에 빠졌습니다 (권한을 더하면 업데이트 뒤 다시 켜서 동의해야 함).
  - `플러그인이 실행 중이 아님`: 꺼져 있거나 멈췄거나(오류 20번/분) 아직 시작 전입니다.
  - 명령 메뉴에 안 보임: `ui.command` 권한과 `commands` 선언이 둘 다 필요합니다.
  - 패널이 비어 있음: 인라인 `<script>`는 실행되지 않습니다. `<script src="panel.js">`로 쓰세요.
  - `message.process`의 `content`가 반영 안 됨: 사용자가 '자동 고침'을 골랐는지 확인하세요 (기본은 '표시만').
  - 응답 후처리가 "HTML 코드 블록" 이유로 거절됨: 새 HTML 블록은 넣을 수 없습니다.
  - `이 플러그인은 사용자가 누른 명령 밖에서 AI를 부를 수 없음`: [AI 호출](#9-ai-호출과-요금)의 표를 보세요.
- 설치가 거절되면 이유가 알림으로 뜹니다 (예: "모르는 권한", "main 파일이 없음", "넣을 수 없는 파일 종류").

## 14. 하지 못하는 것

- 네트워크·외부 서비스 호출, 파일 읽고 쓰기, 다른 플러그인과 통신
- 데이터를 직접 바꾸기·지우기 (제안만 가능)
- 있는 프롬프트를 고치거나 빼기 (더하기만)
- 게임 모드·폰 엿보기에 끼어들기 (후처리·프롬프트 훅은 대화·폰의 응답에만)
- API 키를 읽거나 사용할 API 연결을 고르기
- 온라인 목록·자동 업데이트 (설치는 파일·폴더로만, 업데이트는 사용자가 직접)
- 다른 기기로 동기화

이런 것이 필요하다면 앱 쪽의 새 기능으로 먼저 논의해야 하는 일입니다.
