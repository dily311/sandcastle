## 동기화 대용량 (1-F-3, 2026-11-18)

`cd src-tauri && SYNC_PERF_ROWS=100000 SYNC_PERF_FILES=20 SYNC_PERF_FILE_MB=50 cargo test --release --lib sync_perf -- --ignored --nocapture` (`service/data/sync_perf_tests.rs`). 캐릭터 행 N개 + 파일 M개, 폴더 저장소. 최대 메모리는 프로세스 전체(시험 도구 포함) 기준.

목표(합의): 행 10만 개·파일 1GB를 몇 분 안에, 메모리는 묶음 크기와 무관하게.

| 단계 | 1만 행 · 100MB | 10만 행 · 1GB |
| --- | --- | --- |
| 파일 해시(목록 만들기) | 0.12s · 17MB | 1.03s · 17MB |
| 묶음 만들기(파일 내용 빼고) | 0.35s · 35MB (2.3MB) | 3.0s · 171MB (22.9MB) |
| 묶음 열기·읽기 | 0.09s · 47MB | 0.61s · 348MB |
| 합치기(빈 기기에) | 1.82s · 58MB | 15.7s · 371MB |
| 동기화: 올리는 기기 | 0.84s · 77MB | 5.0s · 528MB |
| 동기화: 받는 기기(처음, 파일 받기 포함) | 3.97s · 100MB | 29.5s · 727MB |
| 동기화: 바뀐 것 없이 다시 | 2.35s · 104MB | 18.2s · 731MB |

- **시간은 기준 안**: 10만 행·1GB 왕복이 한 단계 30초 이하. 파일은 흘려 읽어 해시하므로(64KB씩) 1GB를 해시해도 메모리가 늘지 않음(17MB) — 해시 캐시는 필요 없음.
- **메모리는 기준 밖**: 행 수에 비례해 늘어 10만 행에서 700MB대. 원인은 묶음을 열 때 모든 테이블의 행을 `Vec<Map>`으로 한꺼번에 올리는 `BundleData::read`와 그 위에서 도는 한 트랜잭션 병합. 파일은 무관. 고치려면 테이블 단위(더 나아가 행 묶음 단위) 흘려 읽기·적용이 필요하고 병합 순서(부모 먼저, 테이블 안 의존)를 건드려서 따로 한다 — `plans/current-milestone.md`의 후속.
