### ADR-001 일반 대화와 게임모드 테이블 통합

**상태** Rejected (2026-11-15) — 통합하지 않는다.

**최종 판단** 일반 대화(conversations/messages)와 게임 대화(game\_conversations/game\_messages)는 별도 테이블로 유지한다.

- 게임 대화는 세션·씬(branch\_key)·seq에 묶여 있고, 책갈피 분기 때 seq까지 복사·삭제 연쇄가 필요하다. 일반 대화는 이런 제약이 없어서 한 테이블에 두면 양쪽 모두 조건 분기가 늘어난다.
- 마이그레이션 비용(기존 사용자 DB 변환)이 크고, 얻는 것은 구조의 통일성뿐이다.
- 대신 공통 부분은 코드에서 공유한다: 프롬프트 조립(PromptManager), AI 호출(AiService), 컨텍스트 예산(ContextBudget), 정규식 처리.
- 폰 UI(게임 캐릭터와 게임 밖 대화)는 일반 대화 테이블 위에서 phone\_contacts/phone\_links로 연결한다(구현됨).

아래는 검토 당시의 기록이다.

**배경** 일반 대화와 게임모드 테이블의 유사성. 아키텍처 통일성을 위해서 두 테이블을 통합하고자 함.

- 기존 대화 UI는 폰 UI로 활용하기로 함.
      폰 UI란 게임 캐릭터들과 1:1 혹은 1:n 대화를 할 수 있는 걸 말함.
      여기서 선톡 기능을 지원

**결정**

원 테이블 구조:
```
Conversation
 ├── Chat
 │    └── Messages
 │
 └── Game
      ├── GameSession
      ├── GameSave
      └── GameJournal
```

변경 후 테이블 구조:
```
Conversation
 ├── Template
 │    ├── Chat Template
 │    ├── VN Template
 │    ├── RPG Template
 │    └── Text Game Template
 │
 ├── Messages
 │
 └── GameSession (게임 템플릿에서만 생성)
      ├── GameSave
      └── GameJournal
```

- 한 계층에 통합: 대신 각 기능의 구분을 분명히 할 것.
- Conversation 세션은 공통 진입점으로 하고, GameSession은 템플릿에 따라 선택적 연결
- Chat Engine과 Game Engine의 책임소재 분명히. 대화의 공통 기능과 게임의 전용 기능을 구분하도록 할 것.

### ADR-001 추가 논의: 게임 밖의 폰 대화와 여러 세션

**상태** Proposed

**배경** 폰 UI는 게임에 접속하지 않은 상태에서도 게임 캐릭터와 대화하는 공간으로 확장한다. 사용자는 캐릭터 한 명과의 1:1 대화 또는 여러 캐릭터가 참여하는 1:n 대화를 원한다. AI 응답을 기다리는 동안 다른 대화 세션으로 이동해 대화를 이어갈 수 있어야 한다.

**제안**

- 폰은 게임 실행 여부와 무관한 독립된 대화 진입점으로 둔다. 게임 캐릭터를 대화 상대로 선택해 폰 대화를 시작할 수 있다.
- 대화 목록에서 여러 세션을 보존하고 빠르게 전환한다. 각 세션은 독립적으로 메시지와 생성 상태를 관리하며, 한 세션의 응답을 기다리는 동안 다른 세션을 사용할 수 있다.
- 게임 안에서 진행한 NPC 대화와 폰 대화는 같은 Conversation/Message 기반을 공유하되, 게임 진행 상태·장면·위치에 의존하는 맥락은 게임 세션에 남긴다. 게임 밖 폰 대화는 그 상태를 요구하지 않는다.
- 1:n 대화는 하나의 Conversation에 여러 참여자를 연결하는 방식으로 모델링한다. 누가 어떤 순서와 조건으로 발언하는지, 한 턴에서 몇 명이 응답할지, 호출 비용과 중복 발언을 어떻게 제한할지는 별도 정책이 필요하다.

**구현 난이도와 판단** 여러 세션을 열어 두고 오가는 UI 자체는 보통 수준의 작업이다. 메시지 저장과 세션별 생성 상태를 분리하고, 세션 전환 후에도 진행 중인 응답을 올바른 대화에 반영하면 된다. 다만 앱 종료·네트워크 오류 때 생성 중 상태를 복구하는 정책과 동시 요청 제한은 정해야 한다. 1:1은 현재 채팅 구조를 공통 Conversation으로 옮기면 자연스럽게 지원할 수 있다. 1:n은 참여자 관리와 발언 순서·맥락 구성 때문에 더 높은 난이도이며 단계적으로 추가하는 편이 좋다.

**권장 순서** 먼저 게임 밖 1:1 폰 대화와 여러 세션 전환을 구현하고, 이후 참여자 목록·발언 규칙을 정해 1:n 대화를 추가한다. 여러 세션은 사용자가 수동으로 오가는 것부터 지원하며, 자동으로 대화를 주고받는 백그라운드 동작은 별도 결정으로 둔다.

### ADR-001 추가 논의: 최상위 탐색과 폰 진입 버튼

**상태** Proposed

**배경** 최상위 탐색에는 홈, 프리셋, API, 게임, 설정이 필요하다. 폰은 일반 대화를 담는 주요 기능이므로 어느 화면에서도 빠르게 열 수 있도록 별도 버튼을 둘지 검토한다.

**제안**

- 홈, 프리셋, API, 게임, 설정은 기본 탐색 그룹으로 둔다. 현재처럼 접을 수 있는 사이드바를 유지한다면 여기에 배치한다.
- 폰은 이 그룹에 묻히지 않도록 상시 보이는 별도 주요 동작으로 둔다. 타이틀바 바로 아래 앱 헤더의 왼쪽에 아이콘과 “폰” 라벨을 함께 표시하고, 클릭하면 대화 목록/최근 대화로 이동한다. 새 대화 시작과 세션 전환은 폰 화면 안에서 제공한다.
- 폰을 윈도우의 네이티브 타이틀바 컨트롤 영역에 넣지는 않는다. 해당 영역은 창 이동·최소화·최대화·닫기 동작과 플랫폼 차이가 있어 기능 탐색 위치로 쓰기 어렵다. 앱 콘텐츠의 헤더에 두면 데스크톱과 모바일에서 일관되게 다룰 수 있다.
- 화면이 좁은 모바일에서는 같은 다섯 탐색 그룹과 폰 주요 동작을 하단 탐색 또는 반응형 메뉴로 재배치한다.
- 캐릭터·페르소나·월드인포 같은 관리 화면은 우선 보조 화면으로 취급하고, 폰의 새 대화 흐름이나 홈에서 진입시킨다. 별도 최상위 버튼이 다시 필요해지는지는 사용 빈도를 보고 결정한다.

**판단** 폰을 항상 눈에 띄게 두는 방향은 제품의 핵심 사용 방식과 잘 맞는다. 다만 창 조작용 타이틀바 자체보다 앱이 관리하는 헤더에 두는 편이 크기 조정과 모바일 대응이 쉽다. 버튼에는 명확한 “폰” 이름을 붙이고, 선택 상태와 읽지 않은 대화 표시를 지원할 수 있도록 한다.

**UI 시안** `src/components/AppNavigationSample.svelte`에 데스크톱 상단 탐색과 좁은 화면 하단 탐색 예시를 둔다. 폰은 강조된 독립 동작이고, 나머지 다섯 항목은 일반 탐색 버튼이다. `/phone`은 현재 대화 목록 화면을 재사용하는 진입 경로로 등록한다. 이 컴포넌트는 탐색 방향을 검토하기 위한 시안이며, 앱 전체 레이아웃에 적용하기 전 실제 화면에서 높이·스크롤·모바일 안전 영역을 확인한다.


### ADR-002 채팅 생성 작업(Task) 실행 흐름

**상태** Accepted

**결정**

- 채팅 생성(보내기·다시 생성·이어 쓰기)은 TaskManager의 작업(ChatGenerate)으로 실행한다. 커맨드는 작업을 제출하고 작업 id를 돌려준다. 생성 상태는 대화별로 독립이라 응답을 기다리는 동안 다른 대화로 이동할 수 있다.
- 같은 대화에는 생성 작업이 하나만 돈다(대화 id가 작업의 resource\_key). 취소는 cancel\_task 하나로 통일한다.
- 스트리밍 조각은 기존처럼 프론트가 넘긴 Channel로 보내고, 끝/실패/취소는 TaskEvent로 알린다. Channel이 끊겨도(화면 이동) 작업은 끝까지 돌고 결과는 DB에 저장된다.
- 멈추기를 누르면 Executor에 유예 시간(10초)을 주고, 그 안에 받은 데까지 저장한 결과는 작업 완료로 친다(TaskExecutor::cancel\_grace).
- 앱이 생성 중에 꺼지면 받던 내용은 남지 않고, 다음 실행 때 그 작업은 Interrupted가 된다. 앱 시작 시 사용자에게 다시 만들지 버릴지 한 번 묻는다(recovery.ts). 자동 재시도는 하지 않는다(사용자 키로 비용이 드는 호출이라).
- 다시 시도할 때 사용자 입력을 두 번 저장하지 않도록, 보내기 작업이 저장한 사용자 메시지에는 meta.taskId를 남기고 그 메시지가 마지막이면 응답만 다시 만든다(TurnKind::Reply).
- 구현: `service/chat/chat_task.rs`(Executor·제출·취소), 동시 실행 작업 수는 4.
- 게임 NPC 대화(game\_chat)는 게임 런타임 락과 호출 제한 안에서 돌기 때문에 이번에는 작업으로 옮기지 않았다.

### ADR-003 보류한 기능

**상태** Deferred (2026-11-15)

- **게임 iframe SDK**: 플레이 화면은 Svelte가 직접 그린다. 외부 HTML/JS 게임을 받을 계획이 가까워지면 재개한다. 빌드 입력(game-runtime.html)에서 뺐고, 초안은 `src/lib/game/`에 남아 있다. 게임 모드 ADR-002의 격리 결정은 그대로 유효하다.
- **장기 기억(memory\_settings, memory\_embeddings)·선톡(proactive\_settings)**: 테이블만 있고 코드는 없다. 채팅 작업 흐름(ADR-002) 위에서 만들 수 있게 되었으므로, 착수할 때 새 ADR로 정책(임베딩 제공자, 선톡 빈도·비용 상한)을 정한다. 테이블은 그대로 둔다.
- **다국어**: svelte-i18n만 설정돼 있고 화면 대부분은 한국어로 쓰여 있다. 영어 지원이 목표가 될 때까지 새 화면부터만 locales 키를 쓴다.

### ADR-004 AI 답변의 HTML 코드 블록 렌더링

**상태** Accepted (2026-11-16)

**결정**

- 답변 안의 ```` ```html … ``` ````(또는 언어 표시 없이 태그로 시작하는 코드 블록)은 iframe으로 그린다. 채팅·폰·게임 모두 같은 컴포넌트(HtmlView)를 쓴다. 닫히지 않은 블록(스트리밍 중)은 글로 둔다. 게임은 대본 파서가 코드 블록을 한 줄로 유지한다.
- **srcdoc을 쓰지 않는다.** srcdoc·blob 문서는 앱 창의 CSP(script-src 'self')를 물려받아 인라인 JS가 막힌다. 대신 백엔드가 `htmlview://localhost/<id>`(Windows/Android는 `http://htmlview.localhost/<id>`)로 서빙하고 그 응답에만 별도 CSP를 붙인다. 내용은 메모리에만 두고(같은 HTML = 같은 id, 최근 300개, 1MB 상한) 화면이 register\_html\_view로 등록한다.
- **격리**: iframe은 `sandbox="allow-scripts"`만 준다(allow-same-origin 없음 → 불투명 origin). 앱 화면·저장소·Tauri IPC에 닿지 못한다. CSP: connect-src 'none'(fetch·XHR·WebSocket·IPC 요청 차단), form-action·frame-src 'none'. 외부 https 이미지·글꼴·스타일·스크립트(CDN 라이브러리)는 허용한다.
- 높이는 iframe이 parent에 postMessage({type:"sc-html-height"})로 알리고, 최대 900px에서 iframe 안 스크롤로 넘긴다.

**결과** AI가 만든 스크립트는 사용자 화면에서 돌지만 앱 데이터와 키에는 닿지 못한다. 외부 리소스를 허용했으므로 이미지 요청으로 외부에 신호를 보내는 것은 막지 않는다(필요하면 img-src를 data:/blob:로 좁힌다).

**갱신 (2026-11-16) 편의 함수**

- 문서 맨 앞(테마 뒤)에 `window.sandcastle`을 넣는다: `fill(글)`(입력칸에 넣기), `send(글)`·`choose(글)`(보내기). 스크립트 없이 `data-sc-send` / `data-sc-choice` / `data-sc-fill`을 단 요소를 눌러도 된다(값이 비면 그 요소의 글자).
- 허용된 요청은 `{type:"sc-action", action:"fill"|"send", text}`뿐이고 글은 4000자까지. 화면(HtmlView)은 메시지를 보낸 창이 그 iframe인지 확인한다.
- **보내기는 요금이 나가므로** 사용자가 그 블록 안을 막 눌렀을 때(iframe에 포커스)만 보낸다. 스크립트가 혼자 부르면 입력칸에 넣기만 하고 "직접 보내기"를 알린다. 받는 쪽은 지금 열린 대화 화면 하나(`shared/html/bridge.ts`).
- 블록 머리줄의 접기 버튼으로 HTML을 접을 수 있다(iframe도 내림). 캐릭터 개요는 코드 블록 밖의 HTML도 같은 iframe으로 그린다(HTML 렌더링이 꺼져 있으면 글만).

### ADR-005 코어 플러그인 (기능 토글)과 AI 도구

**상태** Accepted (2026-11-16)

**결정**

- 부가 기능은 Obsidian의 코어 플러그인처럼 껐다 켠다. 목록·이름·기본값은 백엔드 `sys/plugins.rs` 한 곳에 두고, 켜짐/꺼짐은 기존 기능 설정 저장소(`feature-setting`, id별 bool)에 둔다. 설정 > 코어 플러그인에서 바꾼다.
  - 기본 켜짐: 폰(`phone`), 게임 모드(`game`), 캐릭터 이미지(`chat.images`), 정규식(`regex`)
  - 기본 꺼짐: HTML 렌더링(`html`, AI가 쓴 JS를 실행하므로 — 2026-11-17 합의로 바꿈, M1), 위젯(`widget`, 데스크톱 전용), 번역(`translate`), 음성 읽기(`tts`), 이미지 생성(`imagegen`), 이미지 자동 생성(`imageauto`). 앞으로 추가하는 기능은 모두 기본 꺼짐
- 끄면 화면(사이드바·설정 탭·메시지 동작·패널 스위치)에서 숨기고, 그 화면에 들어가면 "꺼져 있음"과 켜기 버튼을 보여준다. AI 결과에 영향을 주는 것은 백엔드에서도 막는다: 정규식은 불러오지 않고(스위치 하나, `regex_processor::set_enabled`), 캐릭터 이미지 키를 보내지 않고, HTML 서빙과 AI 도구 호출은 거절한다. 끈 기능의 데이터는 지우지 않는다.
- 설정을 바꾸면 백엔드가 모든 창에 `feature_setting::changed`를 보낸다 (메인 창의 플러그인 상태, 위젯 창의 위젯 하위 기능).
- **AI 도구** 세부 설정은 별도 저장소(`plugin-setting`)에 둔다. 셋 다 연결한 API 프로필(주소 + keyring 키)을 쓰고, 비우면 대화/앱에서 고른 API.
  - 번역: 채팅 모델에 번역 지시(형식·태그·코드 블록 유지). 메시지 번역은 meta.translation {lang, text, source}에 저장하고 원문이 바뀌면 무효. 자동 번역, 입력 번역(입력창 + 메뉴).
  - 음성 읽기: OpenAI 호환 `/audio/speech` → mp3를 앱 캐시(tts/)에 저장(같은 글·설정이면 재사용). 태그·코드 블록은 빼고, "대사만 읽기"면 *지문*도 뺀다. 자동 읽기.
  - 이미지 생성: OpenAI 호환 `/images/generations` → png를 앱 데이터(generated/)에 저장하고 meta.generatedImages에 쌓는다. 기본은 채팅 AI가 장면을 영어 프롬프트로 정리하고(캐릭터 설명 포함), 화풍을 끝에 붙인다.

**갱신 (2026-11-16)**

- 공급자: 음성은 ElevenLabs(`/text-to-speech/{voice_id}`, xi-api-key, 계정 목소리 목록), 이미지는 NovelAI(`/ai/generate-image`, 응답 zip의 png, nai-diffusion-4 이상은 v4_prompt 구조)를 지원한다. 음성·이미지 API 프로필의 종류(formatType elevenlabs / novelai, API 키 화면에서 고름)로 갈리고, 그 밖은 OpenAI 호환으로 부른다. NovelAI면 AI가 쓰는 그림 프롬프트도 태그 형식으로 쓴다. 로컬 Stable Diffusion은 지원하지 않는다.
- 이미지 생성 프리셋(NovelAI): 화풍·품질 태그, 네거티브 프롬프트, steps, scale, 샘플러, 크기(64의 배수로 맞춤). 그림 프롬프트를 쓸 채팅 API를 따로 고를 수 있다.
- 폰 대화의 기본 API·프리셋: 대화에 고른 것 → 폰 설정 → 앱 기본값 순서.
- 설정은 "플러그인" 묶음 안에 코어 플러그인(켜고 끄기)과 기능별 탭(폰·번역·음성 읽기·이미지 생성·위젯)으로 나눴다. 기능이 꺼지면 그 탭도 숨는다.
- 이미지 페이지(사이드바 "이미지"): 직접 만들기(AI가 다듬기 선택)와 갤러리(출처별 보기, 크게 보기, 프롬프트 복사·재사용, 원래 대화로, 삭제). 그림은 `generated/<id>.png` 옆 `<id>.json`에 프롬프트·모델·출처를 둔다. 삭제는 그 폴더 안의 png만.
- 게임 대사창: 지금 줄 번역(이번 플레이 동안만 기억), 지금 줄 읽기, 이 응답 장면 그리기(무대 위에 띄움, 갤러리 출처 "게임").
- HTML iframe에는 지금 테마의 CSS 변수와 바탕·글자·버튼·입력칸 기본 스타일을 문서 맨 앞에 넣는다(ADR-004). AI가 쓴 스타일이 뒤에 오므로 덮어쓸 수 있고, 테마가 바뀌면 다시 등록해 새 색이 들어간다.

**갱신 (2026-11-16) 앱 프롬프트**

- 앱이 AI에 보내는 고정 지시문(번역, 장면 → 그림 프롬프트, NovelAI 태그, 캐릭터 이미지 `<cg>` 규칙, 게임 대화 규칙, 씬 입력 규칙)은 `service/app_prompts.rs`에 기본값으로 두고, 사용자가 고친 값은 plugin-setting의 `prompts`에 둔다. 빈 칸 = 기본값이라 "기본값으로"가 언제나 된다. 자리 표시: `{{lang}}`, `{{keys}}`, `{{char}}`. 게임·씬 규칙은 한 줄이 규칙 하나이고, `<updateRel>`이 든 줄은 씬 입력에서 빠진다.
- 설정을 불러오거나 저장할 때 전역 값으로 넣어 두고 쓰는 쪽은 인자 없이 꺼낸다 (설정 > AI > 앱 프롬프트).

### ADR-006 기능·작업·사용량 책임 분리

**상태** Accepted (2026-11-16) — CLAUDE.md 가까운 목표 M2

**배경** 유료 AI 호출이 채팅(TaskManager 작업)과 그 밖(게임 대사·번역·음성·이미지·API 확인, 커맨드에서 바로 호출)으로 갈려 있어, 무엇이 언제 누구 때문에 돈을 썼는지 볼 수 없었다. 원칙: Explicit Execution(실행 주체가 분명), Observability(상태·결과 확인), 사용자 동의 없는 리소스 소비 금지.

**결정** 세 책임을 나눈다. 서로의 저장소를 직접 고치지 않는다.

| 책임 | 무엇을 | 어디에 |
| --- | --- | --- |
| FeatureManager | 기능이 **있는가 / 켜졌는가**와 기능별 설정. 꺼진 기능은 실행 요청 자체를 거절한다 | `sys/plugins.rs`(목록·기본값·`require`), `feature-setting`·`plugin-setting` 저장소 (ADR-005) |
| TaskManager | **실행과 생명주기**: 작업 행·시도·상태 전이·이벤트·취소·복구. 작업에 기능 id(`feature`), 실행 주체(`run_by`: user / auto), 표시 이름(`label`)을 남긴다 | `task/` (`generation_tasks`, `generation_attempts`) |
| ResourceManager (1차) | **사용량**: 공급자 호출 한 번마다 토큰·글자·그림 수, 성공 여부, 걸린 시간 | `db/usage.rs` (`usage_log`) |

- **모든 유료 호출은 작업 안에서**. 오래 걸리고 다시 시도할 수 있는 채팅은 큐 작업(`submit` + 실행기), 그 밖의 짧은 호출은 즉시 실행 작업(`TaskManager::run_inline`)으로 부른다. 즉시 실행 작업도 같은 행·시도·이벤트를 남기고 실행 중 목록에서 멈출 수 있다. 실행기가 없으므로 앱이 꺼지며 끊긴 즉시 실행 작업은 다음 실행 때 취소로 정리한다(다시 시도하지 않음 = 사용자 동의 없이 요금을 쓰지 않음).
  - chat: 응답 생성·다시 생성·다른 응답 / phone: 같은 흐름 + 엿보기 / game: NPC·씬 대사 / translate / tts / imagegen(프롬프트 작성 + 그리기를 한 작업으로) / settings: API 연결 확인
  - 캐시에서 꺼내는 경우(공용 번역 캐시, 이미 만든 음성)는 요금이 없으므로 작업을 만들지 않는다.
- **실행 주체**: 사용자가 누른 것은 `user`, 사용자가 켜 둔 자동 설정(자동 번역·자동 읽기)이 부른 것은 `auto`. 프론트가 명시해서 넘긴다. 자동 설정은 모두 기본 꺼짐.
- **사용량 기록 위치**: 공급자를 실제로 부르는 한 곳(`AiService::generate`, 음성·이미지 호출)에서 남긴다. 어느 작업의 호출인지는 인자로 넘기지 않고 tokio task-local(`task::current_task`)로 안다. 그래서 새 기능이 AiService를 쓰기만 하면 사용량은 자동으로 잡힌다. 작업 밖에서 부른 호출도 사용량은 남는다(작업 id 없음).
- **토큰**: 공급자가 응답에 주면 그 값(OpenAI `usage`, Claude `usage`(스트림은 message_start/message_delta), Gemini `usageMetadata`), 없으면 앱이 추정(프롬프트 블록 토큰 + 받은 글)하고 `estimated=1`. 실패·취소한 호출도 받은 만큼 기록한다(요금이 나갈 수 있음).
- **화면**: 설정 > 관리 > 실행 기록 — 실행 중(멈추기), API 프로필·종류별 사용량(오늘/7일/30일/전체, 비우기), 최근 실행(자동만 보기, 펼치면 작업 id·API·모델·걸린 시간·시도·오류). 화면이 열려 있을 때만 불러오고 `task-event`로 새로 고친다.
- 사용량 기록은 실패해도 원래 호출을 망치지 않는다(로그만).

**다음 단계**: 예산 한도는 ADR-007. 요금 단가표로 금액 환산, 오래된 작업·사용량 기록 정리(1-A-3, 1-A-4).

### ADR-007 예산 한도

**상태** Accepted (2026-11-16) — CLAUDE.md 1-A (M9)

**배경** ADR-006으로 사용량은 보이지만 막지는 못했다. 선톡·에이전트·자동 색인처럼 "사용자가 안 볼 때 요금이 나가는" 기능(5-A, 5-B, 3-C)보다 먼저 상한이 필요하다. 원칙: 사용자 동의 없는 리소스 소비 금지, Observability.

**결정**
- **한도 모델** (`budget_limits`, `db/budget.rs`): API 프로필별 하루/한 달 상한 — 토큰(입력+출력)·음성 글자·그림 장 수. 비우면 한도 없음(기본). 0 이하는 "없음"으로 저장한다(실수로 모든 호출이 막히지 않게). 하루·한 달은 기기의 현지 시각(오늘 0시, 이번 달 1일 0시)부터. 실패한 호출도 센다(요금이 나갈 수 있음). 프로필을 지우면 한도도 지워진다.
- **어디서 막나**: 계획은 "TaskManager가 실행 전에 묻는다"였지만, 작업을 만들 때는 어느 API 프로필을 쓸지 아직 모른다(프리셋·대화 설정·플러그인 설정을 거쳐 AiService에서 정해짐). 그래서 **공급자를 실제로 부르기 직전**(`AiService::generate`, 음성·이미지 호출 — 사용량을 기록하는 바로 그 자리)에 `service/budget.rs`가 확인한다. 이 자리는 항상 작업 안이므로 결과는 같다: 막힌 작업은 공급자를 한 번도 부르지 않고 `BUDGET_EXCEEDED`(재시도 안 함)로 실패하며 실행 기록에 "한도로 막힘"으로 남는다. 호출 종류별로 해당 단위만 본다(채팅은 토큰, 음성은 글자, 그림은 장 수).
- **이번만 계속** (사용자 합의 2026-11-16): 자동 실행(`run_by = auto`)은 항상 막는다. 사용자가 누른 실행(`user`)이 막히면 알림에 "이번만 계속"이 뜨고, 누르면 2분 안에 사용자가 다시 실행하는 **작업 하나**가 한도를 넘어 실행된다(한 작업 안의 여러 호출 — 예: 이미지 프롬프트 작성 + 그리기 — 은 같이 허용). 허용은 메모리에만 있고 앱을 다시 켜면 사라진다. 다시 누르게 하는 것은 Explicit Execution 때문(알림 버튼이 요금을 쓰는 실행을 대신 시작하지 않음).
- 실행 주체는 작업의 task-local(`CurrentTask.run_by`)로 안다. 작업 밖의 호출은 user로 본다.

### ADR-008 사용자 데이터의 범위와 백업

**상태** Accepted (2026-11-16) — CLAUDE.md 1-B (M9). 동기화(2단계)는 이 표를 출발점으로 한다.

**배경** 전체 백업(`.scbackup`)의 `BACKUP_DIRS`가 characters·games·themes뿐이라 갤러리 그림(`generated/`)과 올린 배경(`backgrounds/`)이 빠져 있었다. 복원 뒤 경로 보정도 아바타만 했다.

**결정 — 앱 데이터 폴더의 분류**

| 위치 | 무엇 | 분류 | 백업 |
| --- | --- | --- | --- |

- **백업 v2**: 위 표의 O 폴더 전부. manifest에 담은 폴더(`dirs`)를 적고, 복원은 그 폴더만 바꾼다. v1 백업(`dirs` 없음)은 characters·games·themes만 바꾸고 갤러리·배경은 지금 것을 그대로 둔다.
- **경로 보정**: 다른 PC에서 만든 백업은 앱 데이터 경로가 다르다. 복원 뒤 DB의 모든 글자 칸과 `settings.json`에서 옛 앱 데이터 경로를 새 경로로 바꾼다(그대로 / JSON 안의 역슬래시 두 개 / 슬래시 모양). 앱 데이터 경로는 다른 글에 우연히 나오기 어려운 긴 문자열이라 칸을 가리지 않고 바꾼다.
- 갤러리 정보 `.json` 안의 `path`는 목록을 만들 때 실제 파일 위치로 다시 채우므로 고치지 않는다.
- **마이그레이션 전 사본** (1-B-2): 앱을 시작할 때 이미 쓰던 DB에 적용할 새 마이그레이션이 있으면, 적용하기 전에 `migration-backups/app-<시각>-v<지금 버전>.db`로 사본을 만든다(VACUUM INTO). 최근 3개만 남긴다. 새로 만든 DB는 건너뛴다. 사본을 만들지 못해도 앱은 연다(로그만 — 시작을 막으면 데이터를 꺼낼 방법도 없어짐). 되돌릴 때는 앱을 끄고 사본을 `app.db`로 바꾼다(화면은 아직 없음).

### ADR-009 Android 플랫폼 처리

**상태** Accepted (2026-11-16) — CLAUDE.md 1-C (M10). 점검 결과는 `docs/Android 점검표.md`.

**결정**
- **비밀 저장소**: 데스크톱은 OS keyring(keyring v4), Android는 `android-native-keyring-store`(Android Keystore 키로 암호화한 SharedPreferences, keyring-core 직접 사용). 평문 파일에 두지 않는다. 테스트는 메모리 저장소(OS 자격 증명 관리자를 건드리지 않음).
- **고른 파일**: Android 파일 고르기의 `content://` 주소는 프론트 `pickFiles`/`saveTo`가 받아 백엔드(`service/picked_file.rs`)가 앱 `tmp/`로 복사하거나 `tmp/saving/`에서 고른 곳으로 옮긴다. 가져오기·내보내기 커맨드는 계속 파일 경로만 다룬다. 공용 다운로드 폴더에 직접 쓰지 않는다(Android 10+ 저장소 정책).
- **화면 가장자리**: edge-to-edge를 유지하되, 아래(키보드·탐색 막대)는 `MainActivity`가 비우고 위(상태 표시줄)는 CSS `--safe-top`(= max(env, 앱이 알려 준 값))으로.
- **백그라운드 생성**: AI 작업이 도는 동안만 포그라운드 서비스(dataSync)를 켜고 끝나면 끈다. 서비스는 프로세스를 살려 두기만 하며 작업을 멈추지 않는다(끄는 순간 생성이 끊기지 않게). 알림 줄에 "응답을 만드는 중"이 보인다(Observability). 앱이 꺼진 동안의 실행(선톡 등)은 5-A-6에서 따로 정한다.
- **화면 → 앱(Kotlin) 연결**: 숫자만 돌려주는 상태 표시줄 높이는 `addJavascriptInterface`, 동작이 있는 서비스 켜고 끄기는 `addWebMessageListener`로 **앱 주소(`http://tauri.localhost`)의 최상위 프레임만** 받는다 — AI가 쓴 HTML(htmlview iframe)은 이 객체를 볼 수 없다(Least Privilege).
- **뒤로 가기**: 앱 안 이동 기록(nav)을 브라우저 기록과 맞춰 시스템 뒤로 가기가 앞 화면으로 가게 한다.
- **데스크톱 전용 기능**: 코어 플러그인의 `desktop_only`는 모바일에서 목록에서 빠지고 늘 꺼짐으로 본다.
- **마이그레이션 파일**: `.gitattributes`로 줄 끝 변환을 막는다(sqlx 체크섬이 체크아웃 환경에 따라 바뀌지 않게).

### ADR-010 버전·업데이트·서명·릴리스

**상태** Accepted (2026-11-17) — CLAUDE.md 1-E (M11). 절차는 `docs/배포.md`.

**결정**
- **버전**: `package.json` 한 곳. `tauri.conf.json`은 `../package.json`을 읽고 `Cargo.toml`은 `scripts/version.mjs`가 맞춘다. CI가 세 곳이 같은지 확인. 변경 내역은 `CHANGELOG.md`.
- **업데이트**: GitHub Releases(`dily311/sandcastle`)의 최신 공개 릴리스와 비교해 알리기만 한다. 내려받기·설치는 하지 않고 릴리스 페이지를 연다(사용자가 직접). 확인은 사용자가 누를 때만, "앱을 켤 때 확인"은 별도 스위치이며 기본 꺼짐(사용자 동작 없는 외부 요청이므로). 요청에는 일반 User-Agent만. Tauri updater는 쓰지 않는다(업데이트 서명 키·자동 설치가 필요해 "알림만" 범위를 넘음). 예전 "자동 업데이트" 스위치는 연결된 동작이 없었으므로 화면에서 뺐다(저장값은 호환용으로만 남김).
- **서명** (사용자 결정 2026-11-17): Windows는 당분간 코드 서명 없음(SmartScreen 경고를 릴리스 설명에 적음). Android 키는 사용자 PC(저장소 밖)와 GitHub Secrets에만 두고, `keystore.properties`가 있을 때만 release 빌드에 서명한다. 배포 빌드(R8)에서 JS가 부르는 `@JavascriptInterface`는 keep 규칙으로 지킨다.
- **릴리스**: 태그 `v<버전>` → `.github/workflows/release.yml`이 Windows 설치 파일과 APK를 만들어 **초안** 릴리스에 올린다. 공개는 사람이 한다(Explicit Execution). 태그와 버전이 다르면 멈춘다.

### ADR-011 동기화 방식

**상태** Accepted (2026-11-17, 사용자 결정) — CLAUDE.md 2단계. 대상 표(2-A-1)는 아래. 동기화는 코어 플러그인 `sync`(기본 꺼짐).

**결정**
| 항목 | 결정 | 이유 |
| --- | --- | --- |
| ① 저장소 | **사용자가 고른 폴더를 먼저**(2-C), 같은 `SyncTarget` 위에 **구글 드라이브 앱 전용 폴더**(2-D). WebDAV는 하지 않음 | 폴더 대상은 OAuth 없이 병합 로직을 검증할 수 있고, OneDrive·Dropbox 같은 동기화 앱에 맡길 수 있다. 드라이브는 `drive.appdata` 권한만(Least Privilege) |
| ② 단위 | **항목(행) 단위 병합**. 전체 스냅샷 교체는 하지 않음 | 두 기기에서 따로 쓴 것이 사라지지 않게 |
| ③ 충돌 | **둘 다 남김**. 같은 행을 양쪽에서 고쳤으면 한쪽을 "충돌 사본"으로 남겨 2-E 화면에서 고른다. 대화는 갈라진 지점부터 분기로 남긴다. 지우기 ↔ 고치기 충돌은 고친 쪽을 살린다 | 조용히 덮어쓰지 않는다(Reversibility). 적용 전 자동 백업도 남긴다 |
| ④ 큰 파일 | **사용자 데이터 파일만**(ADR-008 표의 사용자 데이터 폴더: characters·games·themes·generated·backgrounds), **해시로 바뀐 것만** 보낸다. 캐시(음성 캐시·앨범 아트)·임시·안전망 폴더는 제외. Android에 "Wi-Fi에서만" 옵션 | 용량과 데이터 요금을 줄이고, 다시 만들 수 있는 것은 보내지 않는다 |
| ⑤ 암호화 | **선택 사항, 기본 꺼짐**. 켜면 사용자가 정한 암호 문구로 묶음을 암호화하고, 문구는 기기마다 keyring에 넣으며 동기화하지 않는다. 문구를 잊으면 저장소의 사본은 못 읽는다(각 기기의 원본은 남음). 2-C 뒤에 붙인다 | 키·토큰은 원래 묶음에 없고, 대화 내용 보호가 필요한 사람만 켜게 |

**변하지 않는 규칙**
- API 키·토큰·암호 문구는 어떤 경우에도 묶음·저장소·로그에 넣지 않는다(2-B-4 테스트로 고정). API 프로필 행은 동기화하되 키는 기기마다 다시 넣고 "키 없음"을 보여준다.
- 실행은 "지금 동기화" 버튼이 먼저. 자동 동기화(시작·종료·주기)는 별도 스위치, 기본 꺼짐. 실행은 TaskManager 작업(feature `sync`)으로 기록한다.
- 스키마 버전이 낮은 기기는 묶음을 적용하지 않고 업데이트를 안내한다.

**동기화 대상 (2-A-1)** — id는 이미 대부분 `Uuid::new_v4` 글자 id라 기기 사이에서 겹치지 않는다. 정수 id 테이블(`conv_settings`·`usage_log`·`usage_daily`)은 아래처럼 다룬다. 연결 테이블(복합 키)은 그 키로 합친다.

- 예산 한도(budget_limits)는 같이 쓰지만 사용량은 기기마다 세므로 한도도 기기마다 걸린다. 기기를 합친 한도는 하지 않는다(필요하면 나중에).

**변경 추적 구현 (2-A-2)** — 마이그레이션 156.
- 동기화 대상 71개 테이블에 `updated_at`(없던 곳은 추가, 기존 행은 `created_at`이나 지금 시각으로)을 둔다. 행에 지움 표시(`deleted_at`)는 두지 않는다 — 아래 2-A-3.
- 함수마다 고치는 대신 **트리거**로 모든 쓰기를 잡는다: INSERT에서 비었거나 0이면 지금 시각, UPDATE에서 코드가 `updated_at`을 바꾸지 않았으면 지금 시각. 코드가 직접 다른 값을 쓰면 그대로 둔다 — 2-B 병합이 원래 기기의 시각을 넣을 수 있게. 단, 병합이 지금 값과 **같은** 시각을 쓰면 지금 시각으로 바뀌므로 병합은 같은 시각이면 쓰지 않는다(2-B-2).
- 시각은 모두 밀리초. 초로 쓰던 곳(API 프로필, 관계 스냅샷, 기본 페르소나 초기값)을 밀리초로 바꾸고 기존 값(< 1e11)도 맞췄다.
- id: 동기화 대상의 id는 `Uuid::new_v4` 글자 id다. 처음 만들어지는 고정 id(`default` 프리셋·블록·페르소나, `conv_settings` id 1)는 모든 기기에서 같은 항목이므로 같은 id로 합친다. 가져오기(.tgame·.scpack)는 이미 새 id로 바꾼다.
- 키가 없는 테이블(game_journal·game_saves·game_weather_pool_entries)은 UNIQUE 묶음(세션+번호 / 세션+슬롯 / 풀+날씨)을 병합 키로 쓴다(2-B-1).
- 실제 DB 사본(메시지 68개)에서 0.55초, 무결성 점검 정상.

**휴지통과 지운 기록 (2-A-3)** — 마이그레이션 157, `service/data/trash.rs`.
- 계획은 "지우기를 `deleted_at` 표시로"였지만, **떠 두고 지우는 방식**으로 바꿨다. 행에 표시를 하면 모든 목록·검색·프롬프트 조립 쿼리(수백 곳)가 지운 행을 빼야 하고, 하나라도 빠뜨리면 지운 대화가 프롬프트에 섞이는 식의 사고가 난다. 대신:
  - **휴지통**: 지울 때 그 항목과 FK CASCADE로 같이 지워지는 행 전부를 JSON으로 떠서 `trash_items`에 넣고 실제로 지운다. 지울 때 NULL이 되는 바깥 연결(FK SET NULL, 예: 캐릭터를 지우면 대화의 `character_id`)과 트리거로 지워지는 폰 연락처도 적어 둔다. 파일(채팅 이미지 폴더·게임 폴더·앱이 복사한 페르소나 아바타)은 `trash/<id>/`로 옮긴다. 테이블·FK 구조는 DB에서 읽으므로(pragma) 테이블이 늘어도 고칠 곳이 없다.
  - **되살리기**: 행을 다시 넣고(`updated_at`은 지금 — 다른 기기의 지운 기록보다 새것), 끊긴 연결을 다시 잇고(그 사이 사용자가 다른 값을 넣었으면 두고), 파일을 제자리로. 연결된 항목이 이미 없으면(예: 세션을 되살리려는데 게임을 완전히 지움) 아무것도 바꾸지 않고 이유를 알린다.
  - **지운 기록** (`sync_tombstones`): 동기화 대상 테이블의 모든 DELETE를 트리거가 (테이블, 키 json_array)로 남긴다 — 휴지통에 안 가는 지우기(메시지·로어북 항목·게임 편집기)도 포함. 같은 키로 다시 들어오면 지운다(되살리기·다시 연결). 2-B가 이것으로 다른 기기에 지우기를 전한다. 오래된 기록 정리는 2-B/2-C에서 정한다.
- 휴지통에 가는 것: 캐릭터, 페르소나, 대화(여러 개 지우기 포함), 로어북, 프리셋, 게임, 게임 플레이 기록. 메시지·로어북 항목 같은 작은 단위는 휴지통에 가지 않는다(지운 기록만 남음).
- 보존 기간: 설정 `trashRetentionDays`(기본 30일, 7/30/90/계속). 지난 항목은 휴지통을 열거나 새로 지울 때 완전히 지운다 — 시작할 때 따로 돌지 않는다(Lazy Initialization). 완전히 지우기·비우기는 확인을 받는다.
- 휴지통과 지운 기록은 기기마다 따로다(동기화 안 함). 백업에는 들어간다(`trash/` 폴더 = ADR-008 표).
- 화면: 지운 직후 "되돌리기" 알림(6초), 설정 > 데이터 > 휴지통(되살리기 / 완전히 지우기 / 비우기 / 보존 기간).

**기기 id와 설정 나누기 (2-A-4)** — `service/device.rs`, `service/data/settings_scope.rs`.
- **기기 id**: 설치마다 uuid 하나를 앱 데이터 폴더의 `device.json`에 둔다. DB·settings.json에 두지 않는 이유는 둘 다 백업에 들어가서, 백업을 다른 기기에 복원하면 id까지 복제되기 때문. 동기화가 처음 필요로 할 때 만든다(지금은 아무도 부르지 않아 파일이 생기지 않음).
- **설정 칸마다 범위**: settings.json의 모든 칸을 "같이 씀 / 같이 쓰되 경로 보정 / 기기 전용"으로 표에 적었다. 표에 없는 칸이 생기면 테스트가 실패한다. 묶음에는 같이 쓰는 칸만 넣고(`shared_part`), 받는 쪽은 기기 전용 칸과 모르는 칸을 건드리지 않고 합친다(`merge_shared`).

| 같이 씀 | 기기 전용 |
| --- | --- |
| 언어, 프리셋·페르소나 선택, 시각 표시, 폰 모드 프롬프트, 홈 화면 | 고른 API, 엔터로 보내기, 고른 캐릭터·마지막 게임(화면 상태), 업데이트 확인, 실행 기록·휴지통 보관 기간 |
| 테마(모드·테마·강조색·회색 톤·스니펫·배경 불투명도), 배경 이미지·목록(경로 보정) | 창 테두리, 글자 크기(화면에 따라 다름) |
| 번역 언어, 음성 모델·목소리·속도·대사만, 그림 생성 옵션, 폰 기본 프리셋, 앱 프롬프트 | **기능 켜기 전부**(feature-setting), 번역·음성·그림·폰의 API 선택, **자동 번역·자동 읽기** |

- 기능 켜기와 자동 실행 스위치를 기기 전용으로 둔 이유: 요금이 나가는 동작은 그 기기에서 사용자가 직접 켜야 한다("사용자 동의 없는 리소스 소비 금지"). PC에서 자동 번역을 켰다고 폰에서 저절로 요금이 나가지 않게.
- API 선택이 기기 전용인 이유: 키가 기기마다 따로이고, 로컬 모델 주소는 그 PC에서만 닿는다. API 프로필 행 자체는 동기화하고, 키가 없는 기기는 설정 > API 키에 "키 없음"이 보이며(이미 있던 표시), 그 프로필로 보내면 "이 기기에 키가 없음 — 설정 > API 키에서 넣기"로 알린다.
- 그 밖의 기기 전용: 창 위치·크기(window-state), 위젯 음악(`widget.json`), localStorage(폰 주인·배경 선택·마지막 읽음 등).

**동기화 묶음 형식 (2-B-1)** — `service/data/sync_bundle.rs`, 확장자 `.scsync`(zip).

| 안의 파일 | 내용 |
| --- | --- |
| `manifest.json` | `format`("sandcastle-sync")·`formatVersion`(1)·`schemaVersion`(보낸 DB의 마이그레이션 번호)·`appVersion`·`deviceId`·`createdAt`·`since`(이 시각 뒤 바뀐 것만, 없으면 전부)·테이블별 행 수·지운 기록 수·파일 수·`encryption`(지금은 늘 없음) |
| `tables/<테이블>.jsonl` | 동기화 대상 테이블에서 `updated_at > since`인 행, 한 줄에 {열: 값} 하나. 열 이름으로 담으므로 받는 쪽 스키마가 조금 달라도 아는 열만 쓰면 된다 |
| `tombstones.json` | `sync_tombstones`에서 `deleted_at > since`인 것 |
| `settings.json` | 같이 쓰는 설정 칸만 (`settings_scope::shared_part`) |
| `files.json` | 사용자 데이터 폴더(characters·games·themes·generated·backgrounds — 휴지통 제외)의 **모든** 파일: 경로·크기·sha256·수정 시각·`included` |
| `blobs/<sha256>` | `included` 파일 내용(같은 내용은 한 번). `since` 뒤에 바뀐 파일만, 또는 "파일 빼고" 선택이면 없음 |

- 파일 목록은 늘 전부 담는다: 받는 쪽이 "나한테 없는 해시"를 알아 다음 묶음에서 요청하거나(2-C), 없다고 보여줄 수 있게. 내용만 골라 담는다.
- **경로 자리표시**: 행·설정 글자 속의 보낸 기기 앱 데이터 경로(그대로 / JSON 안 역슬래시 두 개 / 슬래시 모양)를 `$SANDCASTLE_DATA$`로 바꾸고, 그 뒤 경로의 구분자를 `/`로 맞춘다. 받는 쪽은 자기 경로로 되돌린다(`/` 구분자 — Windows도 읽음). Windows ↔ Android가 맞고, 묶음에 보낸 사람의 사용자 이름이 든 경로가 남지 않는다(Least Privilege).
- **여는 쪽 검사**: 형식 이름, 형식 버전, **스키마 버전이 이 기기보다 높으면 열지 않고 "이 기기의 앱을 업데이트"** 안내, 암호화된 묶음 거부, 파일 경로가 동기화 폴더 안인지·`..`·드라이브 문자, 해시 모양, 꺼낸 파일의 해시가 맞는지(다르면 지움).
- 넣지 않는 것: 동기화 안 하는 테이블(실행 기록·캐시·기기 전용·휴지통·지운 기록 표 자체), `device.json`, `trash/`, 기기 전용 설정, API 키(원래 DB·설정에 없음 — 2-B-4가 묶음 전체에서 가짜 키를 찾는 테스트로 고정).
- 테이블 구조 읽기(pragma)는 휴지통과 같이 `db/schema.rs`로 옮겨 같이 쓴다.
- 묶음의 `createdAt`은 행을 읽기 **전** 시각이다: 읽는 동안 바뀐 행은 다음 묶음에 들어간다(받는 쪽은 `createdAt` 이전을 "이미 본 것"으로 여기므로).

**병합 (2-B-2)** — `service/data/sync_merge.rs`, 마이그레이션 158(`sync_peers`, `sync_conflicts`).
- **시계를 섞지 않는다.** 기기마다 시계가 다를 수 있으므로, 받은 행의 시각은 보낸 기기 시각(그 기기에서 마지막으로 합친 묶음의 `createdAt`)하고만, 이 기기 행의 시각은 이 기기 시각(그때 합친 시각)하고만 비교한다. 기기마다 `sync_peers`에 이 둘을 적는다. 받아서 쓴 행의 `updated_at`은 이 기기의 지금 시각으로 둔다 — 한 DB 안의 시각은 늘 한 시계.
- 행마다 (키 = 기본 키, 없으면 UNIQUE 묶음):

| 받은 행 | 이 기기 | 결과 |
| --- | --- | --- |
| 그 기기에서 마지막으로 합친 뒤 안 바뀜 | — | 건너뜀 |
| 바뀜 | 없음 | 넣음 |
| 바뀜 | 없음, 이 기기에서 지움 | **되살림**(고친 쪽을 살린다). CASCADE로 매달린 자식도 같이 |
| 바뀜 | 내용 같음(시각 칸 빼고) | 그대로 |
| 바뀜 | 그 뒤로 안 고침 | 받은 것으로 바꿈 (`ON CONFLICT DO UPDATE` — REPLACE는 지웠다 넣어 자식이 CASCADE로 사라지므로 쓰지 않음) |
| 바뀜 | 그 뒤로 고침 | **둘 다 남김**: 이 기기 것을 두고 받은 행을 `sync_conflicts`(edit)에 |

- **받은 지운 기록**: 이 기기가 그 뒤로 고친 행은 지우지 않고(고친 쪽을 살린다), 그 행에 CASCADE로 매달린 행도 지우지 않는다(대화를 고쳤는데 메시지만 사라지지 않게). 나머지는 지운다.
- **같은 대화에 양쪽이 이어 씀**(메시지 번호가 겹침): 이 기기 대화는 그대로 두고, 겹치기 전까지의 메시지를 복사한 **분기 대화**("… · 다른 기기", meta.branch에 부모·기기)를 만들어 받은 메시지를 새 id로 넣는다. 그 메시지를 가리키던 책갈피·태그도 새 id로. `sync_conflicts`(branch)에 기록.
- **넣지 못한 행**은 버리지 않는다: 다른 UNIQUE 규칙에 걸림 → `sync_conflicts`(unique), 이 기기에 없는 항목을 가리킴 → 비워도 되는 연결(FK SET NULL)은 비우고, 아니면 `sync_conflicts`(orphan)에 남기고 뺀다. 이때 생긴 지운 기록은 지운다(다른 기기에 "지웠다"고 전하지 않게).
- **처음 만나는 기기**: 이 기기의 모든 행을 "고친 것"으로 본다. 내용이 같으면(기본 페르소나·프리셋처럼 시각만 다른 것 포함) 아무 일도 없고, 다르면 둘 다 남긴다. 빈 기기가 처음 받을 때는 충돌이 없다.
- **같이 쓰는 설정 칸**은 받은 것으로 바꾼다(설정은 칸마다 시각이 없어 "둘 다 남김"이 없다 — 2-B-3 미리보기에서 보여준다). 기기 전용 칸은 그대로.
- **거절**: 자기 기기의 묶음, 이미 합친 묶음(또는 그보다 오래된 것), 스키마가 더 새 앱의 묶음("이 기기의 앱을 업데이트").
- **미리보기**(`dry_run`): 같은 일을 한 트랜잭션에서 하고 되돌린다 — 숫자(추가·변경·지움·되살림·충돌·분기)만 남는다.
- **묶음이 알려 주는 것** (에뮬레이터 점검에서 추가, 2026-11-17): 처음 만난 기기에서 받으면 이 기기의 모든 행을 "고친 것"으로 보는 규칙만으로는, A → B → (B가 고침) → A 순서에서 A가 B의 고침을 충돌로, B의 지우기를 "이 기기 고침 유지"로 막았다. B는 이미 A의 묶음을 합쳐 그 행들을 봤는데 묶음이 그걸 말해 주지 않았기 때문. 그래서 묶음에:
  - `acks` {기기 id: 그 기기 묶음의 createdAt} — 보낸 쪽이 합친 묶음들. 받는 쪽은 자기 id의 값(= 자기 시계) 이전에 바뀐 자기 행을 "보낸 쪽이 이미 본 것"으로 여긴다(`local_base = max(마지막으로 합친 시각, ack)`). 시계는 여전히 섞이지 않는다.
  - `held` {받을 기기 id: [(테이블, 키)]} — 보낸 쪽이 받은 행 대신 자기 것을 둔 행(아직 고르지 않은 edit 충돌). ack만 보면 받는 쪽은 "보낸 쪽이 내 것을 봤다"며 덮어쓰므로, 이 행들은 받는 쪽도 둘 다 남긴다.
  - 둘 다 형식 v1에 선택 칸으로 더했다(없으면 빈 것).
- 정해 두지 않은 것: 충돌·분기를 고르는 화면(2-E), 오래된 지운 기록 정리(2-C).

**파일로 주고받기 (2-B-3)** — 코어 플러그인 `sync`(기본 꺼짐), 설정 > 동기화, `service/data/sync_exchange.rs`, `commands/sync.rs`.
- 켜져 있어도 사용자가 누를 때만: "만들기"(저장 위치를 고름), "열기"(미리보기) → "합치기". 만들기·합치기는 실행 기록에 `sync` 작업(TaskType::BackgroundSync, 사용자 실행)으로 남는다.
- **만들기**: 늘 전부 담는다(since 없음). 받는 쪽이 `sync_peers`로 이미 본 것을 건너뛰므로 같은 파일을 여러 기기에 줘도 되고, 어느 기기가 무엇을 받았는지 보낸 쪽이 기억할 필요가 없다. "그림·파일 포함"(기본 켜짐)을 끄면 파일 내용 없이 목록만.
- **미리보기**: 병합을 되돌리는 트랜잭션에서 돌려 추가·변경·지움·되살림·이 기기 고침 유지·둘 다 남김·분기·파일(추가/빠짐/이 기기 것 둠) 개수와 "같이 쓰는 설정이 바뀜"을 보여준다. 아무것도 바꾸지 않는다.
- **합치기**: ① 이 기기 DB(VACUUM INTO)와 설정 사본을 `sync-backups/`에(최근 3개) ② 받은 파일 중 **이 기기에 없는 것만** 넣는다 — 같은 자리에 내용이 다른 파일이 있으면 이 기기 것을 둔다(덮어쓰지 않음) ③ DB 병합 ④ 같이 쓰는 설정을 저장하고 화면에 알린다(바뀐 묶음만). 파일을 DB보다 먼저 넣어, 합친 행이 가리키는 그림이 없는 순간이 없게.
- **이 기기 id**는 동기화 화면을 열 때 처음 만든다(기능을 켜고 화면을 연 것이 동의). 화면에는 앞 8자만.
- 되돌리기 화면은 아직 없다: 사본을 되돌리려면 앱을 끄고 `sync-backups/app-…db`를 `app.db`로 바꾼다(마이그레이션 사본과 같음).
