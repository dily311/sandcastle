### ADR-001 일반 대화와 게임모드 테이블 통합

**상태** Rejected (2026-11-15) — 통합하지 않는다.

**최종 판단** 일반 대화(conversations/messages)와 게임 대화(game\_conversations/game\_messages)는 별도 테이블로 유지한다.

- 게임 대화는 세션·씬(branch\_key)·seq에 묶여 있고, 책갈피 분기 때 seq까지 복사·삭제 연쇄가 필요하다. 일반 대화는 이런 제약이 없어서 한 테이블에 두면 양쪽 모두 조건 분기가 늘어난다.
- 마이그레이션 비용(기존 사용자 DB 변환)이 크고, 얻는 것은 구조의 통일성뿐이다.
- 대신 공통 부분은 코드에서 공유한다: 프롬프트 조립(PromptManager), AI 호출(AiService), 컨텍스트 예산(ContextBudget), 정규식 처리.
- 폰 UI(게임 캐릭터와 게임 밖 대화)는 일반 대화 테이블 위에서 phone\_contacts/phone\_links로 연결한다(구현됨).

아래는 검토 당시의 기록이다.

**배경** 일반 대화와 게임모드 테이블의 유사성. 아키텍처 통일성을 위해서 두 테이블을 통합하고자 함.

- 기존 대화 UI는 폰 UI로 활용하기로 함.
      폰 UI란 게임 캐릭터들과 1:1 혹은 1:n 대화를 할 수 있는 걸 말함.
      여기서 선톡 기능을 지원

**결정**

원 테이블 구조:
```
Conversation
 ├── Chat
 │    └── Messages
 │
 └── Game
      ├── GameSession
      ├── GameSave
      └── GameJournal
```

변경 후 테이블 구조:
```
Conversation
 ├── Template
 │    ├── Chat Template
 │    ├── VN Template
 │    ├── RPG Template
 │    └── Text Game Template
 │
 ├── Messages
 │
 └── GameSession (게임 템플릿에서만 생성)
      ├── GameSave
      └── GameJournal
```

- 한 계층에 통합: 대신 각 기능의 구분을 분명히 할 것.
- Conversation 세션은 공통 진입점으로 하고, GameSession은 템플릿에 따라 선택적 연결
- Chat Engine과 Game Engine의 책임소재 분명히. 대화의 공통 기능과 게임의 전용 기능을 구분하도록 할 것.

### ADR-001 추가 논의: 게임 밖의 폰 대화와 여러 세션

**상태** Proposed

**배경** 폰 UI는 게임에 접속하지 않은 상태에서도 게임 캐릭터와 대화하는 공간으로 확장한다. 사용자는 캐릭터 한 명과의 1:1 대화 또는 여러 캐릭터가 참여하는 1:n 대화를 원한다. AI 응답을 기다리는 동안 다른 대화 세션으로 이동해 대화를 이어갈 수 있어야 한다.

**제안**

- 폰은 게임 실행 여부와 무관한 독립된 대화 진입점으로 둔다. 게임 캐릭터를 대화 상대로 선택해 폰 대화를 시작할 수 있다.
- 대화 목록에서 여러 세션을 보존하고 빠르게 전환한다. 각 세션은 독립적으로 메시지와 생성 상태를 관리하며, 한 세션의 응답을 기다리는 동안 다른 세션을 사용할 수 있다.
- 게임 안에서 진행한 NPC 대화와 폰 대화는 같은 Conversation/Message 기반을 공유하되, 게임 진행 상태·장면·위치에 의존하는 맥락은 게임 세션에 남긴다. 게임 밖 폰 대화는 그 상태를 요구하지 않는다.
- 1:n 대화는 하나의 Conversation에 여러 참여자를 연결하는 방식으로 모델링한다. 누가 어떤 순서와 조건으로 발언하는지, 한 턴에서 몇 명이 응답할지, 호출 비용과 중복 발언을 어떻게 제한할지는 별도 정책이 필요하다.

**구현 난이도와 판단** 여러 세션을 열어 두고 오가는 UI 자체는 보통 수준의 작업이다. 메시지 저장과 세션별 생성 상태를 분리하고, 세션 전환 후에도 진행 중인 응답을 올바른 대화에 반영하면 된다. 다만 앱 종료·네트워크 오류 때 생성 중 상태를 복구하는 정책과 동시 요청 제한은 정해야 한다. 1:1은 현재 채팅 구조를 공통 Conversation으로 옮기면 자연스럽게 지원할 수 있다. 1:n은 참여자 관리와 발언 순서·맥락 구성 때문에 더 높은 난이도이며 단계적으로 추가하는 편이 좋다.

**권장 순서** 먼저 게임 밖 1:1 폰 대화와 여러 세션 전환을 구현하고, 이후 참여자 목록·발언 규칙을 정해 1:n 대화를 추가한다. 여러 세션은 사용자가 수동으로 오가는 것부터 지원하며, 자동으로 대화를 주고받는 백그라운드 동작은 별도 결정으로 둔다.

### ADR-001 추가 논의: 최상위 탐색과 폰 진입 버튼

**상태** Proposed

**배경** 최상위 탐색에는 홈, 프리셋, API, 게임, 설정이 필요하다. 폰은 일반 대화를 담는 주요 기능이므로 어느 화면에서도 빠르게 열 수 있도록 별도 버튼을 둘지 검토한다.

**제안**

- 홈, 프리셋, API, 게임, 설정은 기본 탐색 그룹으로 둔다. 현재처럼 접을 수 있는 사이드바를 유지한다면 여기에 배치한다.
- 폰은 이 그룹에 묻히지 않도록 상시 보이는 별도 주요 동작으로 둔다. 타이틀바 바로 아래 앱 헤더의 왼쪽에 아이콘과 “폰” 라벨을 함께 표시하고, 클릭하면 대화 목록/최근 대화로 이동한다. 새 대화 시작과 세션 전환은 폰 화면 안에서 제공한다.
- 폰을 윈도우의 네이티브 타이틀바 컨트롤 영역에 넣지는 않는다. 해당 영역은 창 이동·최소화·최대화·닫기 동작과 플랫폼 차이가 있어 기능 탐색 위치로 쓰기 어렵다. 앱 콘텐츠의 헤더에 두면 데스크톱과 모바일에서 일관되게 다룰 수 있다.
- 화면이 좁은 모바일에서는 같은 다섯 탐색 그룹과 폰 주요 동작을 하단 탐색 또는 반응형 메뉴로 재배치한다.
- 캐릭터·페르소나·월드인포 같은 관리 화면은 우선 보조 화면으로 취급하고, 폰의 새 대화 흐름이나 홈에서 진입시킨다. 별도 최상위 버튼이 다시 필요해지는지는 사용 빈도를 보고 결정한다.

**판단** 폰을 항상 눈에 띄게 두는 방향은 제품의 핵심 사용 방식과 잘 맞는다. 다만 창 조작용 타이틀바 자체보다 앱이 관리하는 헤더에 두는 편이 크기 조정과 모바일 대응이 쉽다. 버튼에는 명확한 “폰” 이름을 붙이고, 선택 상태와 읽지 않은 대화 표시를 지원할 수 있도록 한다.

**UI 시안** `src/components/AppNavigationSample.svelte`에 데스크톱 상단 탐색과 좁은 화면 하단 탐색 예시를 둔다. 폰은 강조된 독립 동작이고, 나머지 다섯 항목은 일반 탐색 버튼이다. `/phone`은 현재 대화 목록 화면을 재사용하는 진입 경로로 등록한다. 이 컴포넌트는 탐색 방향을 검토하기 위한 시안이며, 앱 전체 레이아웃에 적용하기 전 실제 화면에서 높이·스크롤·모바일 안전 영역을 확인한다.


### ADR-002 채팅 생성 작업(Task) 실행 흐름

**상태** Accepted

**결정**

- 채팅 생성(보내기·다시 생성·이어 쓰기)은 TaskManager의 작업(ChatGenerate)으로 실행한다. 커맨드는 작업을 제출하고 작업 id를 돌려준다. 생성 상태는 대화별로 독립이라 응답을 기다리는 동안 다른 대화로 이동할 수 있다.
- 같은 대화에는 생성 작업이 하나만 돈다(대화 id가 작업의 resource\_key). 취소는 cancel\_task 하나로 통일한다.
- 스트리밍 조각은 기존처럼 프론트가 넘긴 Channel로 보내고, 끝/실패/취소는 TaskEvent로 알린다. Channel이 끊겨도(화면 이동) 작업은 끝까지 돌고 결과는 DB에 저장된다.
- 멈추기를 누르면 Executor에 유예 시간(10초)을 주고, 그 안에 받은 데까지 저장한 결과는 작업 완료로 친다(TaskExecutor::cancel\_grace).
- 앱이 생성 중에 꺼지면 받던 내용은 남지 않고, 다음 실행 때 그 작업은 Interrupted가 된다. 앱 시작 시 사용자에게 다시 만들지 버릴지 한 번 묻는다(recovery.ts). 자동 재시도는 하지 않는다(사용자 키로 비용이 드는 호출이라).
- 다시 시도할 때 사용자 입력을 두 번 저장하지 않도록, 보내기 작업이 저장한 사용자 메시지에는 meta.taskId를 남기고 그 메시지가 마지막이면 응답만 다시 만든다(TurnKind::Reply).
- 구현: `service/chat/chat_task.rs`(Executor·제출·취소), 동시 실행 작업 수는 4.
- 게임 NPC 대화(game\_chat)는 게임 런타임 락과 호출 제한 안에서 돌기 때문에 이번에는 작업으로 옮기지 않았다.

### ADR-003 보류한 기능

**상태** Deferred (2026-11-15)

- **게임 iframe SDK**: 플레이 화면은 Svelte가 직접 그린다. 외부 HTML/JS 게임을 받을 계획이 가까워지면 재개한다. 빌드 입력(game-runtime.html)에서 뺐고, 초안은 `src/lib/game/`에 남아 있다. 게임 모드 ADR-002의 격리 결정은 그대로 유효하다.
- **장기 기억(memory\_settings, memory\_embeddings)·선톡(proactive\_settings)**: 테이블만 있고 코드는 없다. 채팅 작업 흐름(ADR-002) 위에서 만들 수 있게 되었으므로, 착수할 때 새 ADR로 정책(임베딩 제공자, 선톡 빈도·비용 상한)을 정한다. 테이블은 그대로 둔다.
- **다국어**: svelte-i18n만 설정돼 있고 화면 대부분은 한국어로 쓰여 있다. 영어 지원이 목표가 될 때까지 새 화면부터만 locales 키를 쓴다.

### ADR-004 AI 답변의 HTML 코드 블록 렌더링

**상태** Accepted (2026-11-16)

**결정**

- 답변 안의 ```` ```html … ``` ````(또는 언어 표시 없이 태그로 시작하는 코드 블록)은 iframe으로 그린다. 채팅·폰·게임 모두 같은 컴포넌트(HtmlView)를 쓴다. 닫히지 않은 블록(스트리밍 중)은 글로 둔다. 게임은 대본 파서가 코드 블록을 한 줄로 유지한다.
- **srcdoc을 쓰지 않는다.** srcdoc·blob 문서는 앱 창의 CSP(script-src 'self')를 물려받아 인라인 JS가 막힌다. 대신 백엔드가 `htmlview://localhost/<id>`(Windows/Android는 `http://htmlview.localhost/<id>`)로 서빙하고 그 응답에만 별도 CSP를 붙인다. 내용은 메모리에만 두고(같은 HTML = 같은 id, 최근 300개, 1MB 상한) 화면이 register\_html\_view로 등록한다.
- **격리**: iframe은 `sandbox="allow-scripts"`만 준다(allow-same-origin 없음 → 불투명 origin). 앱 화면·저장소·Tauri IPC에 닿지 못한다. CSP: connect-src 'none'(fetch·XHR·WebSocket·IPC 요청 차단), form-action·frame-src 'none'. 외부 https 이미지·글꼴·스타일·스크립트(CDN 라이브러리)는 허용한다.
- 높이는 iframe이 parent에 postMessage({type:"sc-html-height"})로 알리고, 최대 900px에서 iframe 안 스크롤로 넘긴다.

**결과** AI가 만든 스크립트는 사용자 화면에서 돌지만 앱 데이터와 키에는 닿지 못한다. 외부 리소스를 허용했으므로 이미지 요청으로 외부에 신호를 보내는 것은 막지 않는다(필요하면 img-src를 data:/blob:로 좁힌다).

**갱신 (2026-11-16) 편의 함수**

- 문서 맨 앞(테마 뒤)에 `window.sandcastle`을 넣는다: `fill(글)`(입력칸에 넣기), `send(글)`·`choose(글)`(보내기). 스크립트 없이 `data-sc-send` / `data-sc-choice` / `data-sc-fill`을 단 요소를 눌러도 된다(값이 비면 그 요소의 글자).
- 허용된 요청은 `{type:"sc-action", action:"fill"|"send", text}`뿐이고 글은 4000자까지. 화면(HtmlView)은 메시지를 보낸 창이 그 iframe인지 확인한다.
- **보내기는 요금이 나가므로** 사용자가 그 블록 안을 막 눌렀을 때(iframe에 포커스)만 보낸다. 스크립트가 혼자 부르면 입력칸에 넣기만 하고 "직접 보내기"를 알린다. 받는 쪽은 지금 열린 대화 화면 하나(`shared/html/bridge.ts`).
- 블록 머리줄의 접기 버튼으로 HTML을 접을 수 있다(iframe도 내림). 캐릭터 개요는 코드 블록 밖의 HTML도 같은 iframe으로 그린다(HTML 렌더링이 꺼져 있으면 글만).

### ADR-005 코어 플러그인 (기능 토글)과 AI 도구

**상태** Accepted (2026-11-16)

**결정**

- 부가 기능은 Obsidian의 코어 플러그인처럼 껐다 켠다. 목록·이름·기본값은 백엔드 `sys/plugins.rs` 한 곳에 두고, 켜짐/꺼짐은 기존 기능 설정 저장소(`feature-setting`, id별 bool)에 둔다. 설정 > 코어 플러그인에서 바꾼다.
  - 기본 켜짐: 폰(`phone`), 게임 모드(`game`), 캐릭터 이미지(`chat.images`), 정규식(`regex`)
  - 기본 꺼짐: HTML 렌더링(`html`, AI가 쓴 JS를 실행하므로 — 2026-11-17 합의로 바꿈, M1), 위젯(`widget`, 데스크톱 전용), 번역(`translate`), 음성 읽기(`tts`), 이미지 생성(`imagegen`), 이미지 자동 생성(`imageauto`). 앞으로 추가하는 기능은 모두 기본 꺼짐
- 끄면 화면(사이드바·설정 탭·메시지 동작·패널 스위치)에서 숨기고, 그 화면에 들어가면 "꺼져 있음"과 켜기 버튼을 보여준다. AI 결과에 영향을 주는 것은 백엔드에서도 막는다: 정규식은 불러오지 않고(스위치 하나, `regex_processor::set_enabled`), 캐릭터 이미지 키를 보내지 않고, HTML 서빙과 AI 도구 호출은 거절한다. 끈 기능의 데이터는 지우지 않는다.
- 설정을 바꾸면 백엔드가 모든 창에 `feature_setting::changed`를 보낸다 (메인 창의 플러그인 상태, 위젯 창의 위젯 하위 기능).
- **AI 도구** 세부 설정은 별도 저장소(`plugin-setting`)에 둔다. 셋 다 연결한 API 프로필(주소 + keyring 키)을 쓰고, 비우면 대화/앱에서 고른 API.
  - 번역: 채팅 모델에 번역 지시(형식·태그·코드 블록 유지). 메시지 번역은 meta.translation {lang, text, source}에 저장하고 원문이 바뀌면 무효. 자동 번역, 입력 번역(입력창 + 메뉴).
  - 음성 읽기: OpenAI 호환 `/audio/speech` → mp3를 앱 캐시(tts/)에 저장(같은 글·설정이면 재사용). 태그·코드 블록은 빼고, "대사만 읽기"면 *지문*도 뺀다. 자동 읽기.
  - 이미지 생성: OpenAI 호환 `/images/generations` → png를 앱 데이터(generated/)에 저장하고 meta.generatedImages에 쌓는다. 기본은 채팅 AI가 장면을 영어 프롬프트로 정리하고(캐릭터 설명 포함), 화풍을 끝에 붙인다.

**갱신 (2026-11-16)**

- 공급자: 음성은 ElevenLabs(`/text-to-speech/{voice_id}`, xi-api-key, 계정 목소리 목록), 이미지는 NovelAI(`/ai/generate-image`, 응답 zip의 png, nai-diffusion-4 이상은 v4_prompt 구조)를 지원한다. 음성·이미지 API 프로필의 종류(formatType elevenlabs / novelai, API 키 화면에서 고름)로 갈리고, 그 밖은 OpenAI 호환으로 부른다. NovelAI면 AI가 쓰는 그림 프롬프트도 태그 형식으로 쓴다. 로컬 Stable Diffusion은 지원하지 않는다.
- 이미지 생성 프리셋(NovelAI): 화풍·품질 태그, 네거티브 프롬프트, steps, scale, 샘플러, 크기(64의 배수로 맞춤). 그림 프롬프트를 쓸 채팅 API를 따로 고를 수 있다.
- 폰 대화의 기본 API·프리셋: 대화에 고른 것 → 폰 설정 → 앱 기본값 순서.
- 설정은 "플러그인" 묶음 안에 코어 플러그인(켜고 끄기)과 기능별 탭(폰·번역·음성 읽기·이미지 생성·위젯)으로 나눴다. 기능이 꺼지면 그 탭도 숨는다.
- 이미지 페이지(사이드바 "이미지"): 직접 만들기(AI가 다듬기 선택)와 갤러리(출처별 보기, 크게 보기, 프롬프트 복사·재사용, 원래 대화로, 삭제). 그림은 `generated/<id>.png` 옆 `<id>.json`에 프롬프트·모델·출처를 둔다. 삭제는 그 폴더 안의 png만.
- 게임 대사창: 지금 줄 번역(이번 플레이 동안만 기억), 지금 줄 읽기, 이 응답 장면 그리기(무대 위에 띄움, 갤러리 출처 "게임").
- HTML iframe에는 지금 테마의 CSS 변수와 바탕·글자·버튼·입력칸 기본 스타일을 문서 맨 앞에 넣는다(ADR-004). AI가 쓴 스타일이 뒤에 오므로 덮어쓸 수 있고, 테마가 바뀌면 다시 등록해 새 색이 들어간다.

**갱신 (2026-11-16) 앱 프롬프트**

- 앱이 AI에 보내는 고정 지시문(번역, 장면 → 그림 프롬프트, NovelAI 태그, 캐릭터 이미지 `<cg>` 규칙, 게임 대화 규칙, 씬 입력 규칙)은 `service/app_prompts.rs`에 기본값으로 두고, 사용자가 고친 값은 plugin-setting의 `prompts`에 둔다. 빈 칸 = 기본값이라 "기본값으로"가 언제나 된다. 자리 표시: `{{lang}}`, `{{keys}}`, `{{char}}`. 게임·씬 규칙은 한 줄이 규칙 하나이고, `<updateRel>`이 든 줄은 씬 입력에서 빠진다.
- 설정을 불러오거나 저장할 때 전역 값으로 넣어 두고 쓰는 쪽은 인자 없이 꺼낸다 (설정 > AI > 앱 프롬프트).

### ADR-006 기능·작업·사용량 책임 분리

**상태** Accepted (2026-11-16) — CLAUDE.md 가까운 목표 M2

**배경** 유료 AI 호출이 채팅(TaskManager 작업)과 그 밖(게임 대사·번역·음성·이미지·API 확인, 커맨드에서 바로 호출)으로 갈려 있어, 무엇이 언제 누구 때문에 돈을 썼는지 볼 수 없었다. 원칙: Explicit Execution(실행 주체가 분명), Observability(상태·결과 확인), 사용자 동의 없는 리소스 소비 금지.

**결정** 세 책임을 나눈다. 서로의 저장소를 직접 고치지 않는다.

| 책임 | 무엇을 | 어디에 |
| --- | --- | --- |
| FeatureManager | 기능이 **있는가 / 켜졌는가**와 기능별 설정. 꺼진 기능은 실행 요청 자체를 거절한다 | `sys/plugins.rs`(목록·기본값·`require`), `feature-setting`·`plugin-setting` 저장소 (ADR-005) |
| TaskManager | **실행과 생명주기**: 작업 행·시도·상태 전이·이벤트·취소·복구. 작업에 기능 id(`feature`), 실행 주체(`run_by`: user / auto), 표시 이름(`label`)을 남긴다 | `task/` (`generation_tasks`, `generation_attempts`) |
| ResourceManager (1차) | **사용량**: 공급자 호출 한 번마다 토큰·글자·그림 수, 성공 여부, 걸린 시간 | `db/usage.rs` (`usage_log`) |

- **모든 유료 호출은 작업 안에서**. 오래 걸리고 다시 시도할 수 있는 채팅은 큐 작업(`submit` + 실행기), 그 밖의 짧은 호출은 즉시 실행 작업(`TaskManager::run_inline`)으로 부른다. 즉시 실행 작업도 같은 행·시도·이벤트를 남기고 실행 중 목록에서 멈출 수 있다. 실행기가 없으므로 앱이 꺼지며 끊긴 즉시 실행 작업은 다음 실행 때 취소로 정리한다(다시 시도하지 않음 = 사용자 동의 없이 요금을 쓰지 않음).
  - chat: 응답 생성·다시 생성·다른 응답 / phone: 같은 흐름 + 엿보기 / game: NPC·씬 대사 / translate / tts / imagegen(프롬프트 작성 + 그리기를 한 작업으로) / settings: API 연결 확인
  - 캐시에서 꺼내는 경우(공용 번역 캐시, 이미 만든 음성)는 요금이 없으므로 작업을 만들지 않는다.
- **실행 주체**: 사용자가 누른 것은 `user`, 사용자가 켜 둔 자동 설정(자동 번역·자동 읽기)이 부른 것은 `auto`. 프론트가 명시해서 넘긴다. 자동 설정은 모두 기본 꺼짐.
- **사용량 기록 위치**: 공급자를 실제로 부르는 한 곳(`AiService::generate`, 음성·이미지 호출)에서 남긴다. 어느 작업의 호출인지는 인자로 넘기지 않고 tokio task-local(`task::current_task`)로 안다. 그래서 새 기능이 AiService를 쓰기만 하면 사용량은 자동으로 잡힌다. 작업 밖에서 부른 호출도 사용량은 남는다(작업 id 없음).
- **토큰**: 공급자가 응답에 주면 그 값(OpenAI `usage`, Claude `usage`(스트림은 message_start/message_delta), Gemini `usageMetadata`), 없으면 앱이 추정(프롬프트 블록 토큰 + 받은 글)하고 `estimated=1`. 실패·취소한 호출도 받은 만큼 기록한다(요금이 나갈 수 있음).
- **화면**: 설정 > 관리 > 실행 기록 — 실행 중(멈추기), API 프로필·종류별 사용량(오늘/7일/30일/전체, 비우기), 최근 실행(자동만 보기, 펼치면 작업 id·API·모델·걸린 시간·시도·오류). 화면이 열려 있을 때만 불러오고 `task-event`로 새로 고친다.
- 사용량 기록은 실패해도 원래 호출을 망치지 않는다(로그만).

**다음 단계**: 예산 한도는 ADR-007. 요금 단가표로 금액 환산, 오래된 작업·사용량 기록 정리(1-A-3, 1-A-4).

### ADR-007 예산 한도

**상태** Accepted (2026-11-16) — CLAUDE.md 1-A (M9)

**배경** ADR-006으로 사용량은 보이지만 막지는 못했다. 선톡·에이전트·자동 색인처럼 "사용자가 안 볼 때 요금이 나가는" 기능(5-A, 5-B, 3-C)보다 먼저 상한이 필요하다. 원칙: 사용자 동의 없는 리소스 소비 금지, Observability.

**결정**
- **한도 모델** (`budget_limits`, `db/budget.rs`): API 프로필별 하루/한 달 상한 — 토큰(입력+출력)·음성 글자·그림 장 수. 비우면 한도 없음(기본). 0 이하는 "없음"으로 저장한다(실수로 모든 호출이 막히지 않게). 하루·한 달은 기기의 현지 시각(오늘 0시, 이번 달 1일 0시)부터. 실패한 호출도 센다(요금이 나갈 수 있음). 프로필을 지우면 한도도 지워진다.
- **어디서 막나**: 계획은 "TaskManager가 실행 전에 묻는다"였지만, 작업을 만들 때는 어느 API 프로필을 쓸지 아직 모른다(프리셋·대화 설정·플러그인 설정을 거쳐 AiService에서 정해짐). 그래서 **공급자를 실제로 부르기 직전**(`AiService::generate`, 음성·이미지 호출 — 사용량을 기록하는 바로 그 자리)에 `service/budget.rs`가 확인한다. 이 자리는 항상 작업 안이므로 결과는 같다: 막힌 작업은 공급자를 한 번도 부르지 않고 `BUDGET_EXCEEDED`(재시도 안 함)로 실패하며 실행 기록에 "한도로 막힘"으로 남는다. 호출 종류별로 해당 단위만 본다(채팅은 토큰, 음성은 글자, 그림은 장 수).
- **이번만 계속** (사용자 합의 2026-11-16): 자동 실행(`run_by = auto`)은 항상 막는다. 사용자가 누른 실행(`user`)이 막히면 알림에 "이번만 계속"이 뜨고, 누르면 2분 안에 사용자가 다시 실행하는 **작업 하나**가 한도를 넘어 실행된다(한 작업 안의 여러 호출 — 예: 이미지 프롬프트 작성 + 그리기 — 은 같이 허용). 허용은 메모리에만 있고 앱을 다시 켜면 사라진다. 다시 누르게 하는 것은 Explicit Execution 때문(알림 버튼이 요금을 쓰는 실행을 대신 시작하지 않음).
- 실행 주체는 작업의 task-local(`CurrentTask.run_by`)로 안다. 작업 밖의 호출은 user로 본다.

| 창 상태, localStorage(폰 주인·배경 선택·마지막 읽음 등) | 화면 상태 | 기기 전용 | X |
| OS keyring | API 키·토큰 | 비밀 | **절대 X** (백업·내보내기·동기화·로그 어디에도) |

- **백업 v2**: 위 표의 O 폴더 전부. manifest에 담은 폴더(`dirs`)를 적고, 복원은 그 폴더만 바꾼다. v1 백업(`dirs` 없음)은 characters·games·themes만 바꾸고 갤러리·배경은 지금 것을 그대로 둔다.
- **경로 보정**: 다른 PC에서 만든 백업은 앱 데이터 경로가 다르다. 복원 뒤 DB의 모든 글자 칸과 `settings.json`에서 옛 앱 데이터 경로를 새 경로로 바꾼다(그대로 / JSON 안의 역슬래시 두 개 / 슬래시 모양). 앱 데이터 경로는 다른 글에 우연히 나오기 어려운 긴 문자열이라 칸을 가리지 않고 바꾼다.
- 갤러리 정보 `.json` 안의 `path`는 목록을 만들 때 실제 파일 위치로 다시 채우므로 고치지 않는다.
- **마이그레이션 전 사본** (1-B-2): 앱을 시작할 때 이미 쓰던 DB에 적용할 새 마이그레이션이 있으면, 적용하기 전에 `migration-backups/app-<시각>-v<지금 버전>.db`로 사본을 만든다(VACUUM INTO). 최근 3개만 남긴다. 새로 만든 DB는 건너뛴다. 사본을 만들지 못해도 앱은 연다(로그만 — 시작을 막으면 데이터를 꺼낼 방법도 없어짐). 되돌릴 때는 앱을 끄고 사본을 `app.db`로 바꾼다(화면은 아직 없음).

### ADR-009 Android 플랫폼 처리

**상태** Accepted (2026-11-16) — CLAUDE.md 1-C (M10). 점검 결과는 `docs/Android 점검표.md`.

**결정**
- **비밀 저장소**: 데스크톱은 OS keyring(keyring v4), Android는 `android-native-keyring-store`(Android Keystore 키로 암호화한 SharedPreferences, keyring-core 직접 사용). 평문 파일에 두지 않는다. 테스트는 메모리 저장소(OS 자격 증명 관리자를 건드리지 않음).
- **고른 파일**: Android 파일 고르기의 `content://` 주소는 프론트 `pickFiles`/`saveTo`가 받아 백엔드(`service/picked_file.rs`)가 앱 `tmp/`로 복사하거나 `tmp/saving/`에서 고른 곳으로 옮긴다. 가져오기·내보내기 커맨드는 계속 파일 경로만 다룬다. 공용 다운로드 폴더에 직접 쓰지 않는다(Android 10+ 저장소 정책).
- **화면 가장자리**: edge-to-edge를 유지하되, 아래(키보드·탐색 막대)는 `MainActivity`가 비우고 위(상태 표시줄)는 CSS `--safe-top`(= max(env, 앱이 알려 준 값))으로.
- **백그라운드 생성**: AI 작업이 도는 동안만 포그라운드 서비스(dataSync)를 켜고 끝나면 끈다. 서비스는 프로세스를 살려 두기만 하며 작업을 멈추지 않는다(끄는 순간 생성이 끊기지 않게). 알림 줄에 "응답을 만드는 중"이 보인다(Observability). 앱이 꺼진 동안의 실행(선톡 등)은 5-A-6에서 따로 정한다.
- **화면 → 앱(Kotlin) 연결**: 숫자만 돌려주는 상태 표시줄 높이는 `addJavascriptInterface`, 동작이 있는 서비스 켜고 끄기는 `addWebMessageListener`로 **앱 주소(`http://tauri.localhost`)의 최상위 프레임만** 받는다 — AI가 쓴 HTML(htmlview iframe)은 이 객체를 볼 수 없다(Least Privilege).
- **뒤로 가기**: 앱 안 이동 기록(nav)을 브라우저 기록과 맞춰 시스템 뒤로 가기가 앞 화면으로 가게 한다.
- **데스크톱 전용 기능**: 코어 플러그인의 `desktop_only`는 모바일에서 목록에서 빠지고 늘 꺼짐으로 본다.
- **마이그레이션 파일**: `.gitattributes`로 줄 끝 변환을 막는다(sqlx 체크섬이 체크아웃 환경에 따라 바뀌지 않게).

### ADR-010 버전·업데이트·서명·릴리스

**상태** Accepted (2026-11-17) — CLAUDE.md 1-E (M11). 절차는 `docs/배포.md`.

**결정**
- **버전**: `package.json` 한 곳. `tauri.conf.json`은 `../package.json`을 읽고 `Cargo.toml`은 `scripts/version.mjs`가 맞춘다. CI가 세 곳이 같은지 확인. 변경 내역은 `CHANGELOG.md`.
- **업데이트**: GitHub Releases(`dily311/sandcastle`)의 최신 공개 릴리스와 비교해 알리기만 한다. 내려받기·설치는 하지 않고 릴리스 페이지를 연다(사용자가 직접). 확인은 사용자가 누를 때만, "앱을 켤 때 확인"은 별도 스위치이며 기본 꺼짐(사용자 동작 없는 외부 요청이므로). 요청에는 일반 User-Agent만. Tauri updater는 쓰지 않는다(업데이트 서명 키·자동 설치가 필요해 "알림만" 범위를 넘음). 예전 "자동 업데이트" 스위치는 연결된 동작이 없었으므로 화면에서 뺐다(저장값은 호환용으로만 남김).
- **서명** (사용자 결정 2026-11-17): Windows는 당분간 코드 서명 없음(SmartScreen 경고를 릴리스 설명에 적음). Android 키는 사용자 PC(저장소 밖)와 GitHub Secrets에만 두고, `keystore.properties`가 있을 때만 release 빌드에 서명한다. 배포 빌드(R8)에서 JS가 부르는 `@JavascriptInterface`는 keep 규칙으로 지킨다.
- **릴리스**: 태그 `v<버전>` → `.github/workflows/release.yml`이 Windows 설치 파일과 APK를 만들어 **초안** 릴리스에 올린다. 공개는 사람이 한다(Explicit Execution). 태그와 버전이 다르면 멈춘다.

### ADR-011 동기화 방식

**상태** Accepted (2026-11-17, 사용자 결정) — CLAUDE.md 2단계. 대상 표(2-A-1)는 아래. 동기화는 코어 플러그인 `sync`(기본 꺼짐).

**결정**
| 항목 | 결정 | 이유 |
| --- | --- | --- |
| ① 저장소 | **사용자가 고른 폴더를 먼저**(2-C), 같은 `SyncTarget` 위에 **구글 드라이브 앱 전용 폴더**(2-D). WebDAV는 하지 않음 | 폴더 대상은 OAuth 없이 병합 로직을 검증할 수 있고, OneDrive·Dropbox 같은 동기화 앱에 맡길 수 있다. 드라이브는 `drive.appdata` 권한만(Least Privilege) |
| ② 단위 | **항목(행) 단위 병합**. 전체 스냅샷 교체는 하지 않음 | 두 기기에서 따로 쓴 것이 사라지지 않게 |
| ③ 충돌 | **둘 다 남김**. 같은 행을 양쪽에서 고쳤으면 한쪽을 "충돌 사본"으로 남겨 2-E 화면에서 고른다. 대화는 갈라진 지점부터 분기로 남긴다. 지우기 ↔ 고치기 충돌은 고친 쪽을 살린다 | 조용히 덮어쓰지 않는다(Reversibility). 적용 전 자동 백업도 남긴다 |
| ④ 큰 파일 | **사용자 데이터 파일만**(ADR-008 표의 사용자 데이터 폴더: characters·games·themes·generated·backgrounds), **해시로 바뀐 것만** 보낸다. 캐시(음성 캐시·앨범 아트)·임시·안전망 폴더는 제외. Android에 "Wi-Fi에서만" 옵션 | 용량과 데이터 요금을 줄이고, 다시 만들 수 있는 것은 보내지 않는다 |
| ⑤ 암호화 | **선택 사항, 기본 꺼짐**. 켜면 사용자가 정한 암호 문구로 묶음을 암호화하고, 문구는 기기마다 keyring에 넣으며 동기화하지 않는다. 문구를 잊으면 저장소의 사본은 못 읽는다(각 기기의 원본은 남음). 2-C 뒤에 붙인다 | 키·토큰은 원래 묶음에 없고, 대화 내용 보호가 필요한 사람만 켜게 |

**변하지 않는 규칙**
- API 키·토큰·암호 문구는 어떤 경우에도 묶음·저장소·로그에 넣지 않는다(2-B-4 테스트로 고정). API 프로필 행은 동기화하되 키는 기기마다 다시 넣고 "키 없음"을 보여준다.
- 실행은 "지금 동기화" 버튼이 먼저. 자동 동기화(시작·종료·주기)는 별도 스위치, 기본 꺼짐. 실행은 TaskManager 작업(feature `sync`)으로 기록한다.
- 스키마 버전이 낮은 기기는 묶음을 적용하지 않고 업데이트를 안내한다.

**동기화 대상 (2-A-1)** — id는 이미 대부분 `Uuid::new_v4` 글자 id라 기기 사이에서 겹치지 않는다. 정수 id 테이블(`conv_settings`·`usage_log`·`usage_daily`)은 아래처럼 다룬다. 연결 테이블(복합 키)은 그 키로 합친다.

**변경 추적 구현 (2-A-2)** — 마이그레이션 156.
- 동기화 대상 71개 테이블에 `updated_at`(없던 곳은 추가, 기존 행은 `created_at`이나 지금 시각으로)을 둔다. 행에 지움 표시(`deleted_at`)는 두지 않는다 — 아래 2-A-3.
- 함수마다 고치는 대신 **트리거**로 모든 쓰기를 잡는다: INSERT에서 비었거나 0이면 지금 시각, UPDATE에서 코드가 `updated_at`을 바꾸지 않았으면 지금 시각. 코드가 직접 다른 값을 쓰면 그대로 둔다 — 2-B 병합이 원래 기기의 시각을 넣을 수 있게. 단, 병합이 지금 값과 **같은** 시각을 쓰면 지금 시각으로 바뀌므로 병합은 같은 시각이면 쓰지 않는다(2-B-2).
- 시각은 모두 밀리초. 초로 쓰던 곳(API 프로필, 관계 스냅샷, 기본 페르소나 초기값)을 밀리초로 바꾸고 기존 값(< 1e11)도 맞췄다.
- id: 동기화 대상의 id는 `Uuid::new_v4` 글자 id다. 처음 만들어지는 고정 id(`default` 프리셋·블록·페르소나, `conv_settings` id 1)는 모든 기기에서 같은 항목이므로 같은 id로 합친다. 가져오기(.tgame·.scpack)는 이미 새 id로 바꾼다.
- 키가 없는 테이블(game_journal·game_saves·game_weather_pool_entries)은 UNIQUE 묶음(세션+번호 / 세션+슬롯 / 풀+날씨)을 병합 키로 쓴다(2-B-1).
- 실제 DB 사본(메시지 68개)에서 0.55초, 무결성 점검 정상.

**휴지통과 지운 기록 (2-A-3)** — 마이그레이션 157, `service/data/trash.rs`.
- 계획은 "지우기를 `deleted_at` 표시로"였지만, **떠 두고 지우는 방식**으로 바꿨다. 행에 표시를 하면 모든 목록·검색·프롬프트 조립 쿼리(수백 곳)가 지운 행을 빼야 하고, 하나라도 빠뜨리면 지운 대화가 프롬프트에 섞이는 식의 사고가 난다. 대신:
  - **휴지통**: 지울 때 그 항목과 FK CASCADE로 같이 지워지는 행 전부를 JSON으로 떠서 `trash_items`에 넣고 실제로 지운다. 지울 때 NULL이 되는 바깥 연결(FK SET NULL, 예: 캐릭터를 지우면 대화의 `character_id`)과 트리거로 지워지는 폰 연락처도 적어 둔다. 파일(채팅 이미지 폴더·게임 폴더·앱이 복사한 페르소나 아바타)은 `trash/<id>/`로 옮긴다. 테이블·FK 구조는 DB에서 읽으므로(pragma) 테이블이 늘어도 고칠 곳이 없다.
  - **되살리기**: 행을 다시 넣고(`updated_at`은 지금 — 다른 기기의 지운 기록보다 새것), 끊긴 연결을 다시 잇고(그 사이 사용자가 다른 값을 넣었으면 두고), 파일을 제자리로. 연결된 항목이 이미 없으면(예: 세션을 되살리려는데 게임을 완전히 지움) 아무것도 바꾸지 않고 이유를 알린다.
  - **지운 기록** (`sync_tombstones`): 동기화 대상 테이블의 모든 DELETE를 트리거가 (테이블, 키 json_array)로 남긴다 — 휴지통에 안 가는 지우기(메시지·로어북 항목·게임 편집기)도 포함. 같은 키로 다시 들어오면 지운다(되살리기·다시 연결). 2-B가 이것으로 다른 기기에 지우기를 전한다. 오래된 기록 정리는 2-B/2-C에서 정한다.
- 휴지통에 가는 것: 캐릭터, 페르소나, 대화(여러 개 지우기 포함), 로어북, 프리셋, 게임, 게임 플레이 기록. 메시지·로어북 항목 같은 작은 단위는 휴지통에 가지 않는다(지운 기록만 남음).
- 보존 기간: 설정 `trashRetentionDays`(기본 30일, 7/30/90/계속). 지난 항목은 휴지통을 열거나 새로 지울 때 완전히 지운다 — 시작할 때 따로 돌지 않는다(Lazy Initialization). 완전히 지우기·비우기는 확인을 받는다.
- 휴지통과 지운 기록은 기기마다 따로다(동기화 안 함). 백업에는 들어간다(`trash/` 폴더 = ADR-008 표).
- 화면: 지운 직후 "되돌리기" 알림(6초), 설정 > 데이터 > 휴지통(되살리기 / 완전히 지우기 / 비우기 / 보존 기간).

**기기 id와 설정 나누기 (2-A-4)** — `service/device.rs`, `service/data/settings_scope.rs`.
- **기기 id**: 설치마다 uuid 하나를 앱 데이터 폴더의 `device.json`에 둔다. DB·settings.json에 두지 않는 이유는 둘 다 백업에 들어가서, 백업을 다른 기기에 복원하면 id까지 복제되기 때문. 동기화가 처음 필요로 할 때 만든다(지금은 아무도 부르지 않아 파일이 생기지 않음).
- **설정 칸마다 범위**: settings.json의 모든 칸을 "같이 씀 / 같이 쓰되 경로 보정 / 기기 전용"으로 표에 적었다. 표에 없는 칸이 생기면 테스트가 실패한다. 묶음에는 같이 쓰는 칸만 넣고(`shared_part`), 받는 쪽은 기기 전용 칸과 모르는 칸을 건드리지 않고 합친다(`merge_shared`).

| 같이 씀 | 기기 전용 |
| --- | --- |
| 언어, 프리셋·페르소나 선택, 시각 표시, 폰 모드 프롬프트, 홈 화면 | 고른 API, 엔터로 보내기, 고른 캐릭터·마지막 게임(화면 상태), 업데이트 확인, 실행 기록·휴지통 보관 기간 |

- 기능 켜기와 자동 실행 스위치를 기기 전용으로 둔 이유: 요금이 나가는 동작은 그 기기에서 사용자가 직접 켜야 한다("사용자 동의 없는 리소스 소비 금지"). PC에서 자동 번역을 켰다고 폰에서 저절로 요금이 나가지 않게.
- API 선택이 기기 전용인 이유: 키가 기기마다 따로이고, 로컬 모델 주소는 그 PC에서만 닿는다. API 프로필 행 자체는 동기화하고, 키가 없는 기기는 설정 > API 키에 "키 없음"이 보이며(이미 있던 표시), 그 프로필로 보내면 "이 기기에 키가 없음 — 설정 > API 키에서 넣기"로 알린다.
- 그 밖의 기기 전용: 창 위치·크기(window-state), 위젯 음악(`widget.json`), localStorage(폰 주인·배경 선택·마지막 읽음 등).

**동기화 묶음 형식 (2-B-1)** — `service/data/sync_bundle.rs`, 확장자 `.scsync`(zip).

| 안의 파일 | 내용 |
| --- | --- |
| `manifest.json` | `format`("sandcastle-sync")·`formatVersion`(1)·`schemaVersion`(보낸 DB의 마이그레이션 번호)·`appVersion`·`deviceId`·`createdAt`·`since`(이 시각 뒤 바뀐 것만, 없으면 전부)·테이블별 행 수·지운 기록 수·파일 수·`encryption`(지금은 늘 없음) |
| `tables/<테이블>.jsonl` | 동기화 대상 테이블에서 `updated_at > since`인 행, 한 줄에 {열: 값} 하나. 열 이름으로 담으므로 받는 쪽 스키마가 조금 달라도 아는 열만 쓰면 된다 |
| `tombstones.json` | `sync_tombstones`에서 `deleted_at > since`인 것 |
| `settings.json` | 같이 쓰는 설정 칸만 (`settings_scope::shared_part`) |
| `files.json` | 사용자 데이터 폴더(characters·games·themes·generated·backgrounds — 휴지통 제외)의 **모든** 파일: 경로·크기·sha256·수정 시각·`included` |
| `blobs/<sha256>` | `included` 파일 내용(같은 내용은 한 번). `since` 뒤에 바뀐 파일만, 또는 "파일 빼고" 선택이면 없음 |

- 파일 목록은 늘 전부 담는다: 받는 쪽이 "나한테 없는 해시"를 알아 다음 묶음에서 요청하거나(2-C), 없다고 보여줄 수 있게. 내용만 골라 담는다.
- **경로 자리표시**: 행·설정 글자 속의 보낸 기기 앱 데이터 경로(그대로 / JSON 안 역슬래시 두 개 / 슬래시 모양)를 `$SANDCASTLE_DATA$`로 바꾸고, 그 뒤 경로의 구분자를 `/`로 맞춘다. 받는 쪽은 자기 경로로 되돌린다(`/` 구분자 — Windows도 읽음). Windows ↔ Android가 맞고, 묶음에 보낸 사람의 사용자 이름이 든 경로가 남지 않는다(Least Privilege).
- **여는 쪽 검사**: 형식 이름, 형식 버전, **스키마 버전이 이 기기보다 높으면 열지 않고 "이 기기의 앱을 업데이트"** 안내, 암호화된 묶음 거부, 파일 경로가 동기화 폴더 안인지·`..`·드라이브 문자, 해시 모양, 꺼낸 파일의 해시가 맞는지(다르면 지움).
- 넣지 않는 것: 동기화 안 하는 테이블(실행 기록·캐시·기기 전용·휴지통·지운 기록 표 자체), `device.json`, `trash/`, 기기 전용 설정, API 키(원래 DB·설정에 없음 — 2-B-4가 묶음 전체에서 가짜 키를 찾는 테스트로 고정).
- 테이블 구조 읽기(pragma)는 휴지통과 같이 `db/schema.rs`로 옮겨 같이 쓴다.
- 묶음의 `createdAt`은 행을 읽기 **전** 시각이다: 읽는 동안 바뀐 행은 다음 묶음에 들어간다(받는 쪽은 `createdAt` 이전을 "이미 본 것"으로 여기므로).

**병합 (2-B-2)** — `service/data/sync_merge.rs`, 마이그레이션 158(`sync_peers`, `sync_conflicts`).
- **시계를 섞지 않는다.** 기기마다 시계가 다를 수 있으므로, 받은 행의 시각은 보낸 기기 시각(그 기기에서 마지막으로 합친 묶음의 `createdAt`)하고만, 이 기기 행의 시각은 이 기기 시각(그때 합친 시각)하고만 비교한다. 기기마다 `sync_peers`에 이 둘을 적는다. 받아서 쓴 행의 `updated_at`은 이 기기의 지금 시각으로 둔다 — 한 DB 안의 시각은 늘 한 시계.
- 행마다 (키 = 기본 키, 없으면 UNIQUE 묶음):

| 받은 행 | 이 기기 | 결과 |
| --- | --- | --- |
| 그 기기에서 마지막으로 합친 뒤 안 바뀜 | — | 건너뜀 |
| 바뀜 | 없음 | 넣음 |
| 바뀜 | 없음, 이 기기에서 지움 | **되살림**(고친 쪽을 살린다). CASCADE로 매달린 자식도 같이 |
| 바뀜 | 내용 같음(시각 칸 빼고) | 그대로 |
| 바뀜 | 그 뒤로 안 고침 | 받은 것으로 바꿈 (`ON CONFLICT DO UPDATE` — REPLACE는 지웠다 넣어 자식이 CASCADE로 사라지므로 쓰지 않음) |
| 바뀜 | 그 뒤로 고침 | **둘 다 남김**: 이 기기 것을 두고 받은 행을 `sync_conflicts`(edit)에 |

- **받은 지운 기록**: 이 기기가 그 뒤로 고친 행은 지우지 않고(고친 쪽을 살린다), 그 행에 CASCADE로 매달린 행도 지우지 않는다(대화를 고쳤는데 메시지만 사라지지 않게). 나머지는 지운다.
- **같은 대화에 양쪽이 이어 씀**(메시지 번호가 겹침): 이 기기 대화는 그대로 두고, 겹치기 전까지의 메시지를 복사한 **분기 대화**("… · 다른 기기", meta.branch에 부모·기기)를 만들어 받은 메시지를 새 id로 넣는다. 그 메시지를 가리키던 책갈피·태그도 새 id로. `sync_conflicts`(branch)에 기록.
- **넣지 못한 행**은 버리지 않는다: 다른 UNIQUE 규칙에 걸림 → `sync_conflicts`(unique), 이 기기에 없는 항목을 가리킴 → 비워도 되는 연결(FK SET NULL)은 비우고, 아니면 `sync_conflicts`(orphan)에 남기고 뺀다. 이때 생긴 지운 기록은 지운다(다른 기기에 "지웠다"고 전하지 않게).
- **처음 만나는 기기**: 이 기기의 모든 행을 "고친 것"으로 본다. 내용이 같으면(기본 페르소나·프리셋처럼 시각만 다른 것 포함) 아무 일도 없고, 다르면 둘 다 남긴다. 빈 기기가 처음 받을 때는 충돌이 없다.
- **같이 쓰는 설정 칸**은 받은 것으로 바꾼다(설정은 칸마다 시각이 없어 "둘 다 남김"이 없다 — 2-B-3 미리보기에서 보여준다). 기기 전용 칸은 그대로.
- **거절**: 자기 기기의 묶음, 이미 합친 묶음(또는 그보다 오래된 것), 스키마가 더 새 앱의 묶음("이 기기의 앱을 업데이트").
- **미리보기**(`dry_run`): 같은 일을 한 트랜잭션에서 하고 되돌린다 — 숫자(추가·변경·지움·되살림·충돌·분기)만 남는다.
- **묶음이 알려 주는 것** (에뮬레이터 점검에서 추가, 2026-11-17): 처음 만난 기기에서 받으면 이 기기의 모든 행을 "고친 것"으로 보는 규칙만으로는, A → B → (B가 고침) → A 순서에서 A가 B의 고침을 충돌로, B의 지우기를 "이 기기 고침 유지"로 막았다. B는 이미 A의 묶음을 합쳐 그 행들을 봤는데 묶음이 그걸 말해 주지 않았기 때문. 그래서 묶음에:
  - `acks` {기기 id: 그 기기 묶음의 createdAt} — 보낸 쪽이 합친 묶음들. 받는 쪽은 자기 id의 값(= 자기 시계) 이전에 바뀐 자기 행을 "보낸 쪽이 이미 본 것"으로 여긴다(`local_base = max(마지막으로 합친 시각, ack)`). 시계는 여전히 섞이지 않는다.
  - `held` {받을 기기 id: [(테이블, 키)]} — 보낸 쪽이 받은 행 대신 자기 것을 둔 행(아직 고르지 않은 edit 충돌). ack만 보면 받는 쪽은 "보낸 쪽이 내 것을 봤다"며 덮어쓰므로, 이 행들은 받는 쪽도 둘 다 남긴다.
  - 둘 다 형식 v1에 선택 칸으로 더했다(없으면 빈 것).
- 정해 두지 않은 것: 충돌·분기를 고르는 화면(2-E).

**폴더 동기화 (2-C)** — `service/data/sync_target.rs`, `sync_run.rs`, `commands/sync.rs`(`sync_now`, `list_sync_runs`), 마이그레이션 159, 설정 > 동기화 > 폴더 동기화.
- **저장소 모양** (`SyncTarget`: list / get / put / delete — 폴더와 2-D의 드라이브가 같이 따름):
  - `devices/<기기 id>.scsync` — 기기마다 **자기 파일 하나만** 쓴다. 두 기기가 같은 파일을 쓰지 않으므로 OneDrive·Dropbox 같은 동기화 앱과 다투지 않는다. 동기화 앱이 만든 충돌 사본(이름 (1).scsync 등)·이름과 안의 기기가 다른 파일은 읽지 않는다.
  - `blobs/<sha256>` — 파일 내용. 한 번 올리면 모든 기기가 같이 쓴다. 기기 묶음에는 내용 없이 목록만 넣는다.
  - 폴더 대상은 고른 폴더 안에 `sandcastle-sync/`만 만든다. 쓸 때는 `.partial`로 다 쓴 뒤 이름을 바꿔, 동기화 앱이 반쯤 쓴 파일을 올리지 않게.
- **"지금 동기화" 한 번** (`sync_run::run`): ① 다른 기기 파일 중 마지막으로 합친 뒤 새로 쓰인 것만 받아, 처음 합치기 전에 DB·설정 사본(`sync-backups/`), 이 기기에 없는 파일을 `blobs/`에서 받아 해시 확인 후 넣고, DB를 합친다(2-B-2) ② 이 기기 묶음을 올린다 ③ 저장소에 없는 파일 내용만 올린다 ④ 지운 기록 정리. "받기 → 올리기" 순서라야 올리는 묶음의 acks에 방금 합친 것이 들어간다.
- **실행 주체**: "지금 동기화" 버튼이 먼저. **자동 동기화는 별도 스위치, 기본 꺼짐** — 켜면 앱을 켜고 20초 뒤 한 번, 그 뒤 15분~3시간마다(앱이 켜져 있는 동안만, 앱을 끌 때는 하지 않음). 동기화 플러그인·자동 스위치·폴더가 모두 있을 때만 타이머를 만든다(`src/app/autoSync.svelte.ts`). 자동 실행은 `run_by = auto`, 실패해도 다시 시도하지 않고 기록·로그에만 남긴다(요금이 드는 일이 아니므로 알림은 띄우지 않음). 동시에 두 번 돌지 않는다.
- **구글 드라이브 (2-D)** — 사용자 결정(2026-11-17): OAuth 클라이언트는 **빌드할 때 넣는다**(`build.rs`가 `src-tauri/google-oauth.env` 또는 환경 변수를 `option_env!`로; 저장소에 없음, CI는 GitHub Secrets), **데스크톱 먼저, Android는 서명 키를 만든 뒤**.
  - 로그인(`service/drive/auth.rs`): 기본 브라우저 → `http://127.0.0.1:<빈 포트>` loopback → PKCE(S256) + state로 토큰 교환. 5분 안에 안 돌아오면 그만둠. 권한은 **`drive.appdata`(앱 전용 폴더) 하나** — 사용자의 다른 드라이브 파일은 보지 못한다(Least Privilege). refresh token은 keyring에만, access token은 메모리에만. 사용자가 "로그인"을 누를 때만 브라우저를 연다.
  - 저장소(`service/drive/target.rs`): 폴더와 같은 `SyncTarget`. `appDataFolder` 안에 `devices/…`·`blobs/…`를 이름 그대로. 동기화 한 번마다 목록을 다 읽어 이름 → id 표. 올리기는 resumable 업로드를 8MB 조각으로(조각마다 세 번까지 다시). 401이면 토큰을 새로 받아 한 번 더. 같은 이름은 바꿔 넣는다(파일이 늘지 않음).
  - 연결 끊기(2-D-3): 구글에서 권한을 거두고(revoke) keyring에서 지운다. **드라이브의 데이터는 그대로**(다른 기기가 계속 씀). "드라이브 데이터 지우기"는 따로 고르고 확인을 받는다(앱 전용 폴더를 비움 — 되돌릴 수 없음). 끊으면 자동 동기화도 끈다.
  - 저장소 고르기: 설정 > 동기화 > 자동으로 주고받기의 "폴더 / 구글 드라이브"(기기 전용 `plugin-setting.sync.target`). 지금 동기화·자동 동기화가 같은 흐름(`sync_run`)으로 돈다.
  - 테스트는 가짜 드라이브 서버(손으로 읽는 HTTP/1.1)로 — 실제 구글에 요청하지 않는다.
  - 실제 구글로 확인(2026-11-17, 테스트 빌드 둘 + 사용자 계정): 로그인(권한 화면에 앱 전용 폴더만), 기기 B가 올리고 A가 받음, A의 고침이 B로 — 충돌 0.
  - 파일 내용은 **4개씩 동시에** 주고받는다(드라이브는 파일마다 왕복이 두 번이라 하나씩이면 40개에 97초 → 4개씩이면 파일당 약 1초).
- **Android 드라이브** (2026-11-17): 구글은 Android에서 데스크톱식(브라우저 + loopback) 로그인을 받지 않으므로, **Play 서비스의 권한 요청**(`AuthorizationClient`, play-services-auth)으로 `drive.appdata` 권한만 받는다(`gen/android/…/DriveAuth.kt`). 구글 클라우드의 **Android 클라이언트(패키지 이름 + 서명 키 SHA-1)**로 앱을 알아보므로 코드에 클라이언트 ID가 없다. refresh token은 받지 않는다 — 동기화할 때마다 화면이 폰에 묻고(이미 허락했으면 화면 없이) 받은 access token을 백엔드에 넘긴다(`drive_use_token`, 메모리에만). keyring에는 "허락받음" 표시만. 토큰이 없거나 만료되면 백엔드가 `details.driveAuthRequired`로 알려 화면이 새로 받는다. 연결 끊기는 지금 가진 access token으로 권한을 거둔다.
  - 화면 ↔ 앱: 기존 `SandcastleNative`(앱 주소의 최상위 프레임만) 메시지 `drive:authorize:<id>:<동의 화면 허용>` → 답 {token | error}. AI가 쓴 HTML iframe은 이 객체를 보지 못한다.
  - **Wi-Fi에서만** (기본 켜짐, 기기 전용 `sync.wifiOnly`): 자동 동기화는 요금이 드는 연결이면 건너뛰고, 직접 누르면 먼저 묻는다. 연결 확인은 `SandcastleNet.unmetered()`(참거짓 하나, `ACCESS_NETWORK_STATE`).
  - Android는 폴더 동기화가 없으므로 저장소 고르기 없이 드라이브만. 자동 동기화도 Android에서 돈다(앱이 켜져 있는 동안).
  - 서명 키마다 Android 클라이언트가 따로 필요하다: 지금은 디버그 키(SHA-1 40:A1:…:62:8F)로 확인했고, 배포용 키를 만들면 그 SHA-1로 클라이언트를 하나 더 등록해야 배포 APK에서 로그인된다.
- **분기로 옮긴 메시지 기억** (Android 점검에서 찾음, 마이그레이션 161 `sync_id_map`): 받은 메시지를 분기 대화로 옮기며 새 id를 줄 때 "받은 id → 이 기기 id"를 남긴다. 같은 메시지가 다른 기기를 거쳐 다시 와도 분기를 또 만들지 않고, 그 메시지를 가리키는 책갈피 등도 같은 새 id로.
- **옛 판 거르기** (2-D 점검 중 찾음, 마이그레이션 160): 합치는 순서가 기기 id 순서라, C가 B의 새 판을 먼저 받고 A의 옛 판(B가 이미 본 것)을 나중에 받으면 충돌로 보였다. 그래서 합친 기기의 acks를 `sync_peers.acks`에 기억하고, 받은 행이 이 기기 행의 출처 기기가 이미 본 판보다 오래됐으면 건너뛴다. 테스트는 두 순서를 모두 고정해서 돈다.
- **기록** (2-C-3): 실행 기록(TaskManager, feature `sync`)과 별도로 `sync_runs`에 시작·끝·성공·오류·요약(기기별 합친 수, 파일 받음·올림·아직 없는 파일, 정리한 지운 기록)을 최근 100개. 화면에 최근 10개와 진행 단계(`sync::progress` 이벤트).
- **설정**: `plugin-setting.sync` {folder, auto, intervalMinutes} — 경로가 기기마다 달라 기기 전용(settings_scope).
- **오래된 지운 기록 정리**: 아는 모든 기기가 이 기기 묶음을 합쳐(`sync_peers.their_ack` = 그 기기 묶음의 acks[이 기기]) 그 기록을 본 뒤, 그리고 30일이 지난 것만 지운다. 아직 합친 적 없는 기기가 하나라도 있으면 지우지 않는다.
- **기기가 셋 이상일 때** (테스트에서 찾음): C가 A의 행을 받은 직후 같은 동기화에서 B의 고침을 받으면 "C도 고침"으로 보여 충돌이 났다. 그래서 받은 행마다 어느 기기의 어느 판이었는지(`sync_row_origin`: 기기·그 기기 시계의 updated_at·받아 쓴 시각)를 적고, 그 뒤 안 고쳤고 보낸 기기의 acks가 그 판을 봤다고 하면 새 판으로 받는다. 같은 폴더를 쓰는 기기들은 서로 직접 합치므로 이것으로 충분하다. 한 기기를 거쳐서만 전해지는 경우(A → B → C인데 C가 A를 직접 못 봄)는 여전히 충돌로 남을 수 있다 — 둘 다 남김이라 잃지는 않는다.
- **Android**: 고른 폴더(SAF)에 일반 파일처럼 쓸 수 없어 폴더 동기화는 데스크톱만(화면에서 숨김). 폰은 파일로 주고받기(2-B-3), 자동은 드라이브(2-D)에서.

**둘 다 남긴 것 고르기와 되돌리기 (2-E)** — `service/data/sync_conflicts.rs`, 설정 > 동기화 맨 위 "둘 다 남긴 항목"·아래 "합치기 되돌리기".
- **양쪽에서 고침(edit)**: 다른 칸만(시각 칸 빼고) "이 기기 / 받은 것"으로 나란히. 고르면 그 결과가 **다른 기기로도 퍼진다**:
  - 이 기기 것 두기 = 그 행을 지금 고친 것으로 표시(updated_at). 이 기기 묶음의 `held`에서 빠지므로, 다음 동기화 때 다른 기기는 이 행을 "새로 고친 것"으로 받는다.
  - 받은 것으로 바꾸기 = 받은 행으로 바꾸고 지금 고친 것으로. 다른 기기와 내용이 같아진다.
  - 동기화로 양쪽 내용이 같아지면(다른 기기에서 고른 결과가 오면) 열린 충돌은 저절로 닫힌다 — 같은 고르기를 두 번 하지 않게.
- **넣지 못한 행(unique·orphan)**: 받은 내용을 보고 **버리기**만. 넣을 자리가 없거나 가리키는 항목이 없으므로.
- **분기(branch)**: 분기 대화를 열어 보고 **확인함**. 필요 없으면 그 대화를 지우면 된다(휴지통).
- **기기별 동기화**: "그 기기 것을 받음"(sync_peers.last_merge_at)과 "이 기기 것을 받아 감"(their_ack — 그 기기의 묶음이 알려 준 것)을 같이 보여준다.
- **되돌리기**: 합치기 전 사본(`sync-backups/app-….db` + `settings-….json`, 최근 3개)을 고르면 다음 시작 때(DB와 설정을 읽기 전) 지금 DB·설정을 `restore-backups/<시각>-sync-rollback/`으로 치우고 사본으로 바꾼다. 중간에 실패하면 원래대로 둔다. **되돌린 설정의 자동 동기화는 끈다** — 켜 둔 채면 그 기기의 기록(sync_peers)도 예전 것이라 다음 동기화가 같은 내용을 다시 합친다. 기존 백업 복원(.scbackup)은 폴더까지 바꾸므로 따로 두었다(사본에는 DB·설정만 있음).

**파일로 주고받기 (2-B-3)** — 코어 플러그인 `sync`(기본 꺼짐), 설정 > 동기화, `service/data/sync_exchange.rs`, `commands/sync.rs`.
- 켜져 있어도 사용자가 누를 때만: "만들기"(저장 위치를 고름), "열기"(미리보기) → "합치기". 만들기·합치기는 실행 기록에 `sync` 작업(TaskType::BackgroundSync, 사용자 실행)으로 남는다.
- **만들기**: 늘 전부 담는다(since 없음). 받는 쪽이 `sync_peers`로 이미 본 것을 건너뛰므로 같은 파일을 여러 기기에 줘도 되고, 어느 기기가 무엇을 받았는지 보낸 쪽이 기억할 필요가 없다. "그림·파일 포함"(기본 켜짐)을 끄면 파일 내용 없이 목록만.
- **미리보기**: 병합을 되돌리는 트랜잭션에서 돌려 추가·변경·지움·되살림·이 기기 고침 유지·둘 다 남김·분기·파일(추가/빠짐/이 기기 것 둠) 개수와 "같이 쓰는 설정이 바뀜"을 보여준다. 아무것도 바꾸지 않는다.
- **합치기**: ① 이 기기 DB(VACUUM INTO)와 설정 사본을 `sync-backups/`에(최근 3개) ② 받은 파일 중 **이 기기에 없는 것만** 넣는다 — 같은 자리에 내용이 다른 파일이 있으면 이 기기 것을 둔다(덮어쓰지 않음) ③ DB 병합 ④ 같이 쓰는 설정을 저장하고 화면에 알린다(바뀐 묶음만). 파일을 DB보다 먼저 넣어, 합친 행이 가리키는 그림이 없는 순간이 없게.
- **이 기기 id**는 동기화 화면을 열 때 처음 만든다(기능을 켜고 화면을 연 것이 동의). 화면에는 앞 8자만.
- 되돌리기 화면은 아직 없다: 사본을 되돌리려면 앱을 끄고 `sync-backups/app-…db`를 `app.db`로 바꾼다(마이그레이션 사본과 같음).

### ADR-012 커뮤니티 플러그인 (사용자 코드 플러그인)

**상태** Accepted (2026-11-17) — CLAUDE.md 6-D (M16). 3단계보다 먼저 하기로 함(사용자 요청)

**배경** Obsidian의 커뮤니티 플러그인처럼 사용자가 만든 기능을 앱에 넣고 싶다. 그러나 이 앱에는 API 키와 요금이 드는 호출이 있어, Obsidian처럼 플러그인이 앱 전체에 닿으면 악성·실수 플러그인이 키를 빼거나 요금을 쓸 수 있다. 원칙: Least Privilege, Explicit Execution, 사용자 동의 없는 리소스 소비 금지, Reversibility, Observability.

**결정 (사용자 합의 2026-11-17)**
1. **격리된 JS + 권한 선언**: 플러그인 JS는 앱 화면 안에서 직접 돌지 않는다. `sandbox="allow-scripts"` iframe(HtmlView와 같은 불투명 origin)에서 돌고, `manifest.json`에 선언하고 사용자가 허락한 권한의 API만 `postMessage` RPC로 부른다. 앱 DOM·저장소·Tauri IPC·API 키에는 닿지 못한다.
2. **확장 지점(첫 버전)**: 메시지 후처리 / 보내기 전 프롬프트 / 화면(패널 탭·명령) / 데이터 읽기·쓰기.
3. **AI 호출 허용, 단 권한과 실행 기록 안에서**: `ai` 권한을 허락받은 플러그인만. 호출은 언제나 TaskManager 작업(기능 id `plugin:<id>`, `run_by`)이고 예산 한도(ADR-007)를 따른다. 자동 실행은 플러그인별 별도 스위치(기본 꺼짐). 실패해도 자동으로 다시 시도하지 않는다.
4. **설치는 파일·폴더로만**: zip 또는 폴더를 가져온다. 온라인 목록·자동 업데이트는 없다(6-F에서 따로 정함).

**형식** — 플러그인 하나 = 폴더 하나 (`<앱 데이터>/plugins/<id>/`)
- `manifest.json`: `id`(소문자·숫자·`-`, 앱 안에서 유일), `name`, `version`, `apiVersion`(앱이 지원하는 SDK 판), `author`, `description`, `main`(기본 `main.js`), `permissions`(아래 표), 선택: `settings`(설정 칸 선언 — 앱이 설정 화면을 그려 줌), `minAppVersion`.
- 코드와 자원(js·css·그림)은 그 폴더 안에만. 크기 상한(예: 폴더 전체 5MB).

**권한** — manifest에 없는 권한의 API는 런타임이 거절한다. 켤 때 권한 목록을 보여주고 동의를 받는다. 권한이 늘어난 새 판을 설치하면 다시 묻는다.

| 권한 | 할 수 있는 일 |
| --- | --- |
| `messages.process` | AI 응답이 저장된 뒤 글을 고치거나 표시를 붙임(후처리) |
| `prompt.modify` | 보내기 전 프롬프트에 블록을 더하거나 고침 |
| `ui.panel` / `ui.command` | 오른쪽 패널 탭 / 명령(명령 팔레트·메뉴) 추가 |
| `data.read:<종류>` | 캐릭터·페르소나·로어북·대화(메시지) 읽기 — 종류별로 |
| `data.write:<종류>` | 고치기 **제안**. 사용자가 바뀌는 부분을 보고 승인해야 적용 |
| `ai` | AI 글 생성 호출 (작업·사용량·한도 안에서) |
| `storage` | 플러그인 자기 설정·작은 저장소(키-값, 상한) |

- 없는 것: 네트워크(fetch·WebSocket — CSP `connect-src 'none'`), 파일 시스템, 다른 플러그인의 데이터, API 키·설정 파일, 앱 화면 DOM.

**런타임**
- 켜진 플러그인만 불러온다(Lazy Initialization). 코어 플러그인 `community`(기본 꺼짐)가 꺼져 있으면 아무것도 읽지 않는다. 플러그인마다 켜짐도 기본 꺼짐.
- 코드는 백엔드가 `plugin://localhost/<id>/…`(Windows/Android는 `http://plugin.localhost/<id>/…`)로 서빙하고 엄격한 CSP를 붙인다: `default-src 'self'`, `connect-src 'none'`, 외부 스크립트 없음(플러그인 폴더 안의 것만), form·frame 없음. AI HTML(htmlview)과 달리 CDN도 막는다 — 코드가 설치 뒤에 바뀌지 않게.
- 플러그인마다 숨은 iframe 하나에서 `main.js`가 돌고, 앱이 넣어 주는 SDK(`sandcastle.*`)로 RPC를 보낸다. 화면(호스트)은 보낸 창이 그 플러그인의 iframe인지, 권한이 있는지 확인한 뒤 IPC로 넘긴다. 백엔드도 같은 권한 표로 다시 확인한다(화면을 믿지 않음).
- 패널 탭은 그 플러그인 폴더의 html을 같은 방식(iframe, 테마 CSS 변수 전달)으로 그린다.
- 오류·시간 초과·호출 횟수 초과는 플러그인 기록(설정 화면)에 남고, 반복되면 이번 실행 동안 그 플러그인을 멈춘다.
- **구현 (6-D-2)**: 도는 플러그인 목록은 백엔드 메모리(`service/community/runtime.rs`)에 있고, 화면의 호스트(`features/community/`)가 시작할 때 채운다. 끄기·지우기·업데이트는 곧바로 목록에서 빼고(그 순간부터 파일을 주지 않음) 화면이 다시 시작한다. 메서드 → 권한 표(`runtime::API`)를 화면과 백엔드가 같이 쓴다. CSP의 `script-src`·`style-src`·`img-src`는 그 플러그인의 경로(`…/<id>/`)와 SDK만 — 다른 플러그인의 파일도 못 부른다. 상한: 초당 호출 100번, 1분에 오류 20번이면 멈춤(다시 켜면 풀림), 저장소는 플러그인마다 키 1000개·1MB·값 64KB. 기록은 플러그인마다 최근 200개(메모리).
- **확인한 것 (실제 앱, 2026-11-17)**: 플러그인 iframe에서 fetch·CDN 스크립트·부모 DOM·localStorage가 막히고 `self.origin`은 `null`. Tauri가 `window.__TAURI_INTERNALS__`를 iframe에도 넣지만 **그 호출은 실행되지 않는다**(설정을 바꾸는 커맨드를 불러도 바뀌지 않고 답이 없음 — 불투명 origin의 IPC를 Tauri가 받지 않음). AI가 쓴 HTML(htmlview, ADR-004)도 같은 sandbox라 같은 결과다. 이것은 Tauri·WebView의 동작에 기대므로 Tauri를 올릴 때 다시 확인한다.

**훅이 백엔드(채팅 코드)와 만나는 방법**
- **후처리**: 응답 저장 → 정규식 → 플러그인(설치 순서). 스트리밍 중에는 돌지 않는다. 백엔드가 응답을 저장한 뒤 화면에 알리면, 호스트가 플러그인을 부르고 결과를 IPC로 돌려준다. 고친 결과는 메시지 meta에 원문과 고친 플러그인을 남기고 "원문 보기 / 되돌리기"를 준다. 플러그인마다 "표시만 / 자동 고침"을 사용자가 고른다.
- **프롬프트**: 프롬프트는 백엔드가 짓는다. 보내기 직전 백엔드가 화면에 블록 목록을 보내고 답을 기다린다(플러그인당 시간 상한, 넘으면 그 플러그인은 건너뛰고 기록). 더한 블록은 토큰 상한 안에서만, 컨텍스트 탭에 어느 플러그인이 무엇을 넣었는지 보인다. 화면이 없으면(창이 닫힘 등) 건너뛴다.
- 이 둘은 무료다(플러그인 코드가 AI를 부르지 않는 한). 플러그인이 훅 안에서 `ai`를 부르면 `run_by = auto`이므로 자동 실행 스위치가 켜져 있어야 한다.

**실행 주체** — 사용자가 명령을 누르거나 패널 안에서 누른 직후(짧은 시간 안)의 `ai` 호출은 `user`, 그 밖(훅·타이머)은 `auto`. 판단은 호스트가 하고 플러그인이 정하지 못한다.

**데이터 쓰기** — 쓰기 API는 원본을 바로 바꾸지 않고 "제안"을 만든다. 사용자가 차이를 보고 승인하면 적용하고, 적용 전 내용은 되돌릴 수 있게 남긴다(5-B의 "제안 → 승인"과 같은 틀로 만들어 에이전트가 다시 쓴다).

**데이터 API (6-D-3)** — `service/community/data.rs`, `service/proposals.rs`
- 읽기: 종류마다 `list`/`get`(대화는 `list`/`messages`, 한 번에 200개). 글 칸만 준다 — 아바타·커버 경로, meta, 프리셋·API 연결은 주지 않는다.
- 제안: `data.<종류>.propose`는 `change_proposals`에 행 하나를 만들 뿐 원본을 바꾸지 않는다. 고칠 수 있는 칸은 종류마다 정해 둔 것뿐(캐릭터: 이름·설명·첫 메시지·예시 대화·제작자 메모·시스템 프롬프트·태그 / 페르소나: 이름·설명·태그 / 로어북: 이름·설명 / 로어북 항목: 키워드·보조 키워드·내용·메모·켜짐, 새로 만들기 가능 / 메시지: 내용). 지우기 제안은 없다.
- 지금과 같은 칸은 빼고, 같은 제안이 이미 기다리고 있으면 그것을 돌려준다(플러그인이 시작할 때마다 다시 보내도 쌓이지 않게). 한 출처가 기다리게 할 수 있는 제안은 50개.
- 적용은 "제안할 때의 값 = 지금 값"일 때만(그 사이 사용자가 고쳤으면 덮어쓰지 않음). 되돌리기는 "적용한 값 = 지금 값"일 때만. 쓰기는 원래 테이블의 UPDATE·INSERT라 변경 추적·동기화가 그대로 동작한다.
- 화면: 새 제안이 오면 알림(보기), 설정 > 코어 플러그인의 "고치기 제안" — 바뀌는 칸만, 여러 줄 글은 줄 단위 차이(같은 줄은 앞뒤 2줄만 남기고 접음).
- 출처 이름은 `plugin:<id>`. 에이전트(5-B)가 같은 표와 화면을 `agent:<id>`로 쓴다.

**메시지 후처리 (6-D-4)** — `service/community/postprocess.rs`, `features/community/postprocess.ts`
- 자리: 새 AI 응답이 저장된 뒤(백엔드 정규식까지 적용된 글) 화면의 `afterReply`가 맨 먼저 부른다. 호스트가 켜져 있을 때만 훅을 등록한다. 스트리밍 중에는 돌지 않는다. 번역·자동 읽기는 고친 글로 한다.
- 플러그인: `sandcastle.on("message.process", ({ message }) => ({ content?, notes? }))`. `messages.process` 권한이 있는 플러그인만, 설치 순서로, 플러그인당 5초. 실패·시간 초과는 건너뛰고 기록한다.
- 방식은 플러그인마다 사용자가 고른다: **표시만(notes, 기본)** — 메모만 메시지 아래에 / **자동 고침(fix)** — 글을 바꾸고 다음 플러그인에 넘김. 표시만인 플러그인이 글을 바꿔 보내도 백엔드가 거절한다.
- 저장: 처음 원문·고친 글·고친 플러그인·메모를 `meta.pluginProcess`에. 다시 처리해도 처음 원문을 지킨다. 지금 보이는 스와이프 글도 같이 고친다. 그 사이 사용자가 메시지를 고쳤거나, 도는 중이 아니거나 권한 없는 플러그인의 결과면 저장하지 않는다. meta를 읽을 수 없으면 덮어쓰지 않고 거절한다.
- 화면: "○○이(가) 고침 · 원문 보기 · 되돌리기"와 메모. 되돌리기는 고친 글이 그대로일 때만, 코어 플러그인을 꺼도 된다.

**프롬프트 훅 (6-D-5)** — `service/community/prompt_hook.rs`, `features/community/promptHook.ts`
- 자리: 대화·폰 생성에서 앱 고정 규칙(메모·작가 노트·이미지 규칙)을 넣은 뒤, 정규식·프롬프트 조립 전. 게임 대사에는 쓰지 않는다.
- `prompt.modify` 플러그인이 하나도 돌고 있지 않으면 화면에 묻지 않는다(기다림 없음). 있으면 이벤트 `user-plugin-prompt`로 묻고, 호스트가 설치 순서로 `sandcastle.on("prompt.build", ctx => ({ blocks }))`를 부른 뒤(플러그인당 2초) `answer_plugin_prompt`로 답한다. 백엔드는 "플러그인 수 × 2초 + 0.5초"(최대 8초)만 기다리고, 넘으면 없이 보내며 기록한다.
- 플러그인이 받는 것: 대화 id·캐릭터 id·이번 입력. 대화 내용은 `data.read:chat`이 있어야 읽는다.
- **더하기만**: 시스템 규칙 끝(rules) 또는 대화 기록의 뒤에서 depth번째(history, 작가 노트와 같은 방식). 있는 프롬프트를 고치거나 빼지 못한다. 블록은 `[플러그인: 이름]` 머리를 달고, 플러그인당 5개·4000자·1000토큰, 모두 합쳐 2000토큰. 부르지 않은 플러그인·권한 없는 플러그인·두 번 온 답은 버린다.
- 넣은 것은 응답 meta.info.pluginPrompt(플러그인·블록 수·토큰)에 남고 컨텍스트 탭에 "플러그인이 더함"으로 보인다. 실제 글은 "보낸 컨텍스트 보기"에.

**화면: 패널·명령 (6-D-6)** — manifest의 `panels`(id·제목·page html)·`commands`(id·제목), 각각 `ui.panel`·`ui.command` 권한이 있어야 선언할 수 있다(설치 화면에 미리 보임). 패널 5개·명령 20개까지.
- 패널: 오른쪽 패널을 쓰는 화면(대화·폰·게임)에서 화면 탭 뒤에 붙는다. `/<id>/__panel/<패널 id>`가 페이지에 SDK와 `<base>`(그 플러그인 폴더)를 넣어 준다. CSP는 플러그인과 같다 — 인라인 `<script>`는 안 되고 폴더의 js 파일만. 앱이 테마 CSS 변수를 보내 주고(SDK가 `<style id="sc-theme">`에 넣음) 테마를 바꾸면 다시 보낸다. 패널 iframe도 그 플러그인의 권한으로 같은 API를 부른다. 플러그인이 꺼지면 탭이 사라지고 화면의 첫 탭으로 돌아간다.
- 명령: 타이틀바의 "플러그인 명령" 메뉴. **사용자가 누를 때만** main.js의 `sandcastle.on("command", ({ id, context }))`가 불린다(AI를 부르는 명령이 있어 90초). 플러그인이 명령을 스스로 실행하지 못한다.
- `sandcastle.app.context()`: 지금 화면의 page·대화 id·캐릭터 id만 (화면의 호스트가 답함, 백엔드는 모름).

**AI 호출 (6-D-7)** — `ai` 권한, `sandcastle.ai.generate(prompt, { system?, maxTokens?, temperature? }) → { text, model }`. `service/community/ai.rs`(정책), `commands/community.rs`(`call_user_plugin`이 직접 실행).
- 실행은 TaskManager 작업(`TaskType::PluginAi`, feature `plugin:<id>`, 표시 이름 "플러그인 · 이름") 안에서 `AiService::generate_once`로 — 사용량이 자동으로 쌓이고 **예산 한도(ADR-007)가 그대로 적용**된다(자동은 항상 막힘, 직접은 "이번만 계속"). 어느 API를 쓰는지는 앱에서 고른 프로필. 실패해도 자동으로 다시 시도하지 않는다.
- **실행 주체는 화면의 호스트가 정하고 플러그인은 정하지 못한다**(`call_user_plugin`의 `by`는 호스트만 채움, 메시지 안의 값은 무시): ① 훅(후처리·프롬프트) 안 → auto ② **사용자가 방금 누른 명령의 몫**(명령 하나에 3번, 60초, 명령이 도는 동안, 메인 프레임에서만)이 남아 있으면 → user ③ 스위치가 켜져 있으면 auto ④ **패널**(눈에 보이는 화면)에서 부른 것만 호출마다 확인 창(플러그인 이름·id, 보낼 글과 시스템 지시 앞부분, 글자 수, 출력 상한, 요금 안내)을 띄우고 허락하면 user — 거절하면 30초 동안 다시 묻지 못한다 ⑤ 그 밖(눈에 안 보이는 프레임의 타이머 등) → auto, 스위치가 없으면 백엔드가 거절하고 **화면에 확인 창을 띄우지 못한다**. 패널은 명령 몫을 못 쓴다(프레임 안의 클릭은 호스트가 믿고 알 방법이 없음).
- auto는 플러그인별 스위치 `ai_auto`(기본 꺼짐, 마이그레이션 166)가 켜져 있어야 하고, 백엔드가 `by = auto`일 때 한 번 더 확인한다.
- 상한: 입력 2만 자(system 포함), 출력 최대 2000토큰(기본 500), 한 번에 하나, 1분에 10번.

**문서와 예제 (6-D-9)** — 만드는 법은 `docs/플러그인 만들기.md`, 예제는 `examples/plugins/`(`word-count`·`quote-check`·`chat-summary`). 문서의 모든 한도·시그니처는 코드에서 옮긴 것이므로 SDK나 한도를 바꾸면 문서도 같이 고친다. 예제는 `cargo test`가 설치 검사(폴더 이름=id, 권한 선언과 main.js 사용의 일치, 패널의 인라인 스크립트 없음)를 매번 돌려 규칙에서 벗어나지 않게 하고, E2E 스모크가 예제 하나를 실제 앱에서 켜 본다.

**관리 화면 (6-D-8)** — 설정 > 커뮤니티 플러그인 (`features/settings/CommunitySection.svelte`, `features/community/`)
- 설치: zip 또는 폴더(데스크톱)를 고르면 **쓰기 전에** 미리보기 — 이름·id·버전·작성자·파일 수·크기·코드 지문, 요청 권한(위험한 것부터, 위험도 배지), 업데이트면 이전 버전과 늘어난 권한, "믿을 수 있는 곳에서 받은 것만" 경고. 설치해도 꺼진 채.
- 켜기: 권한 전부를 보여 주는 동의 창 → "허락하고 켜기" (일부만 허락 불가). 업데이트로 권한이 늘면 꺼지고 "권한이 늘어 꺼짐" 배지, 다시 켤 때 늘어난 권한이 강조된다. 모르는 권한은 가장 위험한 것으로 보인다.
- 자세히: 권한, AI 응답 후처리 방식(표시만/자동 고침), 자동 AI 호출 스위치, manifest `settings`로 선언한 설정칸(앱이 그림, 칸마다 따로 저장, 플러그인은 `sandcastle.settings.get()`으로 읽기만), 기록 보기(최근 200개), zip·폴더로 업데이트, 삭제(휴지통).
- 모든 곳에 플러그인 **id를 이름과 같이** 보인다(이름이 다른 것처럼 보이게 속이지 못하게). 이름·설명·제목의 제어 문자와 글자 방향을 바꾸는 문자·보이지 않는 문자는 manifest를 읽을 때 뺀다.

**보안 점검과 보강 (Opus 자문, 2026-11-18)** — 6-D-1~7을 읽기 전용으로 점검받아 나온 것 중 코드로 확인된 것을 고쳤다.
- **응답에 HTML 블록을 몰래 넣어 데이터를 내보내는 길**(높음): 앱은 ```html 블록(또는 태그로 시작하는 블록)을 살아 있는 HTML 화면으로 그린다(HTML 렌더링 코어 플러그인이 켜져 있을 때, 외부 https 이미지·스크립트 허용). `auto 고침` 플러그인이 대화를 읽고(`data.read:chat`) 응답에 그런 블록을 더하면 데이터가 나갈 수 있었다. → **후처리 결과에 원문에 없던 HTML 블록이 있으면 저장하지 않고 거절**한다(원래 있던 블록을 그대로 두는 것은 된다). 남은 길: 사용자가 승인한 고치기 제안, 프롬프트 훅으로 AI가 쓰게 하는 것 — 둘 다 사용자 눈에 보이거나 AI 응답의 일반 경로이며 HTML 렌더링은 기본 꺼짐.
- **AI 호출 실행 주체**(중간 ×2): 명령이 끝나지 않으면 90초 동안 모든 호출이 user로 치던 것 → 명령 하나에 3번·60초로, 눈에 안 보이는 프레임이 확인 창을 띄우던 것 → 패널만, 거절 뒤 30초 쿨다운, 확인 창에 시스템 지시와 글자 수도 보임.
- **동의가 코드에 묶이지 않음**(중간): 켤 때 폴더의 코드 지문을 저장하고, 지금 폴더와 다르면(손으로 고침·다른 곳에서 바뀜) 꺼진 것으로 본다("코드가 바뀌어 꺼짐", 다시 켜야 함). **백업을 복원하면 모든 플러그인의 켜짐·자동 AI 호출을 끈다**(남이 만든 백업이 동의 없이 코드를 돌리지 않게). 휴지통에서 되살린 플러그인도 꺼진 채, 같은 id가 이미 설치되어 있으면 되살리지 않는다.
- 업데이트 때 허락은 새 manifest가 요구하는 것과의 **교집합**으로만 이어받고(빠졌다가 다시 생긴 권한을 몰래 되살리지 않음) 요구하지 않는 `ai`·`messages.process`의 스위치·방식은 초기화한다. 폴더 없이 행만 남은 id에 새로 설치하면 이전 허락·저장소를 물려받지 않는다.
- 앱이 쓰는 저장소 키(`__…`)는 플러그인의 몫(1MB)에 세지 않아, 가득 채워도 사용자의 설정 저장이 된다. 설정은 칸마다 따로 저장해 빠르게 고쳐도 서로 덮어쓰지 않는다.

**설치·삭제·백업·동기화**
- 설치 전 미리보기: manifest, 권한, 파일 수·크기, 코드 해시. 같은 id가 있으면 업데이트로 보여준다(판 비교, 늘어난 권한).
- 삭제는 휴지통으로(ADR-011 휴지통), 플러그인 저장소도 같이.
- 플러그인 폴더는 사용자 데이터 → 백업에 들어간다(ADR-008 표에 추가). **동기화에는 첫 버전에서 넣지 않는다** — 다른 기기에서 받은 코드가 저절로 생기지 않게. 켜짐·권한 허락은 기기 전용.

**보안 한계(알고 있는 것)** — iframe 격리는 WebView에 기대므로, 플러그인은 화면을 무겁게 하거나(무한 루프) 허락받은 권한 안에서 엉뚱한 일을 할 수 있다. 그래서 권한을 좁게, 쓰기는 제안으로, 요금은 한도로 막는다. 플러그인을 켜기 전에 "믿을 수 있는 출처의 것만" 안내를 보인다.

### ADR-013 어댑터 확장: 임베딩·도구 호출·구조화 출력

**상태** Accepted (2026-11-18) — CLAUDE.md 3-A. 3-B~3-D·4-D·5-B의 바닥. 화면과 기능은 없고(스위치 없음) 부르는 길만 만든다 — 이 길을 쓰는 기능이 각자 플러그인 스위치(기본 꺼짐)와 작업(`run_by`)을 가진다.

**결정**
1. **기존 길은 그대로, 덧붙이기만**: `generate`가 쓰던 요청 모양은 바이트 단위로 같다(기존 테스트 유지). 새 길은 `AiProvider::generate_with(prompt, ChatExtras)`·`embed`, 그리고 `AiService::generate_ext / generate_structured / embed`. `PromptMessage`·`PromptRole`은 바꾸지 않는다 — 도구 루프는 프롬프트 뒤에 붙는 `tail`(`ToolTurn`)로 표현한다.
2. **도구 호출**: 요청에 도구 목록, 응답에서 호출을 읽는다(스트리밍은 조각을 인덱스별로 모아 끝에 확정 — `CallAssembler`). 호출 id가 없는 공급자는 `call_<표>_<번호>`를 붙이고, 인자가 JSON이 아니면 호출을 버리지 않고 `parse_error`를 단다. Gemini는 `thoughtSignature` 등을 되돌려 줘야 하므로 공급자 응답 원본 parts를 `ProviderState`로 불투명하게 들고 다닌다. 종료 사유는 `StopKind`(End/ToolUse/MaxTokens/Filtered)로 맞춘다. **도구와 구조화 출력은 한 요청에 같이 쓰지 못한다**(공급자마다 조합 지원이 달라서). 도구 이름은 공급자 공통 부분집합(영문·`_`로 시작, 영문·숫자·`_`·`-`, 64자). 실행은 호출하는 쪽의 몫 — 어댑터는 도구를 실행하지 않는다.
3. **구조화 출력**: JSON Schema **부분집합**(`adapter/schema.rs`: type·properties·required·items·enum·const·min/max·minLength/maxLength·minItems/maxItems·additionalProperties(bool)·anyOf, 깊이 8·32KB 이하. `$ref`·oneOf·allOf·not·pattern·튜플 items는 거절). 네이티브는 연결이 `지원`일 때만(OpenAI 공식 주소 `response_format`, Claude는 도구 하나를 강제로 부르고 그 입력을 내용으로, Gemini/Vertex `responseSchema`). 그 밖에는 "JSON만 답하라" system 지시 + 앱의 검증. **공급자가 스키마를 지켰다고 믿지 않는다** — 네이티브든 대체든 결과는 앱이 다시 검증한다. OpenAI strict는 스키마가 모든 객체를 닫고 모든 칸이 필수일 때만 켠다. 실패해도 **자동으로 다시 부르지 않는다**(`AI_STRUCTURED_OUTPUT_INVALID`, details에 문제 목록·원문 2000자). 출력 한도에 잘려 끊긴 도구 호출·JSON은 실행하지 않고 `AI_OUTPUT_TRUNCATED`(이미 쓴 토큰은 기록). 도구·구조화 요청은 출력 한도 하한 2048(올리기만 함).
4. **임베딩**: `AiService::embed({프로필, 모델, 글 목록, 용도(문서/질의), 차원})`. 글 2048개 이하(그 이상은 부르는 쪽이 나눔 — 한 번에 큰 요금이 나가지 않게), 빈 글·빈 모델 거절. 사용량은 새 종류 `embedding`, **모델 이름은 프로필의 채팅 모델이 아니라 임베딩 모델**로 기록하고 토큰 한도(`BudgetMetric::Tokens`)에 같이 센다. 공급자가 토큰 수를 안 주면 앱이 세어 `estimated`로 기록. OpenAI 호환 `/embeddings`(100개씩), Gemini `batchEmbedContents`(작업 용도 매핑, 차원을 줄이면 L2 정규화), Vertex `:predict`. Claude는 임베딩 API가 없어 거절하고 Voyage AI나 Gemini 연결을 쓰라고 안내한다.
5. **지원 표**(`adapter/capabilities.rs`, 3-A-4): 연결(형식·주소·모델)별로 임베딩·도구·구조화 각각 `지원 / 확인 안 됨 / 지원 안 함` + 이유. OpenAI 공식 주소 밖(호환 서버)은 전부 `확인 안 됨`. **`지원 안 함`이면 요금이 나가기 전에 `AI_FEATURE_UNSUPPORTED`로 거절하고, `확인 안 됨`은 통과**시킨다(막으면 로컬 모델을 못 씀). 구조화 출력은 글 생성 자체가 안 되는 모델(임베딩·음성 모델)만 `지원 안 함`. 표는 앱이 아는 규칙이지 요청으로 확인한 것이 아니다 — 새 모델이 나오면 틀릴 수 있어 `확인 안 됨`을 기본으로 둔다. 설정 > API 키의 연결 편집 화면이 "이 연결로 되는 것"으로 보여 준다(`get_ai_capabilities`, 요청을 보내지 않는 계산).
6. **가짜 공급자 테스트**: `adapter/testutil.rs`의 로컬 서버로 요청 본문을 기록해 공급자별 요청 모양과 응답 해석을 검증한다. 테스트에서 실제 공급자를 부르지 않는다.

**자문(Opus) 결과 반영** — 설계를 검토받아 바꾼 것: 호출 id가 없거나 겹칠 때 생성·유일성 검사(루프 전체), Gemini 원본 parts 보존(thoughtSignature), `MALFORMED_FUNCTION_CALL` 오류 처리, 도구 이름 첫 글자 규칙, `tool_choice`가 도구 목록과 어긋나는 요청 거절, Claude는 확장 생각을 켜지 않음, 도구 결과를 note 글보다 앞에 둠. 기존 버그도 찾아 고침: **Gemini 사용량이 생각 토큰(`thoughtsTokenCount`)을 빼고 세어 예산을 과소 집계**했다.

**하지 않은 것·알려진 한계**
- 실제 OpenAI·Claude·Gemini·Vertex로 확인하지 않았다(요금·키 없이 가짜 서버로만). 특히 Vertex `:predict` 임베딩의 네트워크 구간은 서비스 계정 없이 확인 불가.
- OpenAI GPT-5·o 계열은 `max_tokens` 대신 `max_completion_tokens`를 요구할 수 있다(기존 `generate`도 같은 한계 — 이번에 건드리지 않음).
- DeepSeek류의 `reasoning_content` 되돌려 보내기, Claude 확장 생각과 도구 호출의 결합은 지원하지 않는다.
- 도구를 자동으로 실행하는 루프·승인은 5-B의 몫이다.

### ADR-014 메시지 linter

**상태** Accepted (2026-11-18) — CLAUDE.md 3-B. 사용자 지시: 후처리(linter)가 6-D의 커뮤니티 플러그인 후처리보다 먼저 일어나야 한다.

**결정**
1. **실행 자리**: AI 응답 → 정규식(`AiOutput`) → `<image>`·`<cg>` 정리 → **linter** → 메시지 저장 → (화면의 `afterReply`) 커뮤니티 플러그인 후처리(ADR-012). linter는 백엔드가 저장하기 직전에 한 번 돌고, 플러그인은 그 뒤 저장된 글을 받으므로 순서가 구조로 보장된다(별도 순서 장치 없음). 스트리밍 중에는 돌지 않는다(받는 도중 화면은 원문 조각 그대로).
2. **정규식과의 관계**: 정규식은 "사용자가 만든 글자 치환", linter는 "글의 모양 검사". 정규식이 먼저 돌아 그 결과를 검사한다. 정규식은 저장·표시 대상이 따로 있지만 linter는 저장하는 글만 본다.
3. **무료 규칙만(3-B-2)**: 닫히지 않은 것(HTML 짝 태그·코드 펜스·`**`·`*`·따옴표), 반복 문단, 내 대사 대신 쓰기(`내 이름:` 줄), 금지어, 글자 수. 규칙마다 끔 / 표시만 / 자동 고침(글자 수는 표시만). 코드 블록 안은 검사하지 않는다. 요금이 나가는 규칙(AI에게 다시 쓰게 하기, 3-B-4)은 이 결정에 없다 — 1-A 한도 안에서 따로.
4. **기본값**: 코어 플러그인 `lint`는 기본 꺼짐. 켜면 규칙 중 닫힘·반복·대사 대신 쓰기는 "표시만", 금지어·글자 수는 끔. 꺼져 있으면 설정도 읽지 않는다. 설정 칸 `plugin-setting/lint`는 취향이라 기기 사이에 같이 쓰고, 켜짐은 기기마다.
5. **원문 보존·되돌리기(3-B-3)**: 걸린 것이 있으면 `meta.lint = { original(고쳤을 때만), content, findings, fixedRules, at }`. 메시지 아래에 걸린 규칙과 "원문 보기 / 되돌리기"를 보인다. 되돌리기는 `meta.lint.content`가 지금 글과 같을 때만 허락한다 — 그 뒤 플러그인(`pluginProcess`)이나 사용자가 또 고쳤으면 거절하고 플러그인 되돌리기를 먼저 하게 한다. 되돌리기 커맨드는 플러그인이 꺼져 있어도 된다. 다시 생성·스와이프를 새로 만들면 이전 `lint`는 지우고 새 응답 것을 넣는다.
6. **고치는 방식의 한계**: 닫기는 글 끝에 닫는 표시를 붙일 뿐 어디서 열렸는지 추측하지 않는다. 대사 대신 쓰기는 그 줄부터 끝까지 잘라 낸다(첫 줄이면 빈 글이 되므로 표시만). 금지어를 모두 지워 빈 글이 되면 표시만. 따옴표는 `"`의 짝수 개수만 보므로 인치 표기 같은 드문 글에서 거짓 경고가 날 수 있다.

7. **대화별 덮어쓰기**: 대화 meta의 `lint: "off"`면 그 대화의 새 응답은 검사하지 않는다(규칙 자체는 전역). 오른쪽 패널 "이 대화"에서 켜고 끄며, 같은 자리에 마지막 응답에서 걸린 규칙을 보인다.

**하지 않은 것**: 폰 엿보기(여러 말풍선 한꺼번에 저장)와 게임 대사에는 적용하지 않음.

### ADR-015 메모리 임베딩 검색

**상태** Accepted (2026-11-18) — CLAUDE.md 3-C. 설계는 Opus 자문을 받아 아래 "자문 반영"과 같이 바꿨다. 이번 범위는 3-C-1~3-C-4(저장·색인·뜻으로 찾기). 프롬프트에 넣기(3-C-5)와 무효화 정리(3-C-6)는 뒤에.

**결정**
1. **코어 플러그인 `memory`**(기본 꺼짐). 꺼져 있으면 `memory.db`를 열지도 않는다(처음 쓸 때 연다). 설정 `plugin-setting/memory`(기기 전용): 임베딩 API 프로필·모델 이름(사용자가 입력, 앱이 모델·가격을 내장하지 않음)·차원(선택)·실행당 토큰 상한(기본 20만)·문서/질의 접두어(e5·nomic류 로컬 모델용).
2. **별도 파일 `memory.db`**(앱 데이터 폴더). 벡터는 크다(1만 chunk × 1536차원 ≈ 60MB). `app.db`에 두면 마이그레이션 전 사본·동기화 전 사본·백업·휴지통 스냅샷이 모두 그만큼 커진다. 따로 두면 그 흐름들이 보지 못하고(백업·동기화·휴지통 제외), `change_tracking` 분류가 필요 없고, "메모리 지우기"는 파일 하나를 지우는 일이며, 깨져도 다시 색인하면 된다. 옛 `memory_embeddings`·`memory_settings` 표는 건드리지 않는다.
3. **표**: `vectors(model_key, text_hash, dim, vector)` — 글 해시로 가리키는 공용 캐시(같은 글은 분기·다른 대화에서도 한 번만 임베딩). `chunks(conversation_id, first_message_id, last_message_id, text_hash, model_key, closed, tokens)` — 어디가 무슨 벡터인지. **chunk 글은 저장하지 않고** 보여 줄 때 살아 있는 메시지에서 다시 읽는다. 벡터는 L2 정규화해서 f32 little-endian BLOB으로.
4. **chunk 경계는 메시지 id에 고정**: 목표 글자 수(약 1000자)에 닿는 메시지 경계에서 닫힌 chunk로 확정하고, 확정된 경계는 다시 색인해도 옮기지 않는다 → 메시지를 덧붙여도 앞 chunk는 그대로(해시 동일)이고, 고친 메시지는 자기 chunk(와 이어 붙인 접두 한 줄을 쓰는 다음 chunk)만 다시 임베딩. 끝의 덜 찬 chunk는 열린 채로 색인하고 다음에 이어 붙을 때 교체한다. 글은 `이름: 내용` 줄로, HTML·상태창 블록·`<image>`·`<cg>`·코드 블록은 뺀다. 접두로 앞 메시지 한 줄을 임베딩 글에 붙이되 경계는 옮기지 않는다. 한 메시지가 4000자를 넘으면 4000자에서 자른다(임베딩 입력 한도). 해시는 정규화한 글 + `chunker_version`으로 계산해 규칙을 바꾸면 깔끔하게 무효화된다.
5. **model_key** = 공급자 종류 + 주소 해시 + 모델 이름 + 차원 + 접두어 해시(프로필 id는 쓰지 않음 — 프로필을 다시 만들어도 같은 모델이면 재사용, 호환 서버가 모델 이름을 겹쳐 써도 구분). 저장하는 벡터는 늘 Document 용도이고 질의 벡터는 저장하지 않는다(메모리 LRU만). 검색은 지금 model_key와 같은 chunk만 본다. 다른 모델로 색인된 것은 "다시 색인"을 안내하고 지우기 버튼을 둔다.
6. **색인은 명시적**: "이 대화 색인"(또는 전체) → 먼저 **미리보기**(chunk 수, 캐시로 건너뛸 수, 새로 임베딩할 수, 예상 토큰 — 앱의 토큰 세기라 "추정") → 사용자가 확인 → TaskManager 작업 하나(`TaskType::Embedding`, feature `memory`, `run_by = user`, "메모리 색인"). 64개씩 배치, 배치마다 한도 확인·취소 확인·자기 트랜잭션으로 저장(중간에 멈춰도 쓴 배치는 남고 다음 실행은 캐시를 건너뜀). 예상 토큰이 상한을 넘으면 거절하고, 사용자가 상한을 넘겨 한 번 더 확인해야 돈다. 자동으로 이어 돌지 않는다. 실패해도 다시 시도하지 않는다. 결과·오류에는 개수만 남기고 대화 글을 싣지 않는다. 자동 색인은 이번 범위 밖(별도 스위치, 한도 안에서, 나중에).
7. **검색**: 엔터를 눌렀을 때만(타이핑마다 아님) 질의를 임베딩(작업 하나, feature `memory`), 같은 질의는 캐시. 지금 model_key의 chunk를 쪽 단위로 읽어 f32로 풀고 정규화된 벡터끼리 내적해 상위 K만 힙에 유지(전부 메모리에 올리지 않음, 모바일 대비). 훑는 벡터 수 상한 5만, 넘으면 "일부만 검색함"을 보인다. 결과는 글 해시로 중복을 합치고 지금 메시지에서 다시 읽은 글로 해시를 확인해 바뀐 것은 "오래됨"으로 표시한다. 범위: 이 대화 / 전체(전체는 제외한 대화를 뺀다).
8. **제외(Least Privilege)**: AI에게 숨긴 메시지, 폰 엿보기·게임 대사, 사용자·AI 말이 아닌 역할은 색인하지 않는다. 대화 meta `memory: "off"`인 대화는 색인·전체 검색에서 뺀다. 설정 화면에 "색인하면 대화 글이 임베딩 공급자에게 전송됨"을 적는다.
9. **지우기**: 대화·메시지를 지워도 memory.db의 행은 남을 수 있어(휴지통 복원이 공짜가 되도록 벡터는 둔다) 검색 때 살아 있는 메시지로 검증해 없는 것은 건너뛰고, "정리"로 남은 chunk·벡터를 지운다. "메모리 전부 지우기"는 파일을 지운다.

**자문(Opus) 반영** — 벡터를 `app.db`에서 `memory.db`로 분리, chunk 경계를 메시지 id에 고정, model_key에 주소·접두어 해시를 넣고 프로필 id는 제외, 질의 벡터 저장 안 함·정규화 다시, 전체 색인은 상한 초과 시 두 번째 확인, 검색은 쪽 단위로 읽어 상위 K만 유지(`sqlite-vec`는 20만 벡터를 넘거나 폰에서 1초를 넘기면 그때 검토), 기본 차원은 모델이 줄이기를 지원하면 768 권장, 설정 칸은 기기 전용.

**하지 않은 것·알려진 한계**: 대화 메시지의 스와이프는 고른 것만 본다(바꾸면 해시가 달라져 "오래됨"), 자동 색인·프롬프트 삽입(3-C-5)·무효화 자동 정리(3-C-6), 결과에서 오래된 메시지로 바로 이동(지금 화면은 최근 메시지만 읽어 먼 메시지로 가려면 "메시지 주변 읽기"가 더 필요), f16/int8 저장, 4000자를 넘는 한 메시지의 뒷부분.
