# 번역 안내 (다국어 기여 가이드)

Sandcastle의 화면 문구와 백엔드 오류·알림 문구는 `svelte-i18n` 기반 영역별 사전으로 관리합니다. 설계 배경과 결정 근거는 `docs/아키텍처 결정 기록 (ADR) — 프로젝트 전반.md`의 **ADR-032**에 있습니다.

---

## 1. 사전 폴더 구조

번역 사전은 `src/locales/<언어코드>/` 아래에 영역별 JSON 파일 7개로 나뉘어 있습니다. 앱은 시작할 때 **현재 선택된 언어의 파일만 지연 불러오기(Lazy Load)** 하며, 다른 언어 파일은 언어를 바꿀 때 불러옵니다.

```
src/locales/
├── ko/
│   ├── common.json      공용 버튼·단위·탐색·앱 틀·토스트·공용 입력 위젯
│   ├── settings.json    설정 화면 전 탭·모델/공급자·단가·테마·동기화·단축키
│   ├── chat.json        캐릭터·페르소나·로어북·대화·메시지·오른쪽 패널·텍스트 카드
│   ├── phone.json       폰 대화·앨범·카메라·프로필·인스타그램
│   ├── game.json        게임 목록·상세·비주얼노벨 플레이·각본가·게임 편집기
│   ├── features.json    홈·이미지 갤러리·대필·슬래시·커뮤니티 플러그인·상태창·위젯/시메지
│   └── backend.json     백엔드 오류(key+args)·코어 플러그인·작업/할당량 라벨·가져오기 경고
└── en/
    └── (ko와 동일한 파일·키 구조)
```

- **언어 결정 순서**: `localStorage("sc.locale")` → 기기 전용 `AppSetting.language` → OS/브라우저 언어(`ko*`면 `ko`, 그 밖은 `en`).
- 같은 언어 폴더 안의 7개 파일은 런타임에 하나로 합쳐지므로, **서로 다른 파일에 같은 최상위 키를 중복 정의하면 안 됩니다** (`i18n.test.ts`가 자동 검사).

---

## 2. 새 언어 추가하기

1. `src/locales/<언어코드>/` 폴더(예: `src/locales/ja/`)를 만들고 `en/` 아래의 JSON 파일 7개를 복사해 번역합니다.
2. `src/lib/utils/i18n.ts`가 `import.meta.glob("../../locales/*/*.json")`으로 폴더를 자동 수집하므로, 파일만 추가하면 `AVAILABLE_LOCALES`와 **설정 > 일반 > 언어** 선택 목록(`GeneralSection.svelte`)에 해당 언어의 고유 자칭(`Intl.DisplayNames`)으로 자동 등록됩니다.
3. 고유 표기를 직접 지정하고 싶다면 아래 두 곳만 보완합니다.
   - `src/features/settings/GeneralSection.svelte`의 `LANGUAGE_LABELS`
   - `src/lib/utils/i18n.ts`의 `defaultTargetLang()` (번역 플러그인의 대상 언어가 비어 있을 때 AI에게 건네는 언어 이름)
4. 아래 [7. 검사 명령](#7-검사-명령)을 실행해 누락된 키나 ICU 문법 오류가 없는지 확인합니다.

## 3. 새 문구 추가·수정 규칙

### 키 이름 규칙
- 키는 `영역.하위영역.역할` 형태의 `camelCase`로 짓습니다 (예: `settings.general.checkUpdateBtn`, `chat.panel.exportJsonl`).
- `ko`와 `en`(및 추가된 모든 언어)의 **키 집합은 항상 100% 일치**해야 합니다. 한쪽 언어에만 키를 넣으면 단위 시험이 실패합니다.
- 문장 조각을 `+`로 이어 붙이지 말고, 어순이 다른 언어에서도 자연스럽게 번역할 수 있도록 치환 변수(`{name}`, `{count}`)를 포함한 완결된 문장으로 작성합니다.

### Svelte 컴포넌트와 TypeScript에서 부르는 법
- **`.svelte` 컴포넌트 안**: 반응형 스토어 `$_`를 씁니다.
  ```svelte
  <script lang="ts">
    import { _ } from "svelte-i18n";
  </script>

  <button>{$_("common.save")}</button>
  <p>{$_("settings.data.trashCount", { values: { count: items.length } })}</p>
  ```
- **`.ts` / `.svelte.ts` 모듈(컴포넌트 밖)**: `$lib/utils/i18n`의 `tr()` 헬퍼를 씁니다.
  ```ts
  import { tr } from "$lib/utils/i18n";

  toast.error(tr("errors.NETWORK_OFFLINE"));
  const message = tr("slash.unknownCommand", { name: cmd });
  ```
- **모듈 최상단 상수 주의**: 모듈이 로드될 때는 아직 사전 지연 로드가 끝나지 않았거나 나중에 사용자가 설정에서 언어를 바꿀 수 있습니다. 모듈 최상단 배열·객체에 `tr(...)` 결과를 바로 담아 두지 말고 **getter**나 함수로 작성하세요.
  ```ts
  // 나쁜 예: 초기 언어로 굳어 버림
  export const MODES = [{ id: "auto", label: tr("common.auto") }];

  // 좋은 예: 읽을 때마다 현재 언어로 평가됨
  export const MODES = [{ id: "auto", get label() { return tr("common.auto"); } }];
  ```
- **시각·숫자 형식**: 한국어 조사를 직접 붙이지 말고 `src/shared/time.ts`처럼 `Intl.DateTimeFormat` / `Intl.RelativeTimeFormat` / `Intl.NumberFormat`에 현재 로케일을 넘겨 표시합니다.

## 4. ICU MessageFormat 따옴표 규칙

`svelte-i18n`은 내부적으로 ICU MessageFormat을 사용합니다. 작은따옴표(`'`)와 중괄호(`{}`) 조합에서 아래 세 가지를 꼭 지켜야 합니다.

1. **일반 변수 치환**: `{name}`처럼 중괄호 한 겹으로 적습니다.
2. **변수를 작은따옴표로 감싸고 싶을 때**: `'{name}'`처럼 적으면 ICU가 중괄호를 리터럴 문자열로 이스케이프해 버려 변수가 치환되지 않습니다. **작은따옴표 두 개(`''{name}''`)** 로 적어야 실제 화면에 `'홍길동'`으로 나옵니다.
   - 잘못된 예: `"'{name}' 플러그인을 켤까요?"` → 화면에 `{name} 플러그인을 켤까요?` 출력
   - 올바른 예: `"''{name}'' 플러그인을 켤까요?"` → 화면에 `'예제' 플러그인을 켤까요?` 출력
3. **리터럴 이중 중괄호·특수 중괄호**: 프롬프트 매크로 `{{char}}`·`{{user}}`나 STscript 클로저 `{: … :}`를 사전에 그대로 적으면 ICU 파싱 오류가 납니다. **`'{{char}}'`**, **`'{: … :}'`** 처럼 작은따옴표로 감싸 리터럴로 이스케이프하세요.

`src/lib/utils/i18n.test.ts`가 모든 언어의 전체 키에 가짜 변수를 넣어 렌더링하며 치환 누락과 ICU 문법 오류를 자동으로 잡아냅니다.

## 5. 백엔드(Rust) 문구 번역 규칙

백엔드 코드는 로그·디버깅 가독성을 위해 한국어 원문 `message`를 유지하되, 프런트엔드가 정확히 번역할 수 있도록 구조화된 키를 함께 내보냅니다.

- **`AppError` / `TaskErrorInfo` 오류 문구**:
  1. `src-tauri/src/error/i18n.rs`의 `EXACT_RULES`(고정 문구) 또는 `TEMPLATE_RULES`(인자 포함 문구)에 매칭 규칙을 추가합니다.
  2. `src/locales/ko/backend.json`과 `src/locales/en/backend.json`의 `errors.detail.<키>`에 양쪽 언어 문구를 추가합니다.
  3. Rust 단위 시험(`error::i18n::tests`)이 모든 규칙의 키가 양쪽 `backend.json`에 존재하는지 검증합니다.
- **작업 이름(`CreateTaskRequest.label`)·할당량(`QuotaLine`)·가져오기 경고**:
  - `src/lib/utils/backendI18n.ts`의 `localizeTaskLabel`·`localizeQuotaLine`·`localizeImportWarning` 매핑표와 `backend.json`(`tasks.labels.*`, `quota.*`, `importWarnings.*`)에 키를 함께 추가합니다.
- **프런트를 거치지 않는 네이티브 UI**:
  - OS 알림(`src-tauri/src/service/notify.rs`), 바탕화면 위젯 트레이 메뉴(`src-tauri/src/widget/manager.rs`), 만료된 HTML 뷰 안내(`src-tauri/src/sys/html_view.rs`)는 백엔드에서 직접 `AppSetting.language`(또는 `Accept-Language`)를 확인해 분기합니다.
- **내장 유틸 프롬프트 기본값(`src-tauri/src/service/app_prompts.rs`)**:
  - AI에게 보내는 시스템 지시문은 영어 원문으로 작성하고 `"Write in the language of the conversation"` 지시로 대화 언어를 따르게 합니다.

## 6. `i18n-ignore` 예외 기준

`scripts/check-i18n.mjs`는 `src/` 아래 `.svelte`·`.ts` 파일(주석·테스트·`dev-mock.ts`·`design-preview/` 제외)에서 한글 문자열이 발견되면 실패합니다. 화면에 보이는 문구에는 예외를 달지 말고 반드시 사전 키로 옮기세요.

예외 표기(`// i18n-ignore: 사유` 또는 `<!-- i18n-ignore: 사유 -->`)는 아래 경우에만 허용합니다.

- DB·사이드카·백엔드와 약속된 내부 고정 값(예: 다인봇 기본 분류명 `"기타"`, 번역 대상 언어 지시어 `"한국어"`)
- 언어 선택기의 고유 자칭(`LANGUAGE_LABELS`) 및 글꼴 미리보기용 한글 샘플 문장
- 한글 음절 여부를 판별하는 정규식(`/[가-힣]/`)과 `backendI18n.ts`의 백엔드 원문 매핑표
- 설정 탭 검색에서 영어 화면 사용자가 한국어로도 검색할 수 있게 둔 보조 색인(`settings.tabKeywords.*`)

## 7. 검사 명령

번역이나 화면 문구를 수정한 뒤에는 아래 세 명령으로 검증합니다.

```bash
# 1. 프런트엔드 하드코딩 한글 0줄 검사 (CI 포함)
pnpm i18n:check

# 2. 언어 간 키 일치 · 영역 중복 0 · 정적 $_() 키 존재 · ICU 치환 · 영문 한글 누출 0 시험
pnpm test:run src/lib/utils/i18n.test.ts

# 3. 백엔드 오류 분류기 ↔ ko/en backend.json 동기화 시험
cargo test --manifest-path src-tauri/Cargo.toml --lib error::i18n
```
