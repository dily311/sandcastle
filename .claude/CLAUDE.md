# 계획
- 목표: ai 채팅앱 구축
- 사용스택: svelte, tauri, pure css, pixi.js
- 플랫폼: 윈도우와 안드로이드
- 주요기능: ai 채팅 플랫폼
- 부가기능
    - 위젯 (데스크톱 전용)
    - phone/game 모드

## 중요하게 생각해야 하는 것
| 원칙 |	설명 |
| Lazy Initialization |	기능을 사용하기 전에는 초기화하지 않는다. |
| Explicit Execution |	API 비용이나 외부 작업이 발생하면 실행 주체가 명확해야 한다. |
| Least Privilege |	기능은 필요한 데이터와 권한만 접근한다. |
| Reversibility |	가능하면 실행 취소, 복구, 원본 보존을 지원한다. |
| Observability |	사용자는 기능의 상태와 실행 결과를 확인할 수 있어야 한다. |

- 기능의 존재와 실행 단계를 반드시 분리
    - 기능이 설치되어 있어도 꺼져 있는 경우 리소스를 소비되게 하면 안됨
    - 새로 기능을 추가하는 경우에는 기본값은 반드시 off
- 데이터와 UI 상태 분리
- 사용자 동의 없는 리소스 소비 금지
    - API 등 지출이 필요한 단계는 사용자가 인식할 수 있어야 함. 예를 들어 채팅기능의 send 버튼처럼 사용자가 실행한 동작이 있어야 함. 선톡 기능의 경우 사용자가 옵션을 키지 않으면 실행되지 않도록 할 것
- 사용자 경험

## 가까운 목표 (2026-11-17 합의)

중장기 1단계(기본 완성도와 안정성)를 세 마일스톤으로 나눠 이 순서로 진행한다. 각 마일스톤이 끝나면 테스트·미리보기 확인 후 커밋하고 여기 체크한다.

### 합의한 결정
- 기본값: 기존 부가 기능 중 **HTML 렌더링만 기본 off**로 바꾼다 (AI가 쓴 JS를 실행하므로). 폰·게임·캐릭터 이미지·정규식은 기본 on 유지. 앞으로 추가하는 기능은 모두 기본 off. 이미 설정을 저장한 사용자의 값은 건드리지 않는다.
- 번역 저장: **공용 번역 캐시** (원문 해시, 언어) → 번역문. 채팅·폰·게임이 같이 쓰고, 같은 문장은 세션·분기·재플레이에서 다시 요금을 내지 않는다. 원문이 바뀌면 해시가 달라져 자연히 무효.
- 실행 관리 범위: **모든 유료 AI 호출을 TaskManager로 통일 + 호출 기록·사용량(ResourceManager 1차) + 화면**. 예산 한도(막기)는 다음 단계.

### M1. 버그와 게임 번역 저장 (완료)
- [x] 좁은 창(모바일 레이아웃)에서도 최소화·최대화·닫기 버튼 보이기 (데스크톱 앱일 때)
- [x] 게임: 갈 수 없는 이동은 버튼을 막고 이유 표시 (대사창 목록·오른쪽 패널·지도 모두)
- [x] 게임: 조사했는데 아무 일도 없으면 "아무 일도 없었다" 줄 표시
- [x] 위젯: 위젯을 끄면 위젯 창도 닫히기 (코어 플러그인·위젯 탭 어느 쪽에서 꺼도)
- [x] 공용 번역 캐시 + 게임 번역 줄 저장 (다시 열어도·지난 대사에서도 번역문)
- [x] HTML 렌더링 기본값 off

### M2. 작업 실행 관리와 사용량 (완료)
- [x] 유료 AI 호출(채팅·폰 엿보기·NPC·씬 입력·번역·음성·이미지·이미지 프롬프트 작성)을 모두 TaskManager 작업으로. 각 작업에 기능 id(코어 플러그인)와 실행 주체(사용자 클릭 / 자동 설정)를 남긴다
- [x] 호출 기록: 작업 id, 기능, API 프로필·모델, 시작·끝, 상태, 오류 위치·원인, 재시도 횟수, 소요 시간
- [x] 사용량(ResourceManager 1차): 입력·출력 토큰(공급자가 주면 그 값, 아니면 추정), 음성 글자 수, 이미지 장 수를 API 프로필별로 집계
- [x] 화면: 실행 중인 작업(취소), 최근 실행 내역(자동 실행 표시), API별 사용량
- [x] FeatureManager(기능 켜짐·설정) / TaskManager(실행·생명주기) / ResourceManager(사용량) 책임 분리 정리 (ADR)

### M3. 화면 완성도
- [ ] 채팅: 제목 옆 동작 메뉴에 "캐릭터 페이지로", HTML 블록 접기, 숨긴 메시지 한 줄로 접기, 대화 목록 열기 아이콘 빼기, 모델명 대신 공급자 아이콘
- [ ] 채팅: 선택한 텍스트를 이미지 카드로 만들기
- [ ] 캐릭터 개요: 메시지와 같은 렌더링(마크다운·HTML·{{}} 치환)
- [ ] 설정: API 저장 시 "Hi" 연결 확인 단계, 테마 배경 이미지(GIF 포함), 기존 테마 JSON ↔ 새 테마 변수 연결
- [ ] 설정: 앱이 쓰는 프롬프트(CG 이미지·게임·번역·이미지 프롬프트 작성 등)를 사용자가 고칠 수 있게
- [ ] iframe 편의 함수: 선택지를 누르면 채팅 입력/전송, 메시지 보내기 등 (허용된 요청만 postMessage로)
- [ ] 홈 페이지 (사용자 커스텀) — 마지막

## 현재 단계의 개선점

### 발견한 버그
- 반응형으로 제작되어 화면을 줄일 경우 모바일 UI대로 표시되는거. 이건 문제가 없은데 최소화, 최대화, 창닫기 버튼이 사라지는 문제가 있음
- 게임모드
	- 위치를 이동할 수 없으면 버튼을 막아두어야 함
	- 조사 기능 사용시 아무 일도 없었다면 명시적으로 "아무일도 없었다"고 표시되어야해.
- 위젯기능
	- 위젯을 꺼도 위젯 윈도우가 자동으로 꺼지지 않아. 


### 있었으면 하는 기능과 해야 하는 일
- 홈 페이지
	- 사용자가 커스텀 할 수 있는 페이지가 있으면 좋겠어.
	- 그다지 중요한 건 아니지만 사용자 경험에서 좋은 느낌을 주잖아.
- 캐릭터 페이지
	- 개요 탭에서도 마크다운 파싱과 html 파싱, {{}} 치환이 같이 되어야 해. 메시지 버블처럼.
- chat 대화 페이지
	- Breadcrumb 옆 대화 동작 아이콘에서 캐릭터 페이지로 이동하는 기능 필요
    - 메시지 버블
        - html 코드 접기기능
        - 유령 메시지 접기기능 (메시지 한줄만 보이게 하고 짧게 접기)
        - 대화 목록열기 아이콘 없는게 더 깔끔해
        - ai 모델명 대신 ai를 상징하는 아이콘을 표시하게 하고 싶어. 아이콘은 어디서 가져오면 좋아?
        - 메시지 텍스트 선택시 컨텍스트에 해당 텍스트를 이미지로 가공하는 부가 기능이 있으면 좋겠어.
- 설정페이지
    - api 연결
        - 테스트 메시지(Hi)를 전송해서 연결이 되었는지 확인하는 단계 필요
    - 테마
        - 백그라운드 이미지(아니면 움짤)를 추가하거나 변경할 수 있었으면 해.
        - 원래 있는 테마json을 새로 만든 테마변수와 연결하는 작업
    - cg 이미지 프롬프트를 사용자가 수정할 수 있게. (게임모드나 다른 프롬프트도 사용자가 수정할 수 있어야 함)
- iframe
	- 선택지를 클릭하면 자동으로 채팅창으로 넘어간다던가 그런기능이 필요해. 주입할때 편의 함수를 몇개 지원하면 좋겠어.
